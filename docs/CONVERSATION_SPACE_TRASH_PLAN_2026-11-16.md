# 会话管理、空间整理与回收站：源码审计及实施方案

- 日期：2026-11-16（Asia/Shanghai）
- 审计基线：FreeAgent `153de60`；当前程序版本 `v8.8.0-dev.8`。
- 状态：P0–P2 已完成，v8.8.0-dev.9 已推送 GitHub、发布开发预发行版并升级 Hytron。本文件取代前面聊天中的方案草稿；第 1–17 节保留审计依据与实施契约，实际结果与未执行设备检查见第 18 节。
- 目标版本：v8.8.0-dev.9，存储 schema 2。
- 实施范围：代码、独立数据库和合成数据测试、操作/升级文档，以及用户授权的发布与 Hytron schema 2 迁移；原会话、凭据和扩展数据保留。

## 1. 目标与已确认选择

补齐会话管理和空间清理：单个会话可以重命名、置顶、移动和删除；空间内可以按类别查看内容、筛选和勾选，再批量整理。操作入口在 Web、桌面版、手机和键盘操作下都能找到。

用户已确认：

| 事项 | 确定行为 |
| --- | --- |
| 会话操作 | 侧栏每行和当前会话顶部提供「⋯」菜单 |
| 右键 | 会话行右键打开与「⋯」相同的会话操作；Web 其他区域保留浏览器原生右键，桌面其他区域保留既有编辑菜单 |
| 删除会话 | 先移到回收站，保留 7 天；支持恢复、永久删除所选和手动清空 |
| 删除空间 | 「同时将其中的会话移到回收站」默认勾选；取消勾选则把会话移到本地空间 |
| 空间整理 | 分类查看、筛选、跨页勾选、批量移动和批量移入回收站 |
| 轻量 Core | Core 管通用会话生命周期、授权和投递约束；扩展自己管理业务数据 |

删除会话不撤销已经发生的文件修改、命令或外发消息，也不清空独立 Memory、Skill、扩展数据或用户工作目录。界面按实际影响说明保留项。

## 2. 审计结论与必须修正的草案内容

整体产品方向可实施，但上一版不能直接作为实现契约。以下修正已纳入后续章节；源码依据见附录 A。

| 编号 | 级别 | 草案问题与源码事实 | 本版决定 |
| --- | --- | --- | --- |
| A01 | 阻断 | `replayUnresolved` 按操作指纹跨会话查询；`ignored` 仍参与防重放。草案却允许无分支时删除证据 | 删除会话不能解除仍适用的操作保护；保留原必要证据并列明，不以“忽略”换取删除资格 |
| A02 | 阻断 | `stopped`、部分 `limited` 仍属于活跃任务；停止不等于结束；批准待确认操作可能执行副作用 | 清理使用“停止并结束本轮”、取消未执行事项；不以批准操作作为删除前置步骤 |
| A03 | 阻断 | 渠道入站有独立持久化意图，outbox 会接收迟到回执；仅删除 messages/runs 会破坏去重或回写旧内容 | 入站去重、投递 claim/回执和生命周期门禁统一覆盖；迟到回执只更新原证据 |
| A04 | 阻断 | PG 外键为 attempts → runs → conversations → spaces；附件文件不属于 PG 事务 | 删除空间在事务内安置会话；永久清理先撤销访问、保留可重试的文件清理记录，再删除文件 |
| A05 | 重要 | `MoveConversation` 保留会话工作目录和模型；外部目标会发布可见正文与附件，并清理部分上下文选择 | 区分普通分类移动与受众变化；不宣称移动会切换工作目录或目标空间模型 |
| A06 | 重要 | 分支复制消息，附件使用新 ID 和独立文件；未决项则继承原记录引用 | 不建设附件引用计数系统；单独处理分支的未决引用和来源链接 |
| A07 | 重要 | `CreateActiveConversation` 拒绝外部单会话模式；活动会话和默认会话是两个指针 | 替换 TG 当前会话必须同时核对两指针；不暗中开启多会话，也不只调用现有 `/new` |
| A08 | 重要 | `DeleteSpace` 撤销该空间的 TG 授权；本地基础空间不可删 | 明确区分“清理空间内容”与“删除并解除渠道关联”；禁止删除基础本地空间 |
| A09 | 重要 | 只有历史版本号无法覆盖改名、置顶、排队输入、投递领取、权限变化 | 预览绑定确切 ID、生命周期和操作相关状态；执行时锁定并重新校验 |
| A10 | 重要 | 普通分页不是全列表快照；动态筛选在确认后可能扩张 | 全选绑定冻结的确切 ID 集合；后续新匹配项不自动加入 |
| A11 | 重要 | 会话草稿是客户端内存和 `sessionStorage`；Core 无法擦除离线标签页 | 明确本客户端/在线客户端清理与重连补查，不承诺即时删除所有客户端副本 |
| A12 | 重要 | 改名为空当前非法；改名不更新会话活动时间；置顶有 50 个上限 | 空标题报错；不新增自动标题恢复；回收站不占置顶名额，恢复满额时正常恢复但不置顶 |
| A13 | 重要 | 当前 PG 校验 schema 版本、SQL 源摘要和实际结构；没有核实可直接复用的跨版本迁移 | 独立交付可验证升级入口和旧程序拒绝机制；不能只写“加两列即可” |
| A14 | 重要 | 现有附件清理只覆盖部分暂存/孤儿路径，不能保证已标记删除文件的失败重试 | 扩充既有附件清理流程；失败保留清理记录和实际磁盘占用 |
| A15 | 重要 | 草案禁止 AI 提议一切永久删除，但现有 `attachments.delete` 已允许模型提议后确认 | 限制针对新会话永久清理操作；现有独立附件删除授权语义另按既有规则执行 |
| A16 | 重要 | AI 若在目标会话内提议删除自己，确认时该 Run 正处于等待确认，会死锁 | 加入“确认后结束本轮并移入回收站”的受控流程；先可靠结束再清理，不删除执行中的记录 |

本次是静态审计，未运行破坏性试验。下文的行为和测试都是实施要求，不代表已经实现。

## 3. 对象、分类与权限边界

### 3.1 空间是分类文件夹，也是既有权限边界

- 普通空间可命名为“工作”“学习”“测试”等，沿用现有 `source=local` 空间。
- 渠道空间展示 Telegram、其他已支持渠道及私聊/群聊标识，绑定实际渠道会话。
- “放到不同类型的空间”通过移动到这些空间实现。本期不另建空间类型表、嵌套文件夹或标签系统。
- 空间类型由来源和渠道绑定决定。重命名普通空间为“Telegram”不会获得渠道能力。
- 会话可以由多个入口接续，管理页展示“所在空间/最近入口”；不能把整个会话武断标记成唯一的 Web、CLI 或 TG 来源。来源不可靠时显示“未记录”，不猜。
- 工作目录属于现有会话配置。移动或恢复不移动磁盘文件、不改全局工作目录。

### 3.2 首版管理权限

完整空间管理、回收站、删除预览和证据明细向经过身份验证且具有管理权限的 Owner 提供。公网 Web 仍受现有认证、CSRF 和权限上限约束；“已经登录”不等于可以提升权限。

TG 群成员和普通渠道参与者不能枚举所有空间、回收站、未决数量或私有附件。受限入口访问不可见对象时使用现有不泄露存在性的错误规则。

恢复、移动和删除都重新校验当前授权。原空间不存在时，普通恢复目标默认本地；恢复到渠道空间必须重新预览公开范围，不能恢复已经撤销的渠道授权。

## 4. 会话与空间菜单

### 4.1 会话「⋯」菜单

```text
项目讨论                                  ⋯
                              ┌────────────────┐
                              │ 重命名          │
                              │ 置顶 / 取消置顶 │
                              │ 移到空间      › │
                              ├────────────────┤
                              │ 选择多个会话…   │
                              ├────────────────┤
                              │ 移到回收站…     │
                              └────────────────┘
```

| 项目 | 具体规则 |
| --- | --- |
| 重命名 | 列表行内编辑；顶部标题可进入同一编辑状态。Enter 保存、Esc 取消，提供可点击保存/取消按钮。中文候选词确认不得触发保存。失焦不静默保存或丢弃 |
| 标题校验 | 去除首尾空白后 1–80 个字符，不含换行或控制字符；空值在字段旁提示，不“恢复自动标题” |
| 并发改名 | 绑定读取时的标题；其他窗口已修改时提示冲突并保留输入，不默认覆盖。改名不改变最近对话活动时间 |
| 置顶 | 沿用既有上限和排序；服务端成功后更新。满额时说明原因。回收站中的记录不占正常列表的 50 个名额 |
| 移到空间 | 选择目标空间，显示普通/渠道与私聊/群聊；可搜索。当前空间不可重复选择。底部提供“新建普通空间并移入” |
| 选择多个会话 | 进入所属空间的管理页，预先选中这一条；不自动选中当前打开的其他会话 |
| 移到回收站 | 打开影响预览；需要先处理运行状态时，预览页给出具体处理按钮 |

已有分支/从某条消息重新开始功能继续放在对应消息操作中，不挤进会话管理菜单。会话菜单不增加模型、思考、权限或扩展设置。

### 4.2 入口与键盘规则

- 侧栏每行预留按钮位置，避免悬停时标题跳动。桌面在悬停、聚焦和选中时可见；触屏始终可见。
- 当前会话标题栏提供同一组操作；列表中操作非当前会话不切换阅读区。
- 点击目标至少 44×44px；图标可小于点击区；按钮不可嵌套在打开会话的 `<button>` 中。
- Web 仅在非编辑状态的会话行拦截右键。改名输入框保留文本编辑菜单；其他页面区域保留浏览器原生行为。
- 桌面会话行使用同一菜单定义，避免与现有 DesktopMenu 同时弹出。桌面其他区域沿用既有复制/粘贴菜单。
- Shift+F10/菜单键打开聚焦行的菜单。Tab、方向键、Enter、Esc、子菜单返回和焦点恢复完整可用。
- 现有 Navigation 会截获上下方向、Home/End。新增编辑输入框和菜单时必须绕过这段列表导航，避免输入光标或菜单被抢。
- 行因虚拟列表滚动卸载时，菜单关闭并回到可用的列表焦点，不把操作对象换成新出现的行。
- 已知运行中仍允许进入操作预览查看原因。不能只提供一个无法解释的禁用按钮。

### 4.3 空间菜单

```text
新建会话
重命名空间
管理内容…
空间设置
────────────
删除空间…
```

基础本地空间没有删除项。“全部空间”只是筛选项，没有改名、删除或渠道绑定操作。新建普通空间沿用现有权限默认值；不自动提升到 Full。

## 5. 移动、恢复与渠道会话替换

### 5.1 移动到普通空间

保留会话 ID、消息、工作目录、选定模型及明确能力选择。后续执行依据目标空间和入口重新计算权限，不继承超出目标范围的授权。权限变化在预览中说明。

同一受众和工作目录未改变时可保留仍有效摘要；受众变化按既有投影/摘要契约失效。不能一概声称移动会改变模型或工作目录。

### 5.2 移动到渠道空间

现有 `publishMovedText` 会生成该渠道可用的历史正文投影，并将相关附件标记为公开；不会把私有工具正文整体公开。预览必须列明“哪些历史文字/附件将成为该渠道模型可用上下文”，而不是只提示文件夹改变。

移动本身不主动向 TG 重发全部历史，但后续渠道回答可能引用公开内容。跨私聊/群聊或不同渠道的移动，必须对目标受众重新检查；不能只检查 `source != local`，也不能套用原 Bot/chat 的可见性。

会话能力中的明确排除（例如未选中 AffectWeave）必须保留，不因移动、恢复或替换会话而重新启用。受众不兼容的 Memory/能力选择可以撤销，但要显示撤销原因；不以删除选择记录退回“全部默认启用”。

### 5.3 TG 当前/默认会话

预览分别读取 `active_conversation_id` 与 `default_conversation_id`：

- 普通会话可以直接移走或移入回收站。
- 被任一渠道指针引用的会话，提供“新建并切换后移走”或“选择本空间另一会话后移走”。
- 替代会话必须属于同空间、未在回收站且符合现有路由条件。
- 单会话模式保持单会话；替换默认与活动指针，不暗中启用多会话。
- 多会话模式只替换确实引用目标会话的指针，不覆盖用户后来选择的另一个会话。
- 新建、设置必要继承项、切换指针和移走旧会话在同一 PG 事务内完成；重复提交返回原结果，不重新切回旧目标。
- 新建替代会话继承当前有效模型/思考选择及明确能力排除，权限按原空间重新计算；不复制消息、摘要、待执行输入、待投递任务或主动发送授权。
- 此操作保留 Bot 配对和访问授权。删除整个渠道空间则撤销该空间授权，见第 8 节。

当前实现的 `CreateActiveConversation` 不覆盖外部单会话模式，实施需要补通用事务能力，而不能简单从 UI 调用 `/new`。

恢复旧会话不抢回 TG 当前或默认指针。用户可以之后在渠道设置中明确切换。

## 6. 回收站生命周期

### 6.1 状态和入口

```text
正常会话 ──移到回收站──> 回收站（7 天）
   ↑                         │
   └────────恢复─────────────┤
                             └──到期/手动永久删除──> 会话内容不可恢复
                                                        │
                                            必要证据/文件清理可能继续保留
```

回收站入口位于侧栏底部；按当前 Owner、Core 和工作区显示可管理条目，标题可显示总数。它是专用视图，不新建一个可运行对话的“回收站空间”。

正常列表、搜索、渠道选择、模型历史回读和新请求都排除回收站会话；内部清理、备份和证据核验仍可按明确用途读取。不能把一个默认过滤器误加到所有存储调用，造成重启恢复或证据核验失效。

### 6.2 移入与撤销

```text
将「周报草稿」移到回收站？

7 天内可以恢复，之后自动清理会话内容。
回收站期间附件仍占用 3.2 MB。
如有必须保留的执行证据，会在明细中列出。

                       取消    移到回收站
```

- 服务端完成后才从正常列表移除。
- 可撤销提示至少保留约 6 秒，鼠标停留或键盘聚焦时暂停计时；关闭提示后仍可从回收站恢复。
- 撤销调用与恢复相同的受控操作。若渠道已换到新会话，撤销不自动恢复路由，不撤销已取消的任务或投递。
- 源空间仍在时可恢复到原空间；源空间已删除时选择普通目标空间，默认本地。
- 恢复时重算权限和受众；不恢复已撤销授权、不自动启动任务、不续送已取消内容、不重新启用主动发送。
- 恢复原置顶时若已满 50 个名额，恢复会话但不置顶，给出提示。

### 6.3 回收站页面

```text
回收站                              恢复所选  永久删除所选  清空回收站
搜索标题…   原空间：全部   排序：最近删除

□ 标题       原空间       删除时间       自动清理时间       附件大小
□ 周报草稿   工作         11-16 10:20    11-23 10:20       3.2 MB
□ 测试贴纸   TG 私聊      11-10 09:02    明天 09:02        —

12 个会话 · 附件 140 MB
必要证据保留 / 文件清理失败：按实际情况显示详情入口
```

支持只读查看、单选、多选、原空间筛选和分页。只读查看不支持发送、分支、重新运行或模型分析；不会触发扩展 hook。附件下载仍需 Owner 授权，并提示是回收站内容。

“清空回收站”指当前管理范围内的全部条目，确认页给出确切总数。应用了筛选时，“永久删除筛选结果”与“清空整个回收站”必须区分，不能用同一按钮表达两种范围。

### 6.4 七天清理

- 服务器保存 UTC 的 `trashed_at` 和 `purge_after = trashed_at + 168h`，客户端按本地时区显示绝对时间和剩余时间。
- 不因重复删除请求、刷新或更改原空间而延长时限。恢复后再次移入回收站算一次新的删除，重新计时。
- Owner 完成恢复且可安全维护后检查；运行期间每小时执行一次有界扫描。到期表示有资格清理，实际执行受扫描周期和停机影响，不能承诺精确秒级删除。
- 程序关闭期间不会运行；下次有效 Owner 启动后补处理。不新建 OS 服务、外部 cron 或通用调度器。
- 单次有数量/时间预算和游标，剩余条目后续继续；清理工作本身不能让按需 Owner 永不退出。
- 恢复与到期清理争用同一生命周期锁。清理尚未取得并提交删除资格时允许恢复；一旦永久清理已提交则返回不可恢复，不能“恢复成功”后又被旧清理任务删掉。
- 使用模拟时钟验收 168h 边界，不依赖真实等待 7 天。时钟回退不提前清理；检测到异常大幅向前跳变时停止当批自动清理并记录维护异常，手动清理仍需正常确认。

## 7. 活跃任务、未决操作与投递处理

删除预览负责告诉用户如何处理，不把清理功能变成批准业务操作的捷径。

| 情况 | 移入回收站的处理 |
| --- | --- |
| 运行中 | 提供“停止并结束本轮”；先请求停止，等执行边界和进程清理确认后，按已有 Abandon/结束规则关闭 |
| `stopped` / 尚未结清的 `limited` | 显示“结束本轮后移入”；不能把界面的停止状态当作已经可以删除 |
| 等待工具/控制面确认 | 撤回或拒绝该提案并结束本轮；不建议先批准以便删除 |
| 排队输入 | 列出数量并在确认中明确取消；禁止删除刚完成却被排队调度器再次启动 |
| 已交接的 UNKNOWN | 可移入回收站，未决事实、原编号和防重放继续保留；不强迫用户点“忽略” |
| 未交接的执行/提交 UNKNOWN | 按现有恢复规则先核验或可靠交接；无法确认的不能伪装为已安全结束 |
| 活着或失控的后台进程 | 请求停止并确认清理；未知进程尚可能继续产生作用时阻止清理，并给出现有检查入口 |
| 尚未派发的投递/主动发送候选 | 预览后取消，复用 outbox 放弃/取消规则；取消对应后续触发资格 |
| 已领取/正在投递的操作 | 等派发终结或可靠记录 UNKNOWN 后再移入；不能将已派发动作改写成“从未发送” |
| 投递 UNKNOWN | 保留原 outbox 事实，取消未派发尾段；既不重发未知段，也不把取消尾段等同于未知段失败 |

停止、结束、取消、移动本身都有独立结果，UI 只对服务端已确认的结果更新状态。一个预览可以列出并确认这些必要步骤，但不能把部分成功展示为全部成功。

空间删除涉及多个运行时，操作说明必须显示数量与范围。“停止并结束这些任务”不得影响空间外任务。停止超时或存储失联时保留原空间和会话，不继续删除。

生命周期门禁还覆盖模型提交、工具派发、队列采纳、协作子任务、主动生成、定时投递、附件上传/绑定、补发和恢复入口。门禁在实际派发/写入事务里复查，不只在按钮点击时检查。

## 8. 删除空间与清理空间内容

### 8.1 两个不同操作

- **管理内容**：分类、移动、移入回收站；保留空间、渠道绑定和权限。
- **删除空间**：删除空间对象及其设置，解除该空间渠道授权；默认把正常会话移到回收站。

```text
删除空间「工作项目」？

空间及其设置将删除。
☑ 同时将其中 128 个会话移到回收站（7 天内可恢复）
  不勾选时，会话移到本地空间。

渠道空间另显示：将解除这个私聊/群聊的授权，需要重新授权才能接收新任务。
会话可从回收站恢复；空间和渠道授权不会随会话恢复。

                              取消    删除空间
```

### 8.2 原子性与外键

1. 预览冻结空间标识、权限/路由修订、确切会话成员集合，以及处理方式。
2. 先完成必要的运行终止/取消准备；准备过程失败时，不删除空间。
3. 事务锁定空间和相关会话，重新核对成员与状态；发现新入站或新会话则要求更新预览。
4. 默认勾选时，将正常会话标记回收站；为满足空间外键，将记录挂到基础本地空间并保留原空间标识/名称快照，正常列表仍看不到。
5. 未勾选时，正常会话回到本地空间；已在回收站的会话仍保持回收站状态和原到期时间。
6. 更新附件授权归属、活动/默认指针、渠道授权及相关自动触发资格，再删除空间，整体提交。

空间最终删除使用一个原子提交边界，不沿用“每个会话一个事务”后直接删父空间的做法。空间太大、预计超出事务预算时，明确引导先在内容管理页分批整理，再删除空间；不截断成员列表或悄悄漏删。

删除一个渠道空间不会删除整个 Bot 配置或其他空间的配对。该空间授权撤销后，不把下一条消息自动当作已重新配对，更不能自动公开恢复出来的旧历史。

基础本地空间不能删除，但可以进入“管理内容”批量清理。删除空间不执行磁盘目录递归删除。

## 9. 空间内容管理与批量操作

### 9.1 页面和分类

从空间菜单“管理内容”、会话菜单“选择多个会话”进入；设置的数据管理区提供辅助入口。

```text
工作 · 管理内容                           移到空间    移到回收站
会话 128 · 附件 342（1.2 GB） · 回收站中有 6 个来自此空间

会话 | 附件与结果文件
搜索标题…   最近活动：全部   状态：全部   排序：最近活动

□ 选择本页       选择全部筛选结果（96 个，默认排除置顶）
□ 标题          最近入口  最近活动   轮次  附件大小  状态
✓ 周报草稿      Web      90 天前     12   3.2 MB   可整理
✓ 贴纸测试      Telegram 60 天前      4   —        可整理
□ 部署记录      CLI       2 天前     85   120 MB   置顶
□ 服务迁移      Web       1 小时前   30   —        需先结束任务

已选 2 个                                取消选择
```

| 类别 | 展示和操作 |
| --- | --- |
| 会话 | 标题、空间、最近入口、最近对话活动、轮次、附件大小和处理状态；支持移动、置顶、取消置顶、移入回收站 |
| 附件与结果文件 | 只列 Core 托管的上传附件和导出结果；显示所属会话、引用次数、大小及是否可删除 |
| 扩展数据 | 能力存在时提供已注册管理页入口，不把扩展数据库列成 Core 可逐条删除的内容 |
| 工作目录 | 显示现有路径与打开入口，不扫描整个文件树、不估算外部目录空间、不递归清理 |

首版“选部分删除”明确到会话和托管附件。任意删除会话中间的消息/工具片段会涉及协议组、摘要覆盖和证据，本期不加入；已有分支能力继续保留。

筛选包括最近对话活动（7/30/90 天前或指定时间）、置顶、空会话、分支、有附件、最近入口、是否有需先处理的任务。支持按最近活动、附件大小、轮次排序。没有可靠来源数据的记录参与“未记录”筛选。

改名和置顶不把老对话变成“刚聊过”。涉及时间筛选，使用明确的消息/运行活动依据；不能直接复用可能因管理操作变化的 `updated_at` 而不说明语义。

轮次和大小采用服务端聚合/分页，不在浏览器加载全部消息再计算。跨空间操作按目标受众分别预览。

### 9.2 跨页勾选的确定含义

1. “选择本页”仅选择当前已展示页；“选择全部筛选结果”由服务端解析完整过滤条件。
2. 全选生成确切 ID 集合，保存操作所需修订；不保存一个稍后重新执行、可能扩大范围的查询作为删除授权。
3. 正常回收操作默认排除置顶，可显式包含。清空回收站包含其全部条目，不再因原置顶而暗中跳过。
4. 修改筛选或管理范围后提示清空原选择；仅翻页和排序不改变已选 ID。
5. 大集合使用有界分页和既有操作记录保存分批清单；每批初值最多 500 项，确认针对完整冻结集合。后续批次不得把新出现的匹配项加入。
6. 显示“已选 96 / 成功 90 / 需重新确认 4 / 失败 2”，并可查看原因。实际失败不能仅作一条瞬间消失的 toast。

### 9.3 预览、执行与取消

- 预览包括动作、目标空间、确切对象、置顶例外、任务处理、公开范围、附件估算和证据保留；由服务端计算。
- 批量移入回收站/恢复/移动按单个会话事务提交，失败不回滚已成功项。空间对象删除另遵守第 8 节原子规则。
- 预览后若内容、排队输入、路由、权限、投递或生命周期有相关变化，受影响项跳过并提示更新预览。不能只核对标题或历史覆盖游标。
- “取消批量操作”停止尚未开始的项目，保留已完成项。恢复已处理项是新的恢复/移动操作，不声称回滚已撤销的投递或任务。
- 页面断开后以原操作 ID 查询结果；同请求键重试返回原结果，不能重复新建替代会话。
- 不为批量清理增加通用后台任务平台。使用既有控制操作记录加有界分批处理；是否继续下一批由明确记录的用户确认决定。

### 9.4 单独删除附件

沿用现有 `attachments.delete` 的永久删除语义：预览文件名称、字节数和引用它的消息数量；删除后消息显示“附件已删除”。运行中、上传/绑定中、分支复制中或已领取待发送的文件不能并发被物理移除。

当前分支复制附件为独立 ID/文件，不跨会话共享同一附件实体。删除原附件不删除分支副本；同一会话多条消息引用同一个 ID 时一起失效。不新增引用计数数据库，也不声称所有相同 SHA-256 文件都会删除。

删除附件无法撤回已发送给 TG、Provider 的数据，也不能自动擦除已经提取到消息、摘要、Memory 或扩展里的文本。界面说明“删除托管文件”，不承诺删除所有衍生内容。

## 10. 永久清理、证据保留与文件释放

### 10.1 清理范围

| 数据 | 永久删除会话时的处理 |
| --- | --- |
| 消息、普通 Run/Attempt、摘要、来源计量与缓存 | 按会话/Run/Attempt 的确切关联删除，必要证据除外 |
| 队列、会话模型/能力/Memory 选择、置顶、分支创建请求缓存 | 清理所属会话的状态；操作回执中仍需去重的标识保留最小形式 |
| 托管附件及暂存文件 | 先撤销引用，再由持久化清理清单物理移除；未引用草稿附件也纳入归属检查 |
| UNKNOWN、部分生效与防重放记录 | 不因删除、忽略或缺少分支而解除保护；保留必要原证据，见 10.2 |
| 渠道入站去重和 outbox | 保留终态去重、领取/回执关联、未知结果与取消事实；移除已不需要的正文副本，见 10.3 |
| 分支消息及其附件副本 | 属于独立会话，不连带删除；来源链接显示“源会话已删除” |
| 独立 Memory/Skill、扩展数据、工作目录 | 不随会话删除；失效来源链接显示不可回读，不把它们重新注入已删除会话 |
| 控制日志、备份及用户已下载副本 | 按各自现有用途和保留策略处理；不承诺被一次会话删除全部擦除 |

实施前建立静态的“记录前缀/表/磁盘路径 → 归属键 → 清理或保留规则”清单。覆盖 `fa.meta`、消息、Run、Attempt、控制日志、投递缓存和附件提交记录；禁止用 UUID 字符串包含关系做全库删除。清单由代码维护，不建设动态垃圾回收插件框架。

### 10.2 UNKNOWN 和分支证据

`ignored`、`user_confirmed_applied` 并不等于可以自动重做。当前防重放查询跨会话生效，因此即使没有分支，也必须保留仍适用的操作保护。

首版选择保留原必要 Attempt、相关证据和其依赖的最小 Run/会话骨架，复用既有未决、确认和 outbox 记录。普通消息、无关执行记录和附件可清理。不能为了宣称“全删”而把 UNKNOWN 改成成功/未执行，也不另建一套模型裁决或仅用一个未经验证的新摘要替代原证据。

保留的 Run 快照或原 Attempt 可能含参数、路径、配置快照或部分文本。删除预览和结果必须列出保留记录类别、数量及可估算的占用，明确它们不属于已释放内容。清理结果使用“会话内容已删除，保留 N 项执行记录”，不能显示“全部数据已擦除”。

保留骨架不出现在正常会话或可恢复列表，也不能提交新请求。Owner 从回收站/数据与连接中的“保留的执行记录”进入现有未决详情，仍可检查和确认；保留证据不能失去处理入口。

现有未决查询依赖 `contextReader`。实施需提供明确的 Owner 管理读取/核验路径，使证据仍可处理；不能为此把回收站重新开放给普通模型历史读取。

分支继承的原项编号和引用保持有效。源会话永久清理后，分支的 `branchSourceReady`、聊天投影、上下文回读要识别源已删除状态；已复制历史继续可用，必要防重放仍有效，不因源不可恢复而阻止所有分支运行。

保留证据仅在既有规则证明不再用于防重放、迟到协调或活跃引用后才可继续清理；没有足够依据时保留并说明。七天期限适用于回收站会话内容，不是取消执行保护的有效期。

### 10.3 入站去重和迟到回执

- 入站事件的“已接收/已采用/已取消”状态不能随消息一起清掉，否则旧事件重投可能新建并执行第二次。
- 清理时将无需完整内容的终态入站记录压成最小标识与指纹回执；保留原去重键。旧事件到达时确认已处理，不再次执行，也不路由到替代会话。
- outbox 保留原 operation、dispatch、group 和真实状态所需的证据；不可根据缺少原 Run 推断“可以重发”。
- 回收站期间收到迟到回执，可以更新原操作事实；不会生成新模型任务、续发尾段或恢复主动发送。
- 永久清理后收到迟到回执，只协调保留的投递证据；不经 `projectDelivery` 把正文重新插回被清理会话。
- 原投递仍在派发中的边界要先收敛。存储提交未知或 Owner 丢失时停下，不把无法确认的派发当作已取消。
- 去重/取消记录需要按来源协议确定安全保留范围；不能为了回收站“七天全删”把其寿命也硬设为七天。

### 10.4 数据库与文件不伪装成一个事务

1. 在有效 Owner 下取得会话生命周期、相关执行和附件锁，重新校验待清理资格。
2. 在 PG 事务内标记永久不可恢复，撤销文件下载/绑定权限，保存待删除附件 ID，清理可清理记录并保留必要证据。
3. 事务提交后删除确切附件文件。只允许经过 ID 校验的托管目录项，不使用用户提供路径，不递归删除工作区，不跟随符号链接/重解析点。
4. 成功或文件已不存在时确认该项完成；失败保留清单、错误与真实磁盘占用，下次维护重试。
5. PG 提交回执未知时先按原操作键查结果；不能猜事务失败后重新公开文件，或未确认数据库已撤权便删除文件。

现有附件清理已有基础互斥和孤儿扫描，但不完整覆盖“已标记 deleted、文件移除失败”的重试。本次扩展该流程，不平行实现第二套文件 GC。

文件尚未物理移除时显示“引用已删除，文件等待清理”，不显示已释放。PostgreSQL 普通删除后空间供后续复用，文件大小不一定下降；不为这个功能自动执行 `VACUUM FULL`。

备份与清理共享现有维护协调边界，保证备份中的引用、文件与生命周期一致。不能让备份刚复制数据库后，清理删掉备份尚未复制的附件。

既有 `control-journal.jsonl` 可能保留标题、组织快照、附件元信息及设置变更。不得用搜索替换 UUID 的方式改写其恢复依据。首版将这些记录列入保留说明；新增清理操作的日志只保存必要标识、确认范围和结果，不再复制完整历史。独立日志压缩另行按既有完整性要求设计。

## 11. 前端一致性、草稿与离线恢复

### 11.1 视觉和交互

沿用已确认的 FreeAgent 侧栏、阅读排版、语义颜色和 Radix 组件，不重设一套主题。管理页以内容列表和已选数量为中心；红色仅用于危险操作，正常移动、恢复和筛选沿用现有主色。

- 浅色/深色、长中文标题、长路径、空列表、加载中、错误、权限不足、部分成功均有明确状态。
- 桌面表格在窄屏改成可勾选条目，主要信息保持可读；不靠整体横向滚动才能找到删除按钮。
- 手机“选择”进入批量模式，底部操作栏避开安全区和软键盘，不遮住最后一条内容。
- 需要处理的阻塞项在页面内列明并可进入详情；不依赖禁用项 hover tooltip，触屏也能看到原因。
- 操作完成和错误使用无障碍状态通知；不因行排序、刷新或 toast 抢走输入焦点。
- 正在执行的批量操作有进度、取消剩余操作和结果明细；错误提示不能两秒后消失。

### 11.2 多窗口和草稿

当前消息、待发送请求和附件草稿位于内存及 `sessionStorage`；表单和秘密草稿为易失内存。服务端不能立即擦除离线页面或操作系统已经保存的副本。

- 在线窗口收到生命周期事件后重新读取权威状态，暂停该会话发送/恢复任务；清理对应待重试请求，避免刷新自动续发。
- 已写但未提交的输入保留为本窗口可复制文本，明确标注会话已移入回收站；永久删除确认中说明本地未发送文字的处理，不把它算作服务器历史。
- 永久删除时，执行操作的窗口清除该会话持久草稿；其他在线窗口清除对应存储和待发送状态。已经显示在输入框中的未提交文字可以暂供复制，不再写回持久存储。
- 断线、刷新、睡眠恢复后的窗口，对现有草稿关联会话做有界状态核对。确认已永久删除后再清理；不能因网络失败、临时未登录或权限错误直接丢弃草稿。
- SSE 只是变更通知；重连后通过快照/状态补查修复漏掉的事件，不能依赖一条不可补发的删除事件。
- 已删除会话的旧 URL 显示合适状态；不可见对象不泄露标题或是否存在。旧 URL 不自动创建同名新会话。

## 12. Core、CLI、AI 与扩展的职责

### 12.1 同一控制入口

Web、桌面和 CLI 共用同一组生命周期操作；AI 使用现有控制提案/确认流程。动作名称在实现时按现有命名确定，本方案不把尚未存在的 CLI 命令当作可执行指南。

| 操作 | 用户直接操作 | 模型提议 |
| --- | --- | --- |
| 重命名、置顶、移动 | 可执行；受众/权限改变先预览确认 | 现有控制提案，经用户确认 |
| 移入回收站、恢复 | 可执行；批量和连带取消显示影响 | Owner 允许范围内提案并确认，Full 也不能绕过 |
| 删除空间 | 显式确认包含会话处理方式与渠道撤权 | 复用现有提案，但必须明示处理方式 |
| 永久删除会话、清空回收站 | Owner Web/桌面/CLI 显式操作 | 新操作不向模型开放 |
| 单独永久删除附件 | 复用既有确认与回执 | 沿用既有 `attachments.delete` 提案能力，不借本次功能偷偷撤掉 |
| 自动清理到期会话 | 系统按已确认的回收站规则执行 | 不由模型驱动 |

CLI 支持列表/筛选、预览、执行、原操作结果查询与回收站恢复。永久清理与批量操作使用明确确认参数；非交互执行也必须绑定预览 ID/摘要，`--yes` 不能授权重新计算后扩大范围。

删除空间的新 UI 默认勾选，不意味着旧 API 缺省参数可以从“保留会话”静默变成“删除会话”。新 API/CLI 必须显式传 `trash_conversations` 或 `keep_conversations`；旧客户端请求保留旧行为或明确要求升级，不能套用更危险的新默认值。

### 12.2 在对话里删除当前会话

模型可以提出整理建议，但确认时目标会话可能正运行这条提案本身。受控处理必须：

1. 确认提案是该 Run 当前唯一等待中的控制动作，没有其他在途副作用。
2. 持久化用户确认、补齐控制结果并可靠结束该轮。
3. 再按生命周期操作移走/回收目标；失败时从独立操作记录恢复，不重新调用模型或工具。
4. 结果显示在管理操作卡片和列表，不要求向已回收会话再追加模型答复，也不自动外发 TG 通知。

如果无法证明符合这条边界，明确提示先结束本轮再操作，不通过放松所有 active Run 检查来解决。

### 12.3 扩展与主动发送

- Core 只取消/禁用指向目标会话的通用后续触发与投递资格，不理解 AffectWeave 人物、情绪、关系或记忆结构。
- 回收站恢复不自动复活旧主动发送授权。用户需要在既有入口重新启用；界面说明哪些授权被取消。
- 回收站只读查看不启动扩展，不向原已停用扩展发起数据查询。
- 扩展数据管理入口只在该能力实际支持时出现，不捏造数据大小或“自动联动删除”。
- 通用“会话已永久删除”通知可作为后续可选项，必须版本化、幂等且只提供必要身份范围；本期不依赖该通知实现清理，不因此增加插件 UI 或第二套生命周期框架。
- 已明确未选中 AffectWeave 的 TG 会话，移动、恢复、替换及升级后仍不得自动选中。

## 13. 数据布局、预览契约与兼容升级

### 13.1 数据布局的最小选择

不沿用草案“固定新增两列就足够”的结论。两列无法表达原空间删除、恢复代次、不可恢复骨架和文件清理失败，也没必要为了它们先建新数据表。

首选在现有 `fa.meta` 保存有版本的 `conversation/lifecycle/<id>` 记录：正常会话可无记录；回收站记录包含状态、删除代次、UTC 删除/到期时间、原空间 ID/名称、删除操作引用及恢复所需的置顶信息。会话彻底清理后，仅在去重或证据需要时留下不可恢复标记/骨架。

待删附件、批量清单和操作回执使用既有元数据/控制日志机制，保存有界且有归属的记录。不复制一份对话正文作为回收站副本。

恢复后保留足以拒绝旧请求的删除代次/操作回执；不是删除生命周期标记就忘掉上一轮删除。旧删除请求重试不得回收已恢复的会话，旧清理请求不得命中新一轮回收记录。永久删除 ID 不复用。

列表使用普通、静态的 PG 查询与 lifecycle 标记过滤；通过查询计划和代表性数据验证。若验证确需新增列或索引，在实施记录中写明原因和迁移，不把“不改结构”当成硬指标，也不引入 SQL 自动改写框架。

### 13.2 预览有效性

预览不复制整段消息，不仅绑定所谓“历史版本号”。按操作需要至少覆盖：

- 对象 ID、生命周期/删除代次、标题与置顶等被修改字段；
- 空间归属、当前/默认渠道路由、权限和访问授权修订；
- 消息/运行序号，非终态 Run/Attempt、排队输入与后台命令状态；
- 相关 outbox/候选投递、附件归属与状态，必要的分支/未决引用；
- 用户确认的取消项、替代会话及新会话继承范围。

由服务端生成有限清单/摘要并在事务内重新读取有关状态。不能沿用一次全仓库快照导致任意无关会话改名也使整个清理失败；也不能缺少关键派发变化而错删。

实现需书面固定锁顺序，将空间路由、会话创建/输入、执行、outbox 领取和附件复制的既有锁纳入检查。HTTP 边界检查不能替代真正写入时的门禁。

### 13.3 升级和旧客户端

即便首版只增加 meta，也改变了“会话存在就可执行”的存储语义。旧程序不认识回收站，可能重新展示或使用被回收的会话，因此必须拒绝旧版本打开并写入升级后的库。

当前 `verifyPostgres` 已校验 `schema/version`、`schema/source` 和实际 schema identity。实施要交付显式、可恢复的版本迁移，协调这些校验；不能绕过结构验证或仅在前端隐藏数据。

- 升级前核对 Owner、正在执行的任务及渠道投递，验证完整备份。
- 迁移期间独占维护，保留原始记录，不在首次启动时自动回收已有会话。
- 中断后明确处于旧版或新版有效格式，重复迁移可核查且幂等。
- 备份恢复入口需要能够识别本次升级前格式，不能因为新版只认新 schema 而无法回退。
- 旧 Web 构建连接新版时提示刷新；旧 CLI 对新操作不默默忽略参数。
- 回退保留升级后的数据副本，再恢复升级前程序与同一时点备份；不只替换二进制。

## 18. v8.8.0-dev.9 实施结果

P0–P2 已实施：生命周期与存储迁移、真实写入门禁、统一菜单、空间内容整理、回收站/恢复/永久删除、到期维护、托管附件清理、控制日志、CLI/AI 提案及当前会话的受控结束后整理。独立扩展不增加业务数据清理规则。

落地选择和约束：

- 使用现有 meta 和控制记录；没有新增业务数据表、Run 枚举、调度器或通用清理框架。schema 2 新增数据库门禁函数/触发器，保留旧版 SQL 源用于核验与显式升级。
- 既有 `space.delete` 保留兼容行为；新 UI/管理 CLI 显式指定会话处理方式。AI 可以在 Owner 允许范围提议删除空间并明示 `trash_conversations`，不能提议新的会话永久删除。
- 会话批次最多 500 项，完整操作最多 5000 项，预览有效 15 分钟；空间删除独立原子事务最多 5000 条会话记录。批量取消在当前批次后停止，不声称回滚已完成项。
- 普通分类保留明确能力选择；非 Owner 私聊的渠道目标撤销私人能力并保存为空，避免继承全局默认。TG 替代会话保留明确排除，恢复不重新授予主动发送资格。
- “最近入口”使用实际 Run 记录，本机入口未继续细分为 Web/桌面/CLI。活动筛选按创建/Run 活动时间；排序保留选择。
- 7 天是 168 小时，Owner 启动和每小时扫描有界执行；异常前移跳过当批并给出维护提示。文件清理使用持久重试与扫描游标，显示未释放占用。
- 保留的执行记录和投递回执有只读查看/处理入口。模型历史与普通新请求仍拒绝回收或永久删除的会话。

当前代码通过完整 Go 回归；最后收尾另完成渠道/扩展/控制专项与 race 验证。真实旧 dev.8 程序拒绝 schema 2、旧格式备份恢复、Owner 确认后自整理、公网登录/CSRF、265 条会话分页与冻结批量、文件失败重试/分支副本、恢复与清理竞争均有测试。

Windows/Linux 归档各重复构建两次且字节一致，原生 Windows 桌面与 Hytron 独立非 root Linux 运行验收通过。程序源码与发行标签为 `515c1c5d9b2f4ca3dbb7f305991cdaf0d8580748`，已发布 [v8.8.0-dev.9](https://github.com/endview/FreeAgent/releases/tag/v8.8.0-dev.9)。

Hytron 已备份并迁移到 schema 2，Core/渠道正常、TG 重连、公网资源匹配新 Owner。7 个会话、114 个 Run、692 条消息、526 条 Attempt 和独立 AffectWeave 数据核对保留；获准结束一条旧 stopped Run，两条排队输入仍保留并暂停。升级没有自动回收任何生产会话，TG 明确未选中 AffectWeave 的状态保持。
