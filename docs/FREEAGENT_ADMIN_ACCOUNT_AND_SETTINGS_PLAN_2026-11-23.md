# FreeAgent 实例管理账号与统一设置实施计划

日期：2026-11-23。状态：已按 dev.7 源码审计修订，待实施。源码基线为已发布的 `v9.0.0-dev.7`；编写时 Hytron 常驻为 `v9.0.0-dev.6`。这是独立工作项，不是 v9 的 W0，不重排已交付的 W1–W5，也不替代[正式版真人验收](FREEAGENT_V9_0_CHANNEL_CHATBOT_PLAN_2026-11-22.md)。下文“验收”均指放行条件，不表示已通过。

**交付目标：实例管理员用自己的用户名和密码登录后台，无需编辑配置文件，就能通过合适的入口配置模型、渠道、空间、工具及可选能力，并批准 AI 提出的具体设置变更。** “能管全部设置”不代表每个入口都能批准全部操作，也不代表宿主执行权限。

## 1. 范围与归属

首版每个实例只有一个管理账号：不开放注册，不设角色，不用共享密码代表多名可独立撤权的人。如果以后需要多人管理，增加同权限的独立账号即可，不必先做 RBAC。Owner 专指唯一写入进程，不是账号名。

| 谁负责 | 复用什么 | 本计划改什么 |
| --- | --- | --- |
| 认证与管理入口 | [公网凭据](../internal/publicweb/credential.go)、[认证会话](../internal/publicweb/auth.go)、[本机交互入口](../internal/chatui/attach.go)、CLI、桌面与 Web | 增加账号名、稳定账号 ID、首次设置、恢复、会话撤销和敏感操作再次验证。不把账号密码传给模型或连接器。 |
| Core 设置控制 | [操作目录与确认日志](../internal/harness/control.go)、[Web 直接保存流程](../internal/chatui/control.go) | 校验入口、提案范围、实际变更、修订与本次确认，记录发起人和决定人。不另建设置数据库、审批队列或用户权限引擎，不改模型与工具执行循环。 |
| Provider、连接器与扩展 | 原有模型与凭据入口；[连接器状态存储实例](../internal/harness/connector_confirmers.go)；[扩展状态契约](EXTENSION_STATE_CONTRACT_V2.md) | 各自解释参数、验证目标并应用修改。TG 身份和绑定归连接器；Skill/MCP 的启用、安装与信任由宿主管理；AffectWeave 人物、回复方式和主动对话归扩展。 |
| 客户端 | [设置页面映射与覆盖现状](FRONTEND_SETTINGS_COVERAGE_V8_1.md) | 保留现有专用表单、草稿与冲突处理，补缺失的保存入口；不要求为了统一而重做所有页面。 |

管理员可以修改资源授权，例如把一个人物授权给某个空间；工具实际执行时，仍由所属模块检查资源权限。修改授权也不能代替原请求人批准工具调用。Run、Attempt、投递回执、已发送消息和审计事实均不属于设置；UNKNOWN 仍走原核查流程，不因设置保存而重放。

## 2. 从哪里能改什么

| 操作 | 受信本机 CLI、桌面、本机 Web | 已登录公网 Web | Telegram 私聊 | Telegram 群或话题 |
| --- | --- | --- | --- | --- |
| 普通产品设置，如默认模型、压缩、搜索、扩展配置 | 直接保存 | 在允许的管理路由保存 | C 启用后，只确认 §4 清单准许的精确单项；其余按下述转交规则 | 不确认全局设置或展示差异 |
| 原有会话设置 | 控制服务保存 | 同一控制服务保存 | 原规则：已准入、在确认名单内的原请求人确认当前会话模型或已选扩展选项 | 原规则：本群已准入且在名单内者可确认已选扩展的一个选项，不能切群模型 |
| Provider Key、TG Token：新增、替换；变更已有 Key 的发送端点 | 专用安全输入，核对凭据用途和目的地 | **允许。** 当前会话 10 分钟内验密、提交时再核对目的地；秘密只写不读 | 不接收秘密；不生成带密钥的提案 | 同左 |
| 其他安全设置：确认名单、管理绑定、资源共享、收紧权限等 | 显示影响，明确确认 | 再次验证后办理；如同时扩大宿主执行授权则适用下一行 | 不直接确认 | 不直接确认 |
| 引入新的宿主可执行内容、扩大宿主执行授权，或提高公网入口自身的权限上限 | 本机核对原提案并明确批准，必须有 CLI 入口 | **只能提案，本机批准前不得写授权或启动候选代码。** 再次验密不改变此限制 | 不批准；仅符合转交条件时指向本机办理 | 不批准，不展示预览 |
| 首次创建账号、遗失密码恢复、首次开启公网入口 | 本机专用，有 CLI 入口 | 不开放匿名认领或遗失恢复；已登录改密另走验证 | 不办理 | 不办理 |

“本机”指持有该实例的交互凭据，或有权管理该实例受保护数据目录的操作系统身份。仅访问回环地址、能运行 CLI 程序、持有只读 attach 凭据，均不等同于管理员。保留[公网权限上限的本机确认规则](../internal/harness/public_policy.go)以及公网路由白名单。

**按实际效果判定。** 安装或更新可执行扩展、首次启用新代码、修改 stdio MCP 的启动命令/参数或影响执行的环境、放宽命令白名单、扩大可执行的宿主目录，均须本机批准。检查必须在首次副作用前执行，覆盖直接接口、测试、导入、启用、更新、重启和回退，而不仅是保存按钮。例如，[现有 MCP 导入会在保存前测试连接](../internal/chatui/mcp.go)，因此预览只能读取声明，不能为预览启动候选进程。已批准、实际内容和授权均未变化的正常运行无需反复审批。无法证明候选内容未变或混合了多种变更时，取更严格的规则。

**同一张提案如何转交。** 对一次请求先区分三种结果，再决定是否建提案：

| 判定 | 接下来的行为 |
| --- | --- |
| 可以在当前入口办理 | 直接保存，或由人在当前入口确认 AI 的原提案；模型不自批。 |
| 有权提出，但须转 Web 或本机批准 | 沿用现有操作记录，保存一次待决提案，指定允许决定的入口、原作用域、期望修订、差异摘要和有效期。原 Run 完成交接，不占用会话、不再调用模型；渠道只回中性提示和认证后可打开的定位链接。须本机批准时，Web 只能查看并给出同一操作 ID 的 CLI 办理方式。 |
| 根本无权提出，或包含不能进入提案的秘密 | 不建可批准记录，不透露资源是否存在或具体差异。对密码、Key、Token 仅提示管理员到专用表单输入。 |

链接不是授权，不携带批准码、秘密或差异，打开不产生副作用。目的入口重新鉴权、展示原提案，并为本次决定取得自己的交互凭据；提交前复核权限、原修订、目标、期限及撤销状态。修订变化须重新预览和确认；若原记录已终结，保留原记录，允许从非敏感意图生成关联的新预览，不要求用户重填，也不能静默改绑批准。多端同时点击最多写一次。

这是新增的交接能力，不是假设已有深链：[现行模型提案先做入口校验](../internal/harness/control_tools.go)，[已脱离 Run 的提案](../internal/harness/control_detached.go)限于特定会话操作。扩展现有控制流程，区分“允许提案但须换入口”和“不可提案”；不要在错误入口先尝试应用、记成失败，再让管理员另建一张。

## 3. A 批：管理账号、迁移与审计

### 3.1 无桌面服务器的首次接入

1. **在 SSH 终端创建账号。** 管理员解压发行包，用随包安装/初始化命令准备实例，运行拟新增的 `freeagent admin init`，隐藏输入密码并重复确认。账号写入成功立即关闭首次创建入口，最后询问是否开启公网 Web，默认“否”。跳过后本机 CLI 仍可用；日后可单独开启。桌面和本机 Web 须有既有交互凭据；SSH 隧道不是身份凭据。首版不做公网 `setup-code`。
2. **从 CLI 开启公网。** 拟增 `freeagent public enable`，与上一步的“是”共用实现。它在当前有效配置上仅更新所需字段：HTTPS Origin、受限 Unix socket、专用代理组、远端权限上限和启用状态。显示差异，明确确认后复用已有的 [`public configure` 控制操作](../cmd/freeagent/public.go)，保留其他安全设置；不新增公网 TCP 直连入口。检查凭据、代理身份/组和 socket 权限。需要重启时区分“配置已保存，待重启”和“公网已可登录”，给出本机操作及 `public status` 核查方式。
3. **登录并接入模型、渠道。** 在浏览器通过 HTTPS 登录，用专用安全表单保存 Provider Key，单独测试连接、选定默认模型并发起对话；需要 TG 时写入 Token、核对 Bot 身份、启用连接，核准指定私聊申请，再核对回复。模型或 TG 测试失败只重做该步骤，不撤销账号、不重开认领入口。扩展、Skill 和 MCP 均为可选。

**基础设施边界：** 域名/DNS、可用的 TLS 证书及按目标 Origin 指向受限 socket 的反代由部署方提供，专用 Unix 用户/组及运行目录按[随包安装与代理约定](PUBLIC_WEB.md)准备。这是端到端验收的明示前提，不由账号向导代办，也不修改既有代理站点。缺前提时说明缺哪一项，保持本机可用，不退回匿名 HTTP 或开放 Owner 端口。

**A 批须补的公网入口：** dev.7 的[公网路由白名单](../internal/chatui/public.go)已允许 Provider Key 写入，但未包含[渠道凭据专用处理](../internal/chatui/channel_credentials.go)，[渠道页](../internal/chatui/frontend/features/settings/ChannelSettings.tsx)在公网模式也不显示秘密输入。A 同时接通 TG Token 专用表单和受限写入路由，并对两类凭据落实再次验密。仅列出非秘密引用；不得将整个本机或 attach 路由开放到公网。

**本机专用操作均须有 CLI 等价入口。** 覆盖账号初始化、恢复、首次开启公网、查看/拒绝/批准待决提案，包括提高公网权限上限和引入新宿主代码。复用现有 [`control list`、`control confirm --operation`](../cmd/freeagent/control.go) 和等待中 Run 的 `preview --run` / `confirm --run`。现有 CLI 会把绑定 Attempt 的操作导向 Run；对**已结束 Run 的转交提案**须补按原操作 ID 查看、预览、决定的本机路径，不要求复活 Run。直接保存被退回本机时应返回原操作 ID 和准确办理方式。

### 3.2 初始化与迁移判定

只判断账号材料，不以有没有对话或是否装过 TG 区分实例。已有效初始化的新格式账号正常启动，不触发迁移。其余只有三种处理：

| 状态 | 行为 |
| --- | --- |
| 无凭据文件、无账号元数据，且无账号初始化或迁移中断的证据 | 仅受信本机可创建，公网管理保持关闭；并发创建至多一次成功。旧实例原有本地使用、已准入渠道和显式能力选择保持不变，不停 Bot；新实例也不自动开启渠道。 |
| 有有效旧公网凭据，且无已迁移或迁移中断的证据 | 为原凭据建立稳定账号 ID 和默认用户名 `admin`，迁移幂等；原密码有效，不索取明文。已有公网用户重新登录一次。 |
| 凭据损坏、已有初始化标记却缺少凭据或账号元数据，或迁移中断 | 关闭公网管理，保留证据，只能受信本机核查/恢复；不能当成“无账号”重新认领或重发账号 ID。 |

**会话与恢复。** 登录改用用户名加密码，延续现有的密码哈希、限速、Secure/HttpOnly/SameSite Cookie、CSRF、空闲及绝对有效期。用户名可改，审计用的账号 ID 不变。保留独立的浏览器会话 ID，用于绑定确认卡、附件、CSRF 和撤销；不能把现有的会话身份一律替换为账号 ID。设置页可查看当前及其他活动会话并撤销指定会话，不回显认证令牌。

公网安全级操作要求**当前会话最近 10 分钟内验证过密码**，服务端提交时再检查。填表期间超时：留在当前页，保留非敏感草稿；清空秘密输入，重新验密、补输秘密并核对修订后，由用户继续提交。验密成功本身不触发保存。改密仍核对当前密码；遗失时通过拟新增的本机 `freeagent admin reset-password` 恢复。两者都更换凭据代次，撤销全部旧 Web 会话及其待用确认，暂停依赖旧代次的渠道管理绑定；已执行的操作不回滚。已有 `public password` 命令复用同一受保护写入与撤销逻辑。

**存储与审计。** [dev.7 凭据读取与写回](../internal/publicweb/credential.go)与 dev.6 相同：读时忽略未知字段，但要求 `version == 1` 和既有哈希参数；旧版改密会从旧结构重写整个文件。保留 `public-admin.json` 的版本、Argon2id 参数、盐、哈希和代次的位置及含义；稳定账号 ID、用户名、已绑定的凭据代次另存为同等保护的账号元数据，不依赖旧版保留未知字段。旧版改密后，新版须识别代次变化，保住账号 ID 与用户名，失效旧会话、旧确认和管理绑定，不还原旧密码。两份材料在同一实例写锁下分步原子替换，中断可识别且不得开放认领；没有第二份密码来源。

在线由 Owner 协调写入；离线须核实数据目录权限及独占写入。审计绑定稳定账号 ID（或本机维护来源）、入口、原提案、修订和结果，不记密码、Key、Token 或哈希。事务提交时再核实代次，避免撤销后的并发点击仍可生效。

### 3.3 A 批放行条件

1. **无桌面首装。** 在具备 §3.1 前提的干净 Debian 上，用发行包从 SSH 初始化、开启公网、必要时重启并核实 HTTPS，到 Web 写入 Provider Key、取得模型答复、写入 TG Token、批准测试私聊并取到投递回执。全程不手改文件、不借本机浏览器代替公网。隔离自动化用模拟端点；真实模型/TG 使用已授权对象，分别报告，未做记 `NOT_RUN`。
2. **账号与凭据。** 在独立目录演练三种迁移状态、重复启动、并发初始化、恢复、单会话撤销、双窗口不可互用原卡和暂存附件、改密后全部重登；缺失本机交互凭据不能初始化。公网写 Provider Key 与 TG Token 均验证验密、CSRF、过期草稿、端点变更、无明文回显；不能只放行路由而仍隐藏表单。完成 §6 的凭据往返演练。
3. **本机批准与转交。** 从公网分别提出提高自身上限和引入隔离测试组件的变更。不论从设置页、控制接口、测试或导入入口发起，本机批准前实际策略不变、候选进程启动次数为零。SSH CLI 能列出并预览原操作，拒绝不写，批准只应用一次；错误会话、过期提案或修订变化均不能套用原确认。A 不等 B 的全量盘点：还不能安全判定的宿主执行变更先拒绝公网执行，明确本机办理途径。

## 4. B 批：让可修改设置真正能保存

**盘点范围有边界。** 以当前版本 [ControlOperationCatalog](../internal/harness/control.go) 的操作、`Config` 对外配置的叶字段及[前端 settings-map.json](../internal/chatui/frontend/settings-map.json)登记项三者的**并集**为基线，按资源/操作/字段去重。明确补列不在三者内的账号、Provider/渠道凭据、连接器专用管理入口，以及已加载模块**公开声明**的管理项；不扫描第三方业务表或把内部字段推断为可写设置。新增模块对其声明走同一覆盖校验。

每项登记：归属模块和范围、读写或只读及原因、各入口能否提出/决定、风险与敏感性、用什么操作保存及校验哪个修订、生效时机、从哪里回读。秘密登记专用写入和无明文回读；派生值登记只读。**有页面映射不等于可以保存。**

**清单中的“可在 TG 私聊确认”是经评审、版本化的后端规则，默认否，不是前端开关。** 它与“可从该入口提出并转交”分列。C 启用后首版仅两行允许直接确认如下；除列出的字段外，还必须验证最终差异。连接器使用已有目录和规则，不再复制一份名单或在 Core 执行循环逐项特判。

| 唯一候选操作 | 在已绑定私聊确认的条件 |
| --- | --- |
| `runtime.set_limits` | 只提交 `auto_compact_percent`，值满足既有范围；实际仅该阈值改变。夹带输出额度等字段即不能在 TG 批。 |
| `model.set_default` | 只选已有可用模型；前后为同一受信 Provider 端点和凭据，能证实未扩大数据发送范围。不能借机增改模型配置、Key 或地址。 |

以后增加受支持项，需审查所属模块的差异校验与测试后更新清单；现有规则无法表达的先保持禁止。登记为可提案但不可在 TG 决定时，走 §2 原提案转交；两种资格都没有就拒绝。

1. **核对 Core、模型和搜索。** 覆盖上下文窗口与 HTTP 字节保护、压缩阈值、默认模型、思考强度、Provider 地址与凭据、搜索选择。普通表单直接保存；AI 提案显示原值、目标值、影响范围和生效时机，由人确认一次，不把一次批准变成持续权限。
2. **核对渠道、Skill、MCP 和扩展。** 管理入口使用相同的授权、修订与审计规则，写入仍走所属模块。复用现有声明及 `read / preview / apply / result` 语义，不要求全部模块换存储或公开一套新 RPC。AffectWeave 管理人物与授权应分别预览；仅在安装或选中后适用的选项不能变成 Core 默认能力。
3. **敏感值不进通用链路。** 密码、Key、Token 和敏感环境变量通过专用安全输入提交；通用设置、提案、草稿、差异、日志和模型只见非秘密引用或“已设置”。末四位仅限原规则允许显示提示的长 Key，密码不显示。测试连接与保存分开，测试通过不能写成已保存。
4. **检查保存结果。** 提交时复核原操作、当前授权与修订；冲突不覆盖，保留非秘密草稿并支持回读。模块回执丢失时按原操作 ID 查询结果，不重发可能已执行的写入。区分已保存、下一轮生效、需重启、未应用和待核实。

**B 批验收分两层：**

- 在[现有设置覆盖测试](../internal/chatui/settings_coverage_test.go)上增设必填校验。注入一个新配置字段或新操作：未登记、缺归属、缺入口判定、缺保存/回读方式均须使 CI 失败；只读或专用入口要有理由。仅登记页面名仍不合格。
- 每个可写项至少有一个受信管理入口；承诺 Web 可改的项须在该页实测保存、刷新回读，不能用 CLI 可用替代。共用路径覆盖重启、并发冲突、验密超时后的非敏感草稿和无秘密泄漏。用浏览器复测长度预算、模型思考设置、渠道凭据和一个已选扩展选项。无可选模块时账号、模型配置、基础对话仍独立可用。

## 5. C 批：可选的 Telegram 私聊管理绑定

这是管理员对**特定私聊操作**的委托，不是给 TG 用户签发 Web 登录身份。默认没有绑定，只能在受信本机或已再次验密的公网管理页建立、暂停或撤销。以每个 Bot 为单位，绑定管理账号、平台核实的本人数字 ID 和凭据代次；平台身份由连接器维护。既有聊天准入、[会话设置确认名单](../internal/harness/connector_confirmers.go)和工具审批各自独立。**绑定不自动加入确认名单，进入名单也不获得管理绑定。** 不给整群授权，不推断不同渠道里的同名用户是同一人。

- **全局单项取自 §4 清单。** 只在本人已绑定且获准的私聊中展示原值、目标值、生效时间和“全局”范围。清单允许发起但必须换入口的，不带私有差异提示原提案链接，结束本轮；秘密或无权提出的请求不落为待决提案。
- **一次决定只对原提案有效。** 连接器核对已绑定的原发起人、Bot、私聊及原卡；宿主核对原提案、账号与绑定代次、当前准入、修订、期限和完整目标。只接受经认证桥接提交的这次决定，不信任入站消息自称“管理员”。批准最多写一次，由宿主回告结果，不重跑模型。群或话题遇到全局设置只提示转管理页，不展示差异。
- **撤销不靠事后清卡。** 解绑、改密、恢复或撤权后，点击时的复核须能立即拒绝旧卡；重新绑定不能复活旧卡。原本独立授予的会话确认资格不随管理绑定增减。没有可信按钮或回调的其他渠道不提供此入口。

**C 批验收：** 用隔离夹具验证仅在旧确认名单内、绑定但未准入、私聊正例、错误点击人或 Bot、跨群/话题、重设后重绑、夹带其他字段。另测合法的“提出但不能在 TG 批”请求：Web 登录后打开同一提案，TG 不显示差异，原 Run 不阻塞聊天；链接被转发也不授权，修订过期须重新预览。重复点击或两端同时决定最多写一次，核对实际修订、模型调用数和平台回执。真人验收先指定获准目标与动作，条件不具备记 `NOT_RUN`。

## 6. 发布与回退

A 先交付无桌面初始化、账号恢复和 Web→本机的安全交接；B 的盘点可与 A 并行，完整验收使用 A 的真实账号。C 依赖 A 的身份/撤销、B 的入口清单及差异校验；若暂无 TG 私聊管理需求可整批推迟，不阻塞 A、B，也不改变原有会话确认规则。各批验收后可出预发行版，具体版本号按实际发布线确定。

**A 批必跑的凭据往返演练：** 使用隔离数据和测试密码，分别覆盖 dev.6、dev.7 旧程序。先由旧密码迁移，新版改密并撤销先前会话，在独立目录切到旧版，验证**新密码可登录、旧密码不可登录**；再用旧版改密并升回新版。验收稳定账号 ID、用户名未丢失，只有最后一次设置的密码有效，旧会话/旧确认不能重用；已有绑定或等价的旧代次夹具不得复活，C 启用时再用真实绑定逻辑复测。不得通过拷回旧密码文件来制造通过结果。

**上线与回退边界：** 先在独立 PostgreSQL 环境验证 Windows/Linux 发行包；发布后比对 GitHub 附件与已验包产物的摘要。常驻切换前核对活跃任务、渠道及可恢复备份。凭据、账号元数据、属主权限和对应程序只在私有维护范围保全，不打入普通产品备份或发行包。旧程序即使能读密码，也不具备新版的入口限制；若不能维持同等保护，须在切换前关闭公网管理并核实外部不可达，使用受信本机恢复，不静默降级。不得覆盖升级后产生的对话或复活已撤销的授权。

Hytron 的密码由管理员自行输入，核对原对话、准入、名单、工具权限及 AffectWeave 数据保持一致。分别记录“已发布”“隔离验收”“已更新常驻”；本计划不代表已发布、已迁移或获准真人发信。出现匿名认领、意外扩权、未批先执行、旧 Bot 停服或秘密泄漏即停止放行。
