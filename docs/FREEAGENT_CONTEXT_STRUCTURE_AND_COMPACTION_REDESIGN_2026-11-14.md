# FreeAgent 上下文结构与压缩实施计划

日期：2026-11-14。状态：三批实现已接入，正在进行完整回归、双平台和真实模型验收；尚未标记发布完成。实现对应 `v8.8.0-dev.2`。

基线为 `v8.8.0-dev.1`、产品提交 `cd6f1a8`。线上数值引用 [11 月 11 日审计](FREEAGENT_CONTEXT_MANAGEMENT_AUDIT_2026-11-11.md)，不是本次重新测量值。使用说明见 [上下文管理](CONTEXT_MANAGEMENT.md)，记录来源和写入清单见 [上下文记录契约](CONTEXT_RECORD_SOURCES.md)。本文规定验收目标；审计文档保留原故障证据，实际通过项和未测项另记，不以实现状态替代发布验收。

实施分为三批：**修正确性 → 减少超限 → 提高摘要质量**。第 10 节规定交付范围，第 11 节规定发布门槛；后面的优化不能阻塞第一批修复。

## 1. 重新判断

现有“完整历史持久保存、请求按需装配、摘要与原始证据分离”的方向可以保留。主要问题是历史选择、消息分组、预算与恢复没有形成一致的边界。继续增大限额、追加失败重试或增加记忆层，无法修复这种不一致。

方案收敛为：**一份原始记录、一个按需计算的上下文投影入口、每种有限授权视图一个滚动摘要检查点。** 每次请求只使用与当前视图匹配的检查点。GUI、CLI、TG 共用；差异来自当前授权与能力选择，渠道本身不另做摘要、记忆或历史裁剪。有限分槽规则见 4.5，不按用户无限建立摘要缓存。

主流程为：

```text
持久记录 + 当前授权/配置
        ↓
统一上下文视图：筛选来源、组成完整工具组、确定可压缩边界
        ↓
装配：规则 + 参考材料 + 摘要 + 近期原文 + 当前输入/运行状态
        ↓
预算判断 ──需要压缩──→ 同一视图中的旧完整组 → 新摘要候选
        ↑                                      ↓
        └──────── 重建、校验、原子保存 ──────────┘
        ↓
Provider 编码与模型请求
```

这是现有 Core 内的函数边界调整，不是新增服务、调度器或数据库。

## 2. 分清四种数据

| 数据 | 用途 | 保存与修改规则 |
| --- | --- | --- |
| 原始记录 | 聊天、工具调用与已捕获结果、审批、投递、失败与 UNKNOWN 的事实来源 | 复用 PG 现有记录；压缩不改原文，不把摘要当执行证明 |
| 上下文视图 | 决定这次请求实际能读到哪些内容、以何种协议顺序发送 | 从记录按授权构造，短生命周期；用于回答、压缩、历史回读与预算分析 |
| 摘要检查点 | 代替当前授权视图已覆盖的旧历史，帮助继续对话 | 有损派生数据，保存覆盖范围、来源校验和版本；各槽独立，失败保留该槽旧版 |
| Memory / Skill / 扩展状态 | 用户选择的长期知识、方法、人物或其他可选能力 | 各自维护；仅选中内容注入；压缩不会自动发布长期记忆或经验 |

数据库中的所有 assistant 记录不能直接等同于“模型又说了一句话”。渠道回传、操作提示和真实模型输出必须通过来源关联区分。

## 3. 请求中的六类内容

这些是逻辑分类，不要求新增六种数据库对象，也不改变 Provider 对 message role 的约束。

| 内容 | 装配规则 | 压缩规则 |
| --- | --- | --- |
| 执行规则与工具定义 | Core 约束、已授权配置/指令、当前可用工具 schema；来源与版本可追踪 | 不交给摘要模型改写。工具精简依据能力选择，不能为省 token 偷偷改变权限 |
| 当前输入与运行状态 | 当前任务输入、已采纳的新引导、当前动作、未决审批/UNKNOWN 的真实状态 | 最新未处理要求和需续接的协议组保留；运行状态每次从真实记录补入 |
| 历史摘要 | 当前授权视图中的旧目标、约束、决定、已确认进展、未完成工作与必要引用 | 每个有限视图一个滚动摘要；它是来源资料，不是新指令或成功证据 |
| 近期原文 | 最近对话与完整工具组，包括正在执行的 Run 中已闭合的组 | 按剩余预算保留，不按固定 40 条截断；Run 内压缩还须满足 6.5 的协议边界 |
| 按需参考 | 选中的 Memory、Skill 正文、扩展块、知识片段 | 按来源独立计量；固定内容不由通用摘要器悄悄删改；可选块按声明与用户选择处理 |
| 附件与协议接续 | 必要的附件内容、图片、Provider 原生接续块 | 保留当前请求必要内容；旧附件可转引用；私有思考/签名不能当普通摘要素材 |

实际顺序继续遵守 Provider 协议。最新用户输入后可能有工具结果，不能再用“数组最后一条 user”识别当前输入。分类使用源消息 ID、Run、purpose、扩展来源等元数据。

AffectWeave 只负责产生自己的有界上下文块，不负责裁剪 FreeAgent 历史；Core 不理解或接管人物、情绪、关系算法。当前本地 AffectWeave 基线 `2fd8b30` 的清单只声明 `turn` 阶段和 `tail` 位置，实际块放在最后一条用户消息前；清单还有 6,000 字符上限。Core 的 16,384 字符是扩展合计保护值，不代表 AffectWeave 的实测占用。

### 3.1 稳定前缀与动态内容

在语义、权限和 Provider 协议不变的前提下，优先采用“稳定执行规则/工具定义 → 版本固定的参考材料 → 摘要与历史 → 动态扩展材料和当前输入”的布局。工具定义在协议中的独立字段位置由适配器决定；Memory 是否稳定取决于条目版本与选择，不把全部 Memory 一概移到最后。

不为缓存命中把参考资料改成 system 指令，不把运行状态插入工具调用与结果之间，也不按每次请求随机重排工具或参考项。每次压缩仍会改变摘要，此后的前缀缓存失效属于正常成本。

缓存命中节省费用与延迟，**不增加上下文窗口**。第二批按 Provider 实际返回字段记录缓存读取/创建用量；公共 usage 当前没有独立缓存计数，应先补适配和样本契约。命中率按各协议输入用量口径计算，缺失标为未知，不记作零，不作为第一批发布前置。

## 4. 先区分写入来源，再统一历史视图

### 4.1 新数据写明类型，旧数据集中兼容

第一批在现有写入路径中明确内容类型、稳定请求标识、Run/调用关联与来源。原创消息继续使用现有消息记录；传输回执使用已有投递记录/元数据，不再另外写一条会进入模型序列的 assistant 副本。不新建一套通用事件存储。

新回执保存确定的 Run、源消息标识或源片段范围、目标、投递状态与幂等标识；一条回执可能对应一个源消息的部分正文，也可能对应多个源片段，不能仅用一个不准确的来源 ID。先生成不等于已发送，部分发送不等于完整送达。

同时列出依赖旧“回执助手行”的读端：聊天历史展示、公开回复/文件导出、回复消息定位、分支、扩展事实同步与经验总结输入等。它们共用确定的来源关联和受众检查，不能只改模型上下文后让新投递在其它入口消失。UI 可继续展示通知和投递状态，不要求 UI 与模型使用相同的消息数量；公开导出不得用未送达的完整原文补齐缺失回执。

旧数据只经一个有版本的兼容函数归类。优先读取 `request_key`、`channel/delivery/<run_id>/...`、投递操作和已保存源关联；**禁止按“它前面最近的 Run”猜归属**。延迟发送、重复回执和主动消息都可能跨 Run 到达。信息不足时保留未确定来源及可见状态，不伪造执行归属或已送达结果。

### 4.2 所有写入来源必须有投影规则

下表是第一批类型覆盖基线。实施时扫描所有 `insertMessage`、`INSERT INTO fa.messages` 与投递写入调用点，建立“写入位置 → 类型 → 可见性/排序规则 → 回归用例”清单。新增类型未登记处理规则时测试失败；运行时遇到未知类型明确报告，不默认解释成普通助手回答。

| 来源 | 主上下文/公开视图 | 压缩与排序规则 |
| --- | --- | --- |
| 已采纳用户文本、附件、引用、贴纸/表情等媒体输入 | 按真实发送者、来源与附件权限提供 | 是对话源；引用资料不自动变成用户指令 |
| 待发输入、尚未采纳的引导 | 持久保存但不提前进入当前请求 | 不计入摘要覆盖，采纳时按 4.4 更新可见顺序 |
| 模型原始回复、工具调用与协议接续块 | 按授权提供，保留当前必需协议结构 | 原创内容；协议私有字段不作为摘要正文 |
| 工具结果、NOT_RUN、UNKNOWN 核查结果 | 与原调用关联，真实状态保持 | 完整组处理，不将未执行或未知写成成功 |
| 文本分段发送回执、重试及部分发送回执 | 完整视图去掉重复正文；公开视图只提供确认送达片段 | 回执不成为第二次原创回答，不插入工具组内部 |
| 附件投递回执 | 显示已确认送达的文件引用和状态 | 不把导出成功当作送达成功，不混入工具协议 |
| 命令回复、状态通知、系统提示 | UI 保留；有关运行/设置事实从受控状态装配 | 通知本身不作为普通 assistant 历史；用户命令和实际效果仍可追溯 |
| 主动生成内容 | 是原创内容，保存自身来源与 Run；公开视图以确认送达为准 | 未发送候选不得冒称已说过；在完整组后的安全边界装配，不重复注入其回执 |
| 经用户授权发布到空间的内容 | 按发布范围可见，保留原来源 | 是明确发布的资料，不借发布提升指令权限 |
| 从消息重新开始/分支复制 | 归属新会话，并保留分支来源 | 不复制源摘要，不为复制内容伪造执行 Run；组边界必须有效 |
| 历史回读结果（第二批） | 按相同授权视图返回有限片段 | 保留工具配对，正文按来源去重，新增结论照常进入摘要 |

主动内容的生成与发送是不同事实；候选生成后被取消、投递失败或 UNKNOWN 的情况必须单测。Core 只处理通用原创/投递类型，不以 AffectWeave 名称硬编码分支。

### 4.3 按需计算的统一视图

增加一个包内公共函数，输出有序消息组、来源、当前有效可见边界、可压缩前缀与受保护边界。主请求、摘要、分片、手动操作、模型候选预算探测和历史回读共用。视图不持久化为另一份消息库；摘要器不再另写一套原始历史筛选 SQL。

一个需续接的工具组包含原模型输出、所有调用、对应结果和协议必需字段。用确定的 Run/源关联与调用 ID 配对，不仅凭下一条 assistant 分组。允许异步回执在原始记录中穿插，但不能在模型协议序列中切开工具组。未知缺失结果不能靠重排或删除记录伪装为完整。

投影按身份、会话/空间、当前授权及来源决定，不以 GUI/TG 标签代替权限。完整视图以原创消息为准；受限公开视图可能只允许看到确认送达正文，不能用完整私有输出替代它。

**摘要和历史回读也必须使用同一受众过滤。** 当前 Run 因执行授权临时可见的工具片段，不自动成为该空间的公开历史；未公开结果不能写进公开摘要。若其可见范围不能与当前摘要槽匹配，则不得为了压缩扩张该槽权限；使用获准的有界结果/引用或明确报告当前执行内容过大。摘要不直接总结装配时加入的 Memory、Skill、动态扩展块；对话中已出现的相关内容仍按原来源权限判断。

### 4.4 采纳顺序、稳定身份与安全前缀

覆盖游标代表统一视图中稳定、完整的前缀。未闭合工具组不能被跨过并宣称已覆盖；永久非语义的传输事件可按规则排除。待发输入不能堵住所有后续压缩，也不能被摘要游标吞掉。

当前 `moveInputMessage` 已在同一事务内分配新的会话消息顺序、取消 Deferred、绑定 Run 并保存采纳记录。因此第一批复用该机制，明确“稳定请求标识用于身份，可见顺序用于覆盖”，不为本次修复强制新增 `projection_seq` 列。测试必须覆盖：先入队后压缩、晚采纳、并发采纳、重复请求、重启、已生成摘要之后采纳。

仅当需要不可变的物理消息 ID 且现有机制不能满足引用稳定性时，再单独迁移出 `adopted_seq`；迁移要覆盖索引、分支、回执和旧游标，不能只加一列。短锚点仅对已采纳的稳定记录暴露，见第 7 节。不具备安全采纳保证的旧记录作为明确边界处理，禁止仅凭 `id <= covered_through` 略过。

### 4.5 有限摘要槽位及受众隔离

按 `(conversation_id, projection_kind)` 复用现有 meta 保存检查点。投影种类固定为实际需要的 `full`、`public_text`、`channel_public`，最多三种，同一会话通常只使用其中两种；不是按身份无限缓存，也不能只按“高/低权限”分两类。

每槽有自己的覆盖范围、摘要版本、来源校验、投影版本和有效授权范围标识。服务端根据实际权限选择槽位，客户端不能通过传 `full` 越权。各槽独立比较版本并提交，低权限请求不能覆盖高权限槽。

`public_text` 与 `channel_public` 的可见内容不相同，即使都叫受限也不能互用；授权范围变化时只使受影响槽失效，不借保留的旧槽绕过撤权。模型选择变化不自动等于受众变化，重新验证预算和原生协议即可。手动 compact/refresh/clear 和 AI 确认卡片必须绑定具体授权视图及预期版本。

旧单槽摘要只有来源和可见范围可验证时才迁移到对应槽；否则标记需重建，保留原记录，不仅改版本号继续使用。源文未授权或已失效时，不以旧完整摘要作为受限摘要的生成输入。

### 4.6 分支、改写与失效

当前“从消息重新开始”创建新会话且不复制旧摘要，继续保留这一行为；原会话及其摘要不因分支创建而失效。

若使用历史版本加快失效判断，它应代表影响已覆盖源的改写、隐藏/删除或可见范围改变，普通追加、通知回执和安全采纳不触发整个旧前缀失效。第一批保留已有来源校验；未证明所有变更路径都受版本约束前，不用一个版本号替代完整性检查，也不新增逐消息哈希存储。

## 5. 将三类预算分开

### 5.1 模型上下文预算

已知模型窗口时，以 token 为主要容量尺度；输入、输出/思考预留按厂商对窗口的定义核算。总窗口型模型可使用：

```text
可用输入 = 总窗口 - 有效输出预留 - 安全余量
```

厂商若声明输入/输出独立限制，适配器按其规则处理，不强套一个公式。窗口来自已核实预设或用户声明，不能从型号名字或 `/models` 数量猜容量。

没有可靠窗口时，保留清楚标注的保守本地预算；显示“模型窗口未知”，不把估算包装成厂商精确额度。

### 5.2 请求大小与读取保护

请求字节上限用于 HTTP 载荷、图片编码、内存和读取保护，不能继续被称作模型的 token 窗口。最终编码前后的边界由 Provider 适配器检查，内部审计元数据不算作模型看到的正文。

必须保留字节保护，但默认值与历史迁移单独处理：旧的 128 KiB 可能是用户明确选择，不能静默放大。新建模型的默认保护值在图片/大工具结果测试后确定；旧值仍生效时显示“当前受旧字节上限约束”并提供经用户确认的调整入口。

输出预留扣减于 token 窗口；已知窗口场景不再把输出 token 换成字节扣 HTTP 载荷。未知窗口的保守折算必须单独标注。

### 5.3 摘要目标与输出额度

第三批提供“自动摘要目标”和兼容的高级自定义上限，前两批继续尊重已保存的摘要值。自动目标由有效输入容量、必须保留的原文和固定材料共同决定；有效输入预算的 10% 可作为待校准初值，另设经测试确定的内置上下限。不能为了固定比例把当前必要内容挤掉。

已知窗口时目标以 token 为单位，再单独检查存储字节保护；未知窗口使用清楚标注的保守预算。不能把旧字节预算的 10%（约 11 KB）直接加上思考 token 作为 `max_tokens`。用户明确保存的字节硬上限保持原单位和含义，不默认为自动值。

自动目标是软目标：摘要稍长但新请求明显缩小、低于硬限制时可接受，不因几个字节差异让任务停下。自定义硬上限仍严格遵守。摘要存储也保留独立的最大保护值，不能无限增长。

摘要正文目标、模型输出额度、思考消耗是三件事。摘要请求不得把正文字节数直接作为 `max_tokens`；使用获准的有效输出额度，考虑对应模型的思考行为。主回答的回复长度选择不应隐式成为摘要的长度目标。压缩用途可以有高级输出覆盖，默认继承既有授权额度，并受全局与模型上限约束；不能根据“目标长度加思考”自行突破这些上限。

思考用量并非所有模型都能预先精确分配；预算不足时使用明确错误和恢复动作，不保证算出一个相加值就一定完成。优先利用用户已选择的辅助关闭/低思考档位，不强制关闭不支持关闭的模型，不暗中提高已授权额度。

现有辅助思考也影响扩展分析，界面必须说明这一范围。若后续需要压缩专用覆盖，应作为现有模型辅助设置的可选覆盖，不能悄悄改动扩展的分析策略。本轮不要求另配一个摘要 Provider。

### 5.4 估算与显示

来源统计至少能区分规则、工具定义、摘要、历史/当前输入、工具结果、Memory、Skill、扩展、附件与协议开销。每项标明来源和是否可缩减，不给用户新增十几个配额旋钮。

复用现有 Provider 编码逻辑获得实际待发结构的估算视图，避免独立复制编码器。缺少可靠 tokenizer 时明确使用估算。扩展的字符限制保留兼容，展示实际 UTF-8 字节与估算 token；16,384 个常见汉字约 48 KiB 是上界示例，不是某扩展的实际占用。图片 Base64 当前已从消息 JSON 排除再单独计入，未发现重复计算；新编码计量仍要回归这一点。

### 5.5 用同一次请求的实际用量校准

校准绑定同一个 Attempt 的实际待发结构、Provider/模型/协议、有效视图与返回 usage。复用现有 Attempt 保存观测，不另存一份正文日志；附加清单只记来源范围/版本、占用、估算方法及请求关联。未派发请求没有实际 usage，不能拿邻近的响应当它的真值。

11 月 11 日的 55,010 token 估算属于后来准备的 **93,031 字节请求**；实际 39,281 输入 tokens 属于前一次已发送的 **88,010 字节请求**。二者不能直接证明高估 40%，也不能据此设置统一折算率。

- 同模型、端点、协议及稳定前缀未变且仅追加内容时，可用上次实测输入量加新增内容估算和安全余量；新增助手输出是否回传私有字段按实际编码判断。
- 压缩、折叠正文、换工具、Memory/扩展内容或视图变化、切模型/协议时重新估算。没有可比基准时回退保守策略，不凭减去字符数认定释放了精确 tokens。
- 按各 Provider 定义归一化输入及缓存字段，避免漏算缓存输入或重复相加；缺失用量不视为零。缓存命中率不用于放大窗口。
- 用中文、代码、JSON、工具循环、图片和混合输入的成对样本校准误差与安全余量，记录估算误差分布。校准不自动改写用户声明的模型窗口或成本上限。

DeepSeek [官方 token 说明](https://api-docs.deepseek.com/quick_start/token_usage/)给出中文字符约 0.6 token 的粗略换算，同时说明模型之间可能不同。该比例用于检查估算是否明显失衡，不作为所有模型/数据类型的精确 tokenizer。

## 6. 压缩流程改成一条有边界的流程

### 6.1 触发与目标不同

默认建议仍约 80% 触发，目标约 60%；两者是待长对话测试校准的初值。用户改变触发比例时，目标按比例调整并始终低于触发线，不另外增加一个必须配置的数字。

保留比例差是为了给后续工具结果和回复留空间。不能只检查“比原来少一点”：从 82% 降到 81% 会很快再次压缩。

若当前必要输入和工具组本身超过目标占比，就按实际最低占用处理。仍能容纳时允许继续，并记录无法进一步缩减的原因；不能强行丢掉必要内容去凑 60%。

预防性压缩可跳过有效收益过小的源；“不足预算 10%”仅是待测的收益判断候选，不能成为通用硬门槛。硬预算附近即使较小缩减也可能必要。相同源、投影、配置和输入版本不循环调用摘要模型，不能通过收到一个无关通知就重置这个判断。

### 6.2 单次过程

1. 在允许的模型调用边界采纳输入，读取统一视图和有效配置；先验证全部计划处理的消息组。
2. 装配并测量完整待发内容，区分历史太多与固定/当前输入本身太大。冻结本次准备的已采纳输入集合，缓存扩展和附件材料；同输入版本的压缩重建不重跑 hook。
3. 按剩余预算保留近期原文，保护当前任务输入、最新未处理要求、需续接的完整协议段和真实未决状态；不是固定保留 N 条，也不是必须等整个 Run 结束才压缩。
4. 选择足以降低占比的旧完整前缀。第二批启用有界引用后，主请求中可折叠的旧工具正文可先转成预览；没有模型可用的原文回读能力时不启用这种正文裁剪。摘要器仍从同一授权视图读取实际需要覆盖的源内容，不能把未读取的正文宣称为已完整总结。完整组不能被任意拆成可执行半组。
5. 摘要输入为“上一个有效摘要 + 本次新增覆盖源”。默认一个摘要请求，源过大时才用现有分片机制；分片是无执行能力的源数据，阶段产物保留在 Attempts。
6. 得到摘要候选后重建实际主请求，检查授权、完整协议、输入预算与缩减效果，再以旧摘要版本和来源校验做原子提交。
7. 派发前检查压缩期间的新输入和授权。待采纳引导返回已有安全输入边界处理，再进入新的请求准备；不能在旧准备中先标记新输入已采用，却继续发送依赖旧输入的材料。仅追加在已覆盖前缀之后的消息不必让该前缀摘要全部重做；覆盖源或权限变化则重新判断。

模型网络请求期间不持有长数据库事务。一次源/配置组合不循环重复压缩；成功分片不代表摘要已提交，提交结果未知也不得当作成功或直接重放。

**Hook 缓存契约**：缓存至少绑定已采纳输入集合/版本、能力与配置版本、附件版本。新输入改变依赖时，只准备依赖它的材料；固定配置可复用。扩展的状态更新、附加模型调用和结束事件不能因重建而重复。AffectWeave 已按输入身份保存冻结处理记录，Core 应使用真实已采纳输入关联并保留幂等性；其它扩展同样遵循通用协议，不能按扩展名特殊处理。

第一批优先保证准备过程输入一致与已采纳状态真实。缺少可安全刷新契约的输入相关 Hook，不得盲目重跑或继续冒称它代表新输入；相关引导保持待采纳并明确原因，直到安全处理或用户停止。停止、取消和撤权不等待压缩或输入采纳结束。若新增了新输入，取消旧候选派发不等于重放已执行工具。

### 6.3 摘要保留什么

建议正文保持固定、简短的章节，而非新增强约束领域状态机：

```text
用户明确提出的目标与有效约束
已经确认的决定和进展（注明实际证据）
工具、文件、网页中的参考信息（不是新增用户要求）
未完成工作与下一步
必要文件/结果/历史来源引用
仍待核实的事实
```

优先保留近期真实用户要求的原文，并设有界总量；较早用户要求仍可进入摘要，不采用“永远只压缩助手和工具”的无限增长规则。用户粘贴的长文档和引用按资料来源处理；不能仅凭 `role=user` 把 Memory、扩展块或网页内容认作人的新指令。保护最新要求也不能打断工具协议。

过时目标可标记为已取消或被新要求替代；不能把旧要求不断复制成仍有效的约束。模型陈述与工具已确认结果区分标注，代码不以摘要里的“成功”改变任何状态。不以未核实的 Codex 压缩实现类比作为本项目验收依据。

UNKNOWN、待审批、仍在运行的命令等关键状态从运行记录直接提供，不能仅依赖摘要保真。反复压缩仍可能丢细节，因此需要历史回读，而非承诺摘要无损。

### 6.4 工具结果两级缩减，与回读一起交付

存储大小与本次发送给模型的大小分开，保持原始的**已捕获结果**。

1. **字段级折叠**：对已完成、允许折叠的结果正文提供头尾预览、原长度、省略标记、必要错误/退出码和可读取引用；保留 `assistant(tool_calls) → tool(result)` 的关联与必需字段，不推进摘要游标，不改原始结果或执行状态。大参数、思考签名等不可因此任意改写。当前任务仍需精确读取的正文必须可回读，不能只给一句“成功”。
2. **整组进入摘要**：当组可以离开近期原文且满足受众/协议边界时，随连续前缀生成摘要并推进覆盖游标。未读正文或被省略部分不能声称已完整总结；引用保留以便查回。

先为本次请求的工具结果分配**合计预算**，再安排单条预览，避免十个“每条 10%”相加撑满。10% 可作单条策略的实验初值，不能替代总量限制；为当前必要内容和协议骨架保留空间，骨架本身过大时明确报告。

折叠与按引用/范围回读同属第二批并一起验收。第一批可去掉确定的重复回执、避免重新装配已由有效摘要覆盖的源，但不单独上线无法查回正文的预览裁剪。若决定前移，必须将最小回读接口及权限测试一并前移，不把它当作微小显示修改。

当前命令捕获本身有上限，超出捕获范围的字节不一定保存，不能承诺恢复。需要完整大输出时使用明确的文件/附件方式；复用现有记录、附件和分页，不建设无限日志存储。

### 6.5 Run 内压缩受 Provider 协议边界约束

保留长 Run 中安全压缩的能力；只折叠工具正文不能控制不断增长的输入、参数、规划和协议数据。Core 的 Run 结束与 Provider 的完整推理段结束不是同一边界。

适配器明确哪些保留消息和原生块必须原样回传、哪些完整旧段可被检查点替代。未完成调用及保留段所需的 reasoning/signature/items 不改写，不把私有思考送给摘要模型。对不能证明安全的段，报告受保护占用，不能删除字段后反复尝试。

DeepSeek [官方思考说明](https://api-docs.deepseek.com/guides/thinking_mode/)要求携带 tools 的后续请求完整回传相应 reasoning_content；不能只按“上一轮结束”判断可剥离字段。Anthropic 原生思考块及 Responses 接续项按发布支持的具体型号/协议建立样例与真实验收，不能把本次未能读取的厂商页面或中转结果当成原生证明。

先验证完整旧段替换后的请求合法；若某协议需要显式开启下一推理阶段，以同一任务的确认进展和权限接续，并记录阶段边界，不能伪造工具成功、重放操作或偷换成新任务。未经验证的协议路径不做破坏性改写，不一刀切取消全部 Run 内压缩。

### 6.6 分片成果与正式检查点

第一批和第二批继续采用最终原子替换：阶段结果留在既有 Attempts，整次失败保留正式旧摘要。每成功一块不立即推进用户可见的 covered_through，避免引入未定义的部分成功和恢复状态。

第三批若实测分片成本明显，可增加候选成果复用；恢复前核对来源范围、授权视图、输入/配置与旧摘要版本。候选过期则不用，仍不视为已生效摘要。可恢复分片不是前三批基础验收的前置，不新增摘要调度系统。

## 7. 给压缩增加一个必要补充：历史回读

保留原始历史却只允许用户翻 UI，仍不足以支持模型长期工作。第二批在现有上下文工具中增加只读历史读取动作，复用 PG、会话归属、权限投影与分页；先按引用和范围读取，关键词搜索另行安排，不做跨空间全文检索。

### 7.1 短锚点由 Core 生成并校验

优先使用已采纳消息的会话内稳定标识生成如 `#m42` 的短锚点；工具结果可引用其已记录消息，不为 `#t15` 另建一个全局编号服务。映射不得随一次投影重新编号，也不提前暴露还会移动位置的待发记录。

摘要模型只引用本次源集合中的有效锚点，保存前由 Core 校验。拼错或不存在的锚点明确拒绝/报告，不能改指向最近消息。锚点关联源版本和可见范围，原内容被改写或撤权后不能把不同内容冒充旧引用返回。分支保留来源映射，在新会话范围内解析。

锚点不是授权：解析后仍走同一受众投影。公开片段的引用不能读出其底层完整私有正文；返回出处、时间和真实结果状态，排除未授权内容、凭据、完整内部快照和 Provider 私有思考。最终面向用户的回答不要求输出内部 ID 或哈希。

### 7.2 防止重复回读与重复总结

Core 为回读结果附上原来源/版本/范围标记，可使用内部 `ephemeral_readback` 类型；模型不能靠输出同名字段自行声明豁免。回读结果仍是工具结果，保留完整协议配对和审计记录。

再次压缩时优先把重复的原文片段折回来源引用，不把同一旧正文当成新增事实反复总结；**回读后新产生的发现、纠错、用户决定和待办仍进入摘要**。不能因为读了旧材料就免去整段新对话的摘要。

回读同时受单次返回量、本次准备阶段的回读合计预算和请求工具结果总预算约束，大段分页。相同来源、版本与范围的无变化重复读取应复用记录并给出明确状态，配合无进展判断防止循环；不是每次工具调用都重新获得一个完整窗口。达到预算时提供未读范围和已有引用，允许经有效压缩或缩小范围继续，不能假称全文已读。

相关额度由既有工具/上下文策略推导，第一版不增加多个日常设置旋钮，也不引入普通 Run 整个生命周期的隐式总读取量、总步数或总时长上限。长任务取得实际进展后可继续按新的上下文预算回读。

这是一项有界读取能力，不新增向量库、Embedding、自动 RAG 或共享知识系统。Memory 与经验总结继续作为独立选择。

## 8. 一个恢复决策，保留不同原因

现有三个自动入口收敛到同一个规划/执行入口，并携带触发原因：预防性占用、硬预算、历史读取保护、摘要失效或 Provider 明确拒绝；手动维护也复用它。不得遗漏 `buildContext` 中的读取/失效恢复路径。入口可不同，选择源、预算判断与失败策略共用；受众、purpose 和工具权限仍分别校验。

| 情况 | 应对 |
| --- | --- |
| 预防性压缩失败，重建的主请求有效、未超硬限制，权限和执行状态均正常 | 保留原摘要和失败记录，继续主任务；同一无效源/配置不反复压缩 |
| 摘要为空或不符合自定义上限 | 最多一次内容修复；不能与 429 的通用重试额度混成同一次 |
| 已知无效配置造成输出/思考耗尽 | 暂停同配置预防性压缩；配置修正后恢复，不因下一轮又从头尝试 |
| 达到硬预算但已有压缩暂停记录 | 仍进入恢复决策，不能仅凭暂停直接跳过全部判断；仅新源能改变失败条件、配置已修正或适用其它有界恢复时尝试，已知无效配置不因达到硬预算而原参重发 |
| 主请求本身协议分组错误 | 报上下文结构错误；利用确定的投递关联修正视图；不能假装压缩可以修复未知缺失结果 |
| 固定指令、当前用户输入或必要附件已占满 | 指出来源，提供缩减或改窗口入口；压缩旧历史无济于事时不再烧模型调用 |
| Provider 明确拒绝上下文且未产生内容 | 校准本次可用预算/压缩候选，走既有有界恢复；不重放已执行工具 |
| 数据损坏、权限变化、未决工具或提交 UNKNOWN | 按实际原因停止/核查，不用“超限”覆盖 |

暂停状态绑定会话内具体视图和失败原因；失效判断包含模型/端点/协议、有效输入及输出预算、辅助思考、摘要策略和投影版本。新增可压缩源是否有用取决于失败原因：没有可压缩前缀与固定配置导致空摘要不能用同一规则处理。区分配置失败、临时网络失败与无有效收益，提示只在状态变化时重复；用户显式修复与手动操作的结果可检查。

### 8.1 固定原因码与可执行提示

在既有 Run/Attempt 状态信息中保存稳定原因码与必要结构化诊断，保留人可读说明兼容。新 TG/Web/CLI 根据原因码呈现，不能继续用字符串同时包含 context/budget 就认定硬预算。旧记录的字符串兼容仅在统一映射处处理，未知错误不能伪装为超限。

下面是必须区分的语义；实施时统一固定枚举名称、Go/TS/CLI 契约与旧数据映射：

| 原因语义 | 用户应获得的信息/动作 |
| --- | --- |
| 上下文结构错误 | 指出来源/工具组异常，可查看记录；不能建议反复调思考额度 |
| 模型输入窗口满 | 有效窗口、占用来源，提供手动压缩/模型设置/新对话入口 |
| 本地载荷或历史读取保护 | 明确是字节/读取边界，不冒充厂商 token 上限 |
| 固定材料或当前输入过大 | 指明具体来源及缩减方式，压缩旧历史无效时不重复尝试 |
| 摘要为空、不完整或超自定义上限 | 摘要阶段、有效辅助配置、内容修复结果和可执行调整入口 |
| 主模型输出上限 | 明确主回答未完成，与历史满区分 |
| 压缩无有效收益/暂停 | 是否继续、暂停原因与恢复条件，避免只显示 failed |

模型能否继续以真实请求及运行状态校验为准。TG 提供不依赖模型的 `/context`、`/compact` 和已启用多对话时的 `/new` 指引；手动压缩仍检查未决操作和权限，不保证每种错误都能由 `/compact` 解决。

### 8.2 不默认丢弃旧轮次

本轮不增加“到了硬预算就自动省掉最早几轮”的默认兜底。即使原记录还在，模型失去早期约束也可能改变文件或命令行为。首选有效摘要、有界回读、调整配置或明确新对话。

将来若提供“仅保留近期内容继续”，应是用户明确选择、显示省略范围的独立操作，受当前任务/UNKNOWN/审批约束；不能为了恢复聊天绕过既有确认或宣称完整上下文仍在。该可选操作不阻塞三批基础交付。

## 9. 用户操作应该收敛

日常界面保留“自动压缩开关、当前占用、手动压缩、最近结果”。上下文设置提供触发比例及第三批的摘要目标自动/手动；模型窗口自动来源/手动覆盖、主输出额度和辅助思考放模型设置，字节保护、工具结果合计策略及自定义摘要硬上限放高级项。自动开关与摘要大小解耦，避免新配置继续用 `summary_bytes=0` 承载两种含义；旧格式保持兼容读取。

操作统一到同一 Core：

| 操作 | 约定 |
| --- | --- |
| 手动压缩 | 调用同一规划器和当前授权摘要槽；明确“无需压缩”“已压缩”“阻塞原因”，自动目标上线后无需先填字节数 |
| 保存默认 | 明确影响后续请求，显示 Core 默认、当前 Run 冻结值与本次维护值；提供已有安全接续动作，不静默修改活跃快照 |
| AI 修改 | 继续走现有持久化提案确认，不绕过用户确认 |
| 模型已经无法运行时 | GUI/CLI 的直接控制及 TG 确定性命令仍可查看原因、调整授权范围内的设置或请求压缩，不依赖先发一次超限模型请求 |
| TG `/context`（拟新增） | 返回有效预算、上次测量、阻塞来源和可执行动作；不把全部调参过程塞给模型 |
| TG `/new` | 已开启多对话时，无标题使用默认名称，创建及设为当前会话在同一事务完成；按入站请求幂等，不重建重复会话。未开启多对话时保留显式开启要求；不取消、迁移旧 Run 或改默认会话 |
| 清除摘要 | 仅处理当前获准槽并绑定版本，明确会恢复更多原历史、可能增加占用；不作为“释放上下文”的默认建议 |

手动 `/compact` 或按钮是用户直接发起的操作；模型自行提出持久修改仍需确认。维护与恢复的操作必须遵守已有权限/未决工具边界。

界面显示的是“哪一个 Run、哪一次准备请求、哪套有效配置”的测量。新消息未计入时明确标记；压缩前后给出占比、调用次数和结果，不要求用户读 Attempt 才知道是否恢复。

### 9.1 旧配置迁移不靠数值猜意图

- 有来源记录的设置按来源迁移；没有来源的旧值保留实际行为并标记为旧配置，不因它恰好等于旧默认值就转为自动。
- 11 月 11 日采样的 10,240 字节保留为手动值；原 `task_summary_bytes=0` 继续表示自动压缩关闭，不能迁移后悄悄打开。
- 旧 128 KiB 字节保护继续生效，提供明确的一键改回自动/调整入口及影响说明。用户保存后记录 auto/manual 和来源，切换自动也受硬保护约束。
- 模型提出的持久调整仍走现有确认；人直接使用设置或明确命令沿用现有控制入口。各入口共享校验、生效范围、版本冲突处理和返回状态。
- 自动目标、token 校准和界面简化按批次上线，不把尚未支持的自动行为显示成已经生效。

## 10. 分三批落地，每批独立验收

### 第一批：修正确性，恢复已有会话

| 工作 | 产物与主要位置 |
| --- | --- |
| 新记录分类与读写清单 | `store.go`、`channel_messages.go`、投递/附件、主动生成、队列、分支及依赖回执的读端；新回执不污染模型序列，展示/导出继续正确 |
| 旧数据兼容与统一投影 | 包内公共函数及单一旧数据转换；确定关联、完整组、受众过滤、采纳顺序共用 |
| 有限摘要槽及来源校验 | `context_summary.go`、`context_compaction.go`；槽选择、旧摘要迁移、手动操作及确认绑定 |
| 统一恢复、Hook 输入一致性 | `context_prepare.go`、`context_reliability.go`、`service.go` 和输入/扩展准备路径；保持权限与 UNKNOWN 规则 |
| 原因码与直接操作 | Core/GUI/CLI/TG 契约、`/context`、准确的 `/compact` 提示；`/new` 默认标题、事务与幂等 |

退出条件：重放原故障的合成消息排列后，主请求、自动/手动压缩和下一轮均正常；原上下文能容纳时不会因预防性压缩错误而被误停；新回执写入后不再产生同类污染。已有 TG 会话的隔离重放可直接接续，不要求先 `/new` 或删除记录；真实上线后的接续按既有部署授权与验收流程确认。

本批保留已保存预算值，不加入无回读正文裁剪。它解决已确认的正确性故障，不能提前宣称消除了所有真实容量不足。无需等待 token 校准、自动摘要目标、完整历史回读或所有 Provider 新能力。

### 第二批：减少超限，降低反复压缩成本

| 工作 | 产物与主要位置 |
| --- | --- |
| token/字节分离与成对校准 | `context_budget.go`、模型配置与 Provider 编码；同 Attempt 比较、输入来源清单、图片/缓存用量 |
| 工具正文两级处理和最小回读 | 投影、既有上下文工具；预览与原文引用同时可用，按引用/范围分页及权限验证 |
| 防循环与近期原文保留 | 原生组保护、回读去重、合计预算、压缩触发/目标占比与无收益判断 |
| 来源可视化、稳定前缀和直接恢复 | 上下文页/模型页、CLI/TG 一致状态；缓存指标仅在 Provider 可提供时显示 |

退出条件：规定输入规模与分布的模拟长会话中，工具大结果、中文、图片、回读和动态扩展均能按预算处理；相同源/配置不循环压缩；允许缩减的样本达到目标占比，受保护内容不能达到时给出明确原因。记录真实输入体积下的压缩次数/成本/延迟，不承诺任意长任务都有固定次数上限。需要原生协议证明的路径完成对应 Provider 验收后才扩大支持范围。

### 第三批：摘要质量与自动目标

| 工作 | 产物 |
| --- | --- |
| 摘要目标自动/手动及迁移 | token 软目标、存储/输出硬边界、来源标识和一键切回自动，保留旧设置意图 |
| 近期用户原话与固定摘要栏目 | 真实用户要求、参考信息、确认结果、待办和引用可区分；较早用户内容允许有界摘要 |
| 连续压缩质量基准 | 注入合成事实、变更/撤回要求、文件引用与未完成事项，检查保留和回读效果 |
| 可选成果复用 | 仅实测分片成本需要时加入候选进度恢复；正式检查点仍原子生效 |

退出条件：确定性的用户要求丢失、受众泄漏、错误成功判断、重复副作用和无效引用必须修复；真实模型的统计质量/成本波动单列报告，不以一次随机得分作为发布门槛。真实 DeepSeek 不可用时记录 NOT_RUN，不能声称已做真实质量验收，也不能据此跳过协议兼容必测项。

“Run 结束后空闲预压缩”本轮推迟，不引入后台调度、任务争抢和额外默认调用。三个批次继续复用 PG、Run/Attempt、控制面及扩展接口；不做多层摘要树、独立摘要服务、自动长期记忆写入、新向量库、默认多模型摘要路由或 Core 人物状态。

| C20 / 1 | 新旧回执混用时的聊天展示、回复定位、公开文件导出、分支和扩展事实同步 | 不丢失实际已送达内容、不重复显示原创回答，不导出未公开正文；通知保持可查 |

随机化测试仅打乱允许异步到达的回执、并行结果等独立事件，保持真实因果和来源标识；另设非法顺序/缺失结果用例验证准确拒绝。不能把任意打乱用户指令顺序后仍运行作为正确性目标。

C17 第一批至少完成已支持协议的序列化/模拟边界回归；实际改动了某个原生请求规则时，验证对应原生路径。第二批新增或扩大原生改写范围前完成相应真实验收。未触及的新 Provider 功能不作为第一批前置；未通过的路径不能宣称支持。

### 11.2 效率与质量报告

固定合成数据集记录：输入体积/类型、压缩次数和模型调用次数、实际 token 成本、压缩与接续延迟、压缩前后占比、回读量、来源保留率和可用时的缓存命中率。记录受保护内容最低占用；不能达到目标的样本不以强行截断换取通过。

真实 DeepSeek 使用合成或脱敏用例，保持已授权端点/额度；不要把生产私聊正文拷进公开报告。协议安全、受众隔离、数据完整性和用户约束等确定性缺陷阻塞发布；统计性质量指标形成报告，缺条件明确 NOT_RUN。

### 11.3 环境与交付

先用本地模拟模型与独立 PG 跑定向回归，再跑受影响的 Go/前端/CLI 契约及双平台检查。发布代码时沿用 Windows/Linux 包验证与 Hytron 7C13 Debian 12 独立 unit、端口、数据目录。

每批发布前核对活跃任务、数据备份和回退条件；如新增持久字段，写明旧包能否读取，不能把“可回退二进制”当作数据库可无损降级。常驻 TG、公网配置和凭据按本机协作约定保留；部署结果同步私有记录，公开文档只保留无秘密的结论。

80%/60%、摘要约 10% 和单工具预览约 10% 均为需要测试校准的候选策略，不是已验收保证。第一批退出条件针对确认过的故障，实际通过前不得标记修复完成。
