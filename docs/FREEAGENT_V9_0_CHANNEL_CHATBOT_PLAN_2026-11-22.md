# FreeAgent v9.0 实施计划：接上渠道，就是聊天 Bot

2026-11-22 审计修订。原基线：`v8.9.0-dev.4`。目标正式版：`v9.0.0`。**状态：W1–W3 已分别发布 dev.1–dev.3 并部署 Hytron；W4 验证中，W5 开发中。** [W1](VALIDATION_V9_W1_2026-11-22.md)、[W2](VALIDATION_V9_W2_2026-11-22.md)、[W3](VALIDATION_V9_W3_2026-11-22.md)、[W4](VALIDATION_V9_W4_2026-11-22.md) 与正式版的群聊真人验收分开记录。

## 1. 正式版交付什么

一份已配好模型的 Core，接上 TG、批准目标聊天后，不装 AffectWeave、MCP 或 Skill 就能在私聊、普通群、超级群及其话题对话。Telegram 与 Web 使用同一 TaskService、同一模型/工具执行循环、权限、上下文与恢复；不接渠道时 Web/CLI 照常使用。群里既能聊天，也能调用已有授权的工具和已选扩展、办理审批，并确认少量本会话设置。

**完整 Bot 不等于群成员拥有宿主管理权。** 验收用例：甲在「资料」话题读一份可向全群公开的文件，请 Bot 搜一个公开来源，再按原审批流程写入测试文件；乙能看到群答复，但不能借甲的权限派发写入。甲提议使用本空间已授权的人物，名单内乙可确认；原 Run 和其他话题设置不变。工具审批与设置确认是两件事。

| 本版不做 | 保留的边界 |
| --- | --- |
| 群内切换模型/思考档位、按空间维护模型名单 | 群使用已配置的模型；需要更改可由管理端办理。私聊仍可确认切到已配置可用模型。 |
| 智能参与、逐条模型判断、为此增加 Core hook | v9.0 只有显式唤起和管理员主动开启的「全部回复」。智能参与放入 v9.1 与 AffectWeave 评估。 |
| Computer Use 结果跨会话交回原群；在群内做经验总结 | 仅本机工具仍仅本机；不把成员发言提炼写入 Memory，不新增“群 Memory”。浏览器、协作和现有 Memory 做回归。 |
| 飞书/QQ 新增原生确认、全面功能对齐 | 本版按 v4 声明各自**现有**能力并跑契约测试；原有合法路由不退化。全面对齐放入 v9.1，不用平台不支持的按钮冒充确认。 |

## 2. 发布节奏：先让 Hytron 的群可诊断、可使用

正式版必须完成全部工作包，**开发版不等正式版**。每包验收后打对应 `v9.0.0-dev.N`、推送 GitHub、发带程序包的预发行 Release、更新 Hytron 并记下实测结果。不把仅推源码算作已交付；部署前的空闲、备份及授权条件见第 8 节。W1 同时准备有授权的测试 Bot、两名不同真人账号、普通测试群和启用话题的超级群，不到 RC 时才找人。

| 工作包 / 开发版 | 当次就能用的东西 | 该包的交付证据 |
| --- | --- | --- |
| W1 / dev.1 | TG 收发分层诊断、修复可复现的群不回复、默认不留未唤起文本。先解决当前群，没有必要因架构拆分等待。 | 区分平台未观察到、适配器过滤、未准入、未唤起、忙/队满、已建 Run、已派发和有/无回执。用已授权的当次唤起验证实际链路；历史不足不倒推原因。若群仍有阻断，单列具体阶段、证据和下一步，不报“已修复”。 |
| W2 / dev.2 | **A：TG 私聊设置确认先上线**；每 Bot 名单、可信原卡、宿主提交及状态回读。群暂只给安全管理提示、不留阻塞提案。 | 名单内/外、撤权、过期、双击、修订冲突；批准最多写一次、收尾额外模型调用为零。 |
| W3 / dev.3 | 普通群/超级群话题路由、General、群迁移、成员状态、多人排队、群背景可选留存和清理。 | 两个群和两个话题不串线；队列满有记录，移出群后不再派发；迁移及背景删除可重启复核。 |
| W4 / dev.4 | **B：群内设置确认**、群空间的新会话能力默认、已授权工具与已选扩展在原话题实际执行。 | 甲提议、乙确认、丙在等待时正常聊天；群里不能切模型；读文件、写入审批、搜索、扩展均有执行证据。 |
| W5 / dev.5 | 网页读取失败不中止独立任务、分段投递限流、已有上下文恢复回归、渠道代码归属收尾、飞书/QQ v4 契约检查。 | 多来源读取、明确 429、真实未决、重启均按第 7 节分类；通过包依赖和最小测试连接器检查，无须修改 Core 循环。 |

**止血特例：** 若当前群故障能在稳定线独立修复，先发 `v8.9.x` 配套补丁并更新 Hytron，再把改动带回 W1。稳定线按自身协议成对发包，不给 v9 添加兼容分支。首次 v9 开发包起 Core 与渠道统一为 **channelwire v4**；不匹配即拒绝连接并提示实际/要求版本及“请同时更新两个程序”。现有 HTTP 路由中的 `v1` 不是 wire 版本。

## 4. Telegram 平台与诊断

2026-11-22 直接核对 Telegram 官方 Bot API（页面最近列出 2026-11-09 的 10.4）、Forum 说明及 FAQ。下表左侧是协议事实，右侧是 FreeAgent 的实现约定，不能据此替代某个生产群的真实回执。

| 官方依据 | 连接器与验收约定 |
| --- | --- |
| [Message](https://core.telegram.org/bots/api#message) 的 `message_thread_id` 可指消息线程或论坛话题；`is_topic_message` 才表示发往话题；[Forum topics](https://core.telegram.org/api/forum) 单列 General 的发送方式。 | 用群类型、`is_forum`、`is_topic_message` 和已核实目标联合判断。普通超级群的回复链不能仅凭 thread ID 建话题；非 General 的已确认话题在全部链路保留正确 ID。向 General 发送省略 `message_thread_id`，回复引用另行绑定。无法判定、话题已关或已删，不回退到主厅/私聊。分别测普通回复链、General、两个具名话题。 |
| [迁移字段](https://core.telegram.org/bots/api#message)有 `migrate_to_chat_id` 和 `migrate_from_chat_id`；[官方论坛说明](https://core.telegram.org/api/forum)区分基本群先升级和已有超级群直接开启论坛。 | 不假定每次开启话题都会换 ID。仅按经验证 Bot 收到的迁移事实处理旧/新 chat ID，按 64 位整数或无损字符串保存。迁移可重复、可乱序；保持同一空间、会话、成员授权及群设置，管理页显示迁移关系。未派发项复核新目标、权限和引用后才能迁；已派发/UNKNOWN 仍按原操作收回执，旧卡作废。冲突或引用不可证则暂停，不向两处重发。 |
| [Update](https://core.telegram.org/bots/api#update) 和 [ChatMemberUpdated](https://core.telegram.org/bots/api#chatmemberupdated) 提供 `my_chat_member` 的前后状态；[当前轮询](../internal/channels/telegram.go) 的 `allowed_updates` 没有订阅它。 | 显式订阅并处理。被踢/离群立即不可用并停发；降权先暂停派发，按当前身份、发言权与相关动作权限重核。仍可发言的普通成员可恢复允许的动作，不把失去管理员身份等同永久禁言；权限不明不派发。保留历史、原操作和待处理状态，不自动复活旧卡/未知发送。 |
| [getMe 的 User 字段](https://core.telegram.org/bots/api#user)、[Privacy Mode](https://core.telegram.org/bots/features#privacy-mode) 与 [收消息 FAQ](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get) 区分 Bot 全局隐私模式和特定群管理员的可见性。 | 诊断分两行：最近一次成功 getMe 的 `can_read_all_group_messages`（读取失败显示未知），以及 Bot 在本群的身份和权限。即使全局隐私模式开启，成为该群管理员也会扩大可见范围；这不授予 FreeAgent 工具权限，也不会打开背景保存。 |
| [ResponseParameters](https://core.telegram.org/bots/api#responseparameters) 的 `retry_after` 以秒计；[发送限制 FAQ](https://core.telegram.org/bots/faq#my-bot-is-hitting-limits-how-do-i-avoid-this) 区分同聊天/群等限制。 | 限流按实际 Bot/chat 协调，多个话题和 AffectWeave 的分段不能各自抢额度。对**明确未接受的 429**，outbox 记录最早再派发时刻，不早于 retry_after；保序、重启后仍等足、到期前重核权限；若超出授权期限则停止而非提前重试。无回执的发送不是 429。 |

W1 的诊断页按时间窗显示：平台更新 → 过滤/身份 → 准入 → 唤起/队列 → Run → 投递回执。将 `/start` 的「申请已存在」「申请已满」「个人身份不能核实」「Bot 未绑定」分开，群里不列私有名单。区分 Bot 级与群级证据；未观察到更新就如实显示，不归咎于隐私模式或模型。已知的历史事实仅是当时目标群准入一人、三条留存群事件都是命令，未见普通群 Run。先用现有记录，再在获准测试目标做一次定向唤起；不要求用户反复重发，不记录被过滤文本、token 或完整身份清单。

## 5. 群消息、背景和能力默认

**群空间能读取的资源，按可向整个群公开处理。个人权限只决定谁能触发操作，不决定谁能看到群答复。** 管理员不得把私有文件、私聊历史、个人浏览器资料或私有人物资料授权给群空间。此规则在取数、扩展 hook、模型输入和历史回读**之前**执行；输入给了模型就可能被它复述，不能许诺靠输出过滤保密。话题用于路由和上下文隔离，不是群内成员之间的保密隔间。工具审批仍绑定原请求人；不会因为返回值可公开就允许任何人运行工具。

| 输入 | 默认行为与保留规则 |
| --- | --- |
| 明确 @、回复 Bot、适用命令 | 通过准入后在原会话/话题办理，作为正常对话记录。合法唤起的默认策略不变；同一 update 不重复启动 Run。 |
| 未唤起普通文本 | **按群独立开关，默认关闭。** 关闭时仅计无正文的原因/数量；在写入[完整入站意图](../internal/harness/channel_inbound_receipt.go)、消息、媒体下载、日志、摘要或扩展前丢弃。忽略不等于失败，无须回群通知。 |
| 管理员开启「保存群背景」 | 只取已准入来源、开关生效后收到的本群/话题文本，按收到时间滚动保留 **24 小时**；不保存背景附件、不进长期摘要、Memory 或经验总结。仅在有效期内作有界参考。管理页注明期限与受众；只有认证的 Web／本机管理员可按群清空。关闭立即停止且使已存背景不可再读，手动清空/到期从活动存储清理；既有备份按原轮换到期。已正式发出的回复不能承诺被一并抹除。 |
| 管理员显式开启「全部回复」 | 仅平台实际下发且获准的成员消息成为正常请求，启用前说明这些消息将作为对话记录；不顺带开启背景保存。一个话题会话同时一个 Run，复用有界队列与已有 Owner 预算，**不加专用预算**。队满即拒绝新请求，计「队列已满，已丢弃」，不隐式重放或改存为背景。Bot 自己、其他 Bot/不可验证身份不自动触发对话。 |

老版本已存的背景不能被升级静默公开或冒充新用户同意。迁移前统计并备份；新投影默认排除旧背景，旧摘要凡可能含有该背景就失效重建；历史清理提供管理员按群预览/清空，不静默删原 Run、用户请求或回执。失效和删除应覆盖引用、缓存及含正文的暂存记录；测试直接查活动库和实际模型输入，而非只看页面。

**空间能力默认只用于初始化新会话，不是授权层。** 新会话创建时从已配置的空间默认复制选项，一次写入会话选择；未设则用安全空选择，纯 Core 照常聊天。以后改空间默认不回填已有会话，既有显式空选择保持为空；创建时与每次执行都以现有空间/人员权限、能力启用状态、资源授权及本轮选择为准。没有新的“空间允许能力/模型”名单。群内状态只说明本人可用能力和安全的下一步；管理端区分未安装、未启用、未选中和无权访问。

## 6. 连接器状态、确认和 Core 边界

- **谁负责什么。** 平台收发、准入申请/身份、唤起与命令、群设置、确认名单、贴纸与原生格式属于连接器及其宿主侧集成。Core 只受理可信桥接的来源/目标与单次决定，负责空间/请求人授权、会话、TaskService、能力快照、Attempt、上下文及恢复；Owner 维持唯一入站去重和 outbox。平台策略退出执行循环，不另起 Agent、调度器、平台用户中心或独立投递库。未配置渠道不启动连接。
- **存什么、怎么存。** 以 `connector/telegram/<verified-bot>/…` 为逻辑命名空间（不是新数据库）：每 Bot 一份名单，群设置/准入按 chat，申请按原申请作用域、期限与当前 Owner 代次。复用扩展状态的四种操作语义：`state.read(scope)`、`state.preview(change, expected_revision)`、`state.apply(operation_id, digest, change)`、`state.result(operation_id, digest)`。宿主注入受限作用域；写入冲突不覆盖；重复操作返回原结果。申请仍遵守原上限/过期/重启失效，不因采用存储契约复活。业务事实由所属模块解释；现有可同事务更新的 `fa.meta` 经窄适配使用，旧授权键仅作显式迁移来源。**不照搬扩展独立 PG 凭据、不给渠道直连 Core 库、不再建通用 KV RPC**。入站消息可申请但不能批准准入/编辑名单；名单默认空，仅认证 Web／本机可写。迁移校验同一群、修订和唯一写入者，不留两份有效授权。
- **私聊 A、群聊 B。** A 允许名单内的已准入原发起人确认当前会话模型，或已启用且已在会话选中的扩展的一个已有选项；B 只允许同群名单内的已准入成员确认**当前会话/话题里已选中扩展的既有选项**，例如当前空间已授权的人物。申请人与确认人可不同；不借此启用扩展、创建人物、切群模型或调全局压缩。普通工具审批仍按原权限，仅原请求人可批。
- **一次决定。** 按钮绑定已验证 Bot、chat/topic、原卡、原提案、真实请求人/点击人、完整目标、修订与期限；点击/派发均复核授权。名单撤销再加入不复活旧卡，未授权点击只用 `answerCallbackQuery` 向本人反馈。群内单项设置等待通过已保存提案交接，不占用整条话题；发起人可撤回自己的待决。批准最多写一次，仅下一轮生效，收尾额外模型调用 **0**。完整声明目标已被另一笔写入满足则不再写；不同须重新预览。拒绝、撤回、过期、设置写入与回执送达分别记账。不能安全公开的管理动作转认证入口，不阻止普通聊天。

## 7. 网页未读到，不等于操作结果未知

现状：[web_fetch](../internal/harness/web_search.go) 为 `EffectModify`，[读取器](../internal/webaccess/fetch.go) 在写出请求头后断连会标不确定。v9 把**公共网页读取的业务结果**改为「未取得正文/读取失败」：原 tool call 有结束结果，来源标未读，不生成副作用 UNKNOWN、不占住会话。Harness 不因这类读取失败自动重试；模型可以继续其他来源，也可在原权限、确认规则和调用预算内**另发一次可审计的新读取**。不要把“没拿到正文”写成“服务器未收到请求”。

这是内置公共读取工具的特定规则，不把任意 HTTP、MCP、命令或外发动作视为只读。保留公共目标、重定向、无凭据、目标/预算等既有约束；读失败与工具授权分别判断，不靠修改通用 Effect 放开权限。不批量清理已有 UNKNOWN。真正的写入/发送可能已生效、数据库提交无法核实、仍在运行的进程仍按[既有未决原则](UNRESOLVED_OPERATIONS.md)保留证据，能隔离则继续无依赖工作，不能隔离才停止。群上下文沿用原窗口/字节/摘要预算：预防性压缩失败但放得下仍发，硬限给出实际原因；受众和话题不因压缩变化。

## 8. 验收、上线与回退

真人 TG 的**能力硬门槛只有四项**：一份可公开文件读取、一次由原请求人批准的写入、一次实际搜索、一个已选扩展（使用合成人物/选项）。另验证产品主线：无扩展的私聊和普通群、两个超级群话题的隔离、两名不同成员的原生设置确认、回复落到原处。模型文案不是通过证据；核对工具/扩展记录、提交修订和 TG 平台回执。浏览器、协作、已有 Memory、Skill/MCP 和桌面来源限制做隔离回归，不对每项要求真人 TG 验收。

| 检查 | 通过条件 |
| --- | --- |
| 入站与路由 | 默认背景关闭时注入标记不出现在入站原文、数据库、模型或日志；启用后的背景跨话题不可读、24h 到期及管理端清空可验证。重复唤起最多一个 Run；满队列丢弃有计数，不借前一人的权限。正常群回复链、General 省略 thread ID、命名话题、群升级双向事件、被踢/降权分别测试。 |
| 空间默认与公开资源 | 修改默认前后的两个新会话取各自创建时值；已有会话/显式空值不变，撤权仍即时。甲读群公开夹具、乙无权触发同一工具但能看公开答复；私人资料标记不进入群模型输入、回读、摘要、卡片和回复。 |
| 设置决策 | 合法私聊与群提案各一正例；名单外、跨群/话题、名单撤销、重复点击、Web 同时决定均无越权/重复写。群内切模型不出卡；等待期间另一成员仍能聊天。批准后新增模型请求数为零。 |
| 多源读取与真实副作用 | 固定三来源 A/B/C，A 断连时标为未读、无待决项；B/C 照常完成。模拟模型分别选择不再读和主动重读，验证 Harness 自发重试为零，不规定模型新调用后 HTTP 总次数仍为一。另对写操作/投递丢回执验证原 UNKNOWN 不重放。 |
| 分段/预算/重启 | 中段收到明确 429 按 `retry_after` 延后，其他话题不能抢同群额度。[适配器](../internal/channels/telegram.go)当前把等待截到 3,600 秒，故专测 3,601 秒：保留真实等待或停止，不得提前派发。发送回执丢失不走限流重试。不因失败摘要循环阻塞可发送请求。重启不重复执行工具、决定或确认送达的消息。 |
| v4、迁移与现有入口 | 同包 v4 成功，v3↔v4 两个方向均明确拒绝；飞书/QQ 只声明原有能力，最小测试连接器不用改 Core 循环；无渠道时 Web/CLI 正常。旧私聊、群授权、未决、暂停队列和显式关闭能力在升级/还原演练中保留。 |

每个 dev 包先跑本工作包相关测试，在 Windows/Linux 独立 PG、独立 unit/端口/数据目录验包，再推 GitHub、发布对应预发行及校验值并按既定流程更新 Hytron。维护常驻实例前核对任务、配置和可恢复备份；升级后核对版本、TG 重连、公网 Web、数据与 outbox。真人发信/点击只在被授权的目标和动作范围内测试，绝不用同一 token 并行轮询。模拟、真实私聊、真实群/话题、常驻部署结果分别记录；必要账号未就绪记 `NOT_RUN`，不妨碍先交付可测 dev，但不当正式版通过。

任一串群、权限提升、错误重放或无法恢复数据即停止放行；保留升级后事实，使用匹配的程序和备份在独立目录验证回退，不覆盖期间产生的新记录。正式 `v9.0.0` 只在目标工作包及必需真人验收通过后发布；私有运维记录不含于公开仓库或发行包。
