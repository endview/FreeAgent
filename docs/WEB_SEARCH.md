# 联网搜索与公共网页读取

本指南对应 v8.9 搜索能力；公网管理请使用 `v8.9.0-dev.3` 或之后版本，旧版漏放行设置接口的问题见[修复记录](VALIDATION_SEARCH_PUBLIC_UI_2026-11-17.md)。实测服务范围见[实施记录](WEB_CAPABILITIES_IMPLEMENTATION_2026-11-17.md)。

## 设置

1. 打开“设置 → 能力管理 → 内置工具”，开启网络工具。只使用搜索时，普通 HTTP 的站点列表可以留空。
2. 打开“连接与数据 → 联网搜索”，选择服务商和 Key。搜索 Key 使用独立的 `search` 协议，服务地址是该 API 的基础地址；DeepSeek 也可引用它已有的模型 Key。
3. 填写连接名称，点击“添加到草稿”，选择默认连接和搜索方式，最后点击“保存搜索设置”。添加到草稿与保存是两个状态，切页保留草稿。
4. 已保存的连接可用“测试连接”执行一次固定的非敏感查询，可能计费，不自动重试。测试不替用户开启搜索，也不读取模型列表。

新增搜索 Key 可在该页完成。后续替换秘密可在“工作台设置 → 模型与 Key”管理；搜索 Key 不显示模型列表，也不作为模型凭据。删除 Key 或改变其地址/协议前，先从搜索连接中解除引用并保存；只轮换秘密无需解除引用。

搜索方式：

| 方式 | 当前行为 |
| --- | --- |
| 关闭 | 不提供搜索/公共网页读取，也不启用新的原生搜索请求 |
| 自动 | 已声明支持时，优先使用已适配的 OpenAI/DeepSeek 官方 Responses 或 Anthropic 官方 Messages 搜索；自定义中转使用默认搜索 API |
| 指定搜索 API | 使用默认连接，不同时启用原生搜索 |
| 模型原生联网 | 支持明确声明的兼容 Responses / Anthropic Messages 接口；中转须单独验证，不支持的模型/协议会在派发前报错 |

DeepSeek 官方原生联网使用 `deepseek-flash` 的 Responses 协议，发送 `deepseek_web_search` / `deepseek_read_url`，不发送 OpenAI 的通用工具名。其他型号可以使用独立搜索 API。

Anthropic Messages 已接入基础 `web_search_20250305`、引用、服务端活动及原生内容块续接。本次按用户要求跳过 Anthropic 官方实测；中转 `claude-opus-5-5` 的单独搜索和小工具集可用，但 FreeAgent 完整工具组合下没有产生搜索结果。该组合建议使用 Tavily 等独立搜索，完整流程已验证。中转 `gpt-6.1-sol` 的 Responses 原生流式搜索及普通工具续接通过。

Anthropic `pause_turn` 会保留原生块并返回明确的暂停错误，不冒充任务完成，不自动重放；自动暂停续接仍待后续批次。Gemini 等其他原生协议也继续分批接入。验收细节见[真实联网验收](VALIDATION_WEB_SEARCH_2026-11-17.md)。

对话输入区的“能力”可以选择继承、关闭、自动或指定路径；该选择用于后续消息并保存在会话中。会话不能越过全局关闭来开启搜索。辅助压缩/分析请求不启用这套搜索工具。未保存过统一策略的旧配置继续保留原有 Responses 搜索声明；首次保存页面会明确采用新策略。

“搜索关闭”不代表断开模型 API、TG 或单独授权的浏览器。[浏览器和 Computer Use](AUTOMATION_EXTENSIONS.md) 为独立可选扩展，不由搜索开关自动安装或开启。

## 支持范围

本批次提供 DeepSeek、Tavily、Brave、博查、SearXNG、Exa、Perplexity Search、Jina Search、智谱、Serper、SerpApi 的适配器及本地契约测试。DeepSeek、Tavily、博查和 Brave 已使用用户提供的账号完成中英文真实调用；其余七家尚无真实账号验收。SearXNG 实例须开启 JSON 输出，不内置公共实例默认地址。

工具 `web_search` 只发送查询词与条数，不自动附带对话历史。查询最多 128 个 Unicode 字符，结果数量默认 5、最多 10；服务商的生成答案不充当来源原文。高级过滤暂使用该服务支持的查询语法，没有跨厂商统一的过滤开关。

`web_fetch` 读取公共 HTTP(S) 网页，默认正文输出预算 16 KiB、下载体上限 2 MiB、最多三次重定向；只接收未压缩的 UTF-8 HTML、文本、Markdown 或 JSON。HTML 去除脚本/样式并提取文本，不执行页面脚本。图片/PDF/登录页等使用其明确支持的附件或后续浏览器路径，不自动切换。

公共页面 GET 仍可能改变外部状态，`web_fetch` 保留修改类工具的授权和确认要求。不要用它访问退订、确认或提交链接。从 v9.0.0-dev.5 起，已有授权的读取无法取得正文时，记录「未读到」并允许模型继续处理其他来源。搜索和网页读取都不会自动重试；未读到正文不证明对端未收到请求。其它 HTTP、命令和外发操作仍按各自的结果规则处理。

网页正文和搜索结果是外部资料，不是执行指令或授权。回答应给出来源 URL；Responses 的来源注释会转成可点击的引用，并保留原生 item 供协议续接使用。历史中的完整工具结果继续由既有上下文工具按消息引用/范围回读，本批次没有另建网页数据库或全文索引。

搜索摘要和索引可能落后于原站。询问最新版本、日期等准确事实时，应继续读取官方原文并核对，不能把一个引用链接等同于正文已经验证。

## CLI 与对话操作

设置与 CLI/AI 使用相同的 `search.set_policy` 控制操作。它替换整份搜索策略，修改前先读状态并保留现有连接；秘密值不能放进参数。

```powershell
freeagent control catalog --json
freeagent control state --data-dir <data-dir> --json
freeagent control plan --data-dir <data-dir> --kind search.set_policy --arguments '{"mode":"off","timeout_seconds":20,"max_results":5,"max_output_bytes":16384}' --json
```

最后一条示例关闭搜索并清空连接，只适合新配置/测试目录。已有配置先取得完整策略再修改。随后使用既有 `control confirm` 流程确认返回的操作；对话中由 `control_read_state` 和 `control_plan_change` 提案，再经用户确认。Web 的直接保存使用同一控制面并校验修订，不额外创建一套设置。

## 网络与数据

公共网页读取不携带模型 Key、Cookie 或环境代理；DNS 结果、重定向与实际连接地址受公共地址限制。内网、环回、元数据与特殊地址被拒绝。显式配置的搜索服务地址是另一项授权，自托管搜索可以连接指定本机服务，但不会使网页读取获得内网权限。

VPN 的 fake-IP 模式可能把公网域名解析成 `198.18.0.0/15` 等特殊地址，本批次会明确拒绝。应为此进程/域名提供正常 DNS 与可达出口；不会以关闭私网校验或自动继承代理来绕过。自定义代理支持另行实现和验证。

本批次未改 PostgreSQL schema。旧程序的配置解码器不认识 `web_search` 和 `search` Key 协议，回退时须恢复升级前的配置与 Key 文件备份，不能直接让旧程序读取已保存的新配置。操作前保护凭据和会话数据，不以恢复配置为由覆盖新产生的执行记录。
