# FreeAgent 原 dev.5 草案（已被 v9.0 大版本计划取代）

日期：2026-11-22。**历史草案，停止作为发版依据。** 请执行 [v9.0 实施计划](FREEAGENT_V9_0_CHANNEL_CHATBOT_PLAN_2026-11-22.md)。原 v8.9.0-dev.5 排期已取消；v9 按工作包发开发版，正式版同时验收私聊与群聊。下列旧的网页读取 UNKNOWN 等规则不再是实施依据。

本版要让用户能回答三个问题：**群消息走到了哪一步？这段私聊的设置能不能当场改？一个来源没读完，其他工作能不能继续？** 以这三条实际流程检验 Core 与连接器的边界，不以搬了多少文件衡量重构。群内设置确认另批发布。

## 1. 现状与取舍

| 已有证据 | 本版决定 |
| --- | --- |
| 11 月 19 日对 Hytron 的排查：目标私有超级群已准入一名成员；当时保留的 3 条群事件均为命令，没有普通群消息启动的 Run。Bot 当时是普通成员，开启了隐私模式。 | 平台可能未下发普通群文本；这不能证明每条历史消息丢在哪里。先补分层诊断，不改 Bot 隐私设置、不扩大群准入。 |
| [TG 申请处理](../internal/harness/telegram_access.go)区分申请容量、身份和 Bot 绑定等条件，但[渠道入口](../internal/harness/channel_runtime.go)会给用户同一句「请求已满或身份不可验证」。 | 管理端显示可证实的原因；能给当事人安全、有效的下一步时再给。不是每个失败都应叫用户稍后重试。 |
| 「创建芋圆」是管理动作；未选中扩展时本轮读不到它。另一次设置冲突中，两次读取都是修订 5，是另一笔确认写成了 6。 | 分开说明「本轮未选中」「此操作须在管理页进行」「预览已过期」。只读查询不推进修订；也不为消除报错而放开创建人物或启用扩展。 |
| 平台收发已由独立 `freeagent-channel` 承担；群准入、命令、按钮和部分平台规则仍在宿主的 `internal/harness`。 | 本版迁出一条实际使用的 TG 策略路径，保留一个 Owner、一份执行记录和一份投递记录；不是重写全部渠道。 |
| [现有未决交接](../internal/harness/unresolved.go)只适用于若干工具。[公共网页读取](../internal/harness/web_search.go)的 GET 可能有外部作用：请求头已写出但连接中断时，[读取器](../internal/webaccess/fetch.go)可返回 UNKNOWN。 | 不把所有 GET 改成「只读可重试」。本版只让这一类已结束的网页调用可靠交接；未取得正文的来源不能算作已读。 |

## 2. 职责：谁判断，谁写入

| 归属 | 本版负责什么 | 不获得什么 |
| --- | --- | --- |
| 渠道进程与 TG 集成模块 | 进程解析平台更新、实际发送、接收回执；集成模块解释 TG 身份、准入/触发原因、每 Bot 确认名单、按钮及私下反馈。集成模块可与 Owner 同进程。 | 不直连 Core 数据库，不自行建 Run、改设置、重发外部操作或重建 outbox。 |
| 执行 Core 与宿主共享服务 | 沿用空间及请求人权限、冻结本轮能力；核对可信来源、目标、修订和一次精确决定；经同一控制服务写入。保存 Run、Attempt、协议配对、未决和投递事实，派发前复核撤权。 | 不维护 TG 用户 ID 名单或群管理员角色；不理解人物名称、群命令或表情。新增通用字段不能成为入口自报的「管理员」标记。 |
| AffectWeave 及后续扩展 | 扩展声明已有选项，提供本空间可见候选，使用时复核人物授权；人物创建、分段表达与主动发送仍由扩展负责。 | 选人物不等于启用扩展、授权工具或打开主动外发。本次不要求发 AffectWeave 新版。 |
| Web／本机管理入口 | 维护本 Bot 的确认名单，查看诊断，处理未开放的管理动作；复用现有认证、保存冲突和回读界面。 | 普通渠道配置保存、聊天消息、模型工具都不能改名单；配对、聊天准入、设置确认、普通工具审批不是同一种权限。 |

其他渠道以后各自验证本平台的人、群、线程与点击，通过同一个宿主入口提交一次明确决定。不支持可信点击或无法绑定受众，就转现有管理界面。本版不建设跨平台账户体系、群级名单、远端执行节点、集群或新的审批队列。

## 3. 实施顺序与交付物

### P0：先能解释群里为什么没回复

1. 在现有「渠道 → Telegram」设置里提供一处接收诊断，展示最近观测窗口、连接状态、各阶段计数/最近原因：**收到平台更新 → 适配器接纳或过滤 → 准入 → 命令／背景／明确唤起 → Run → outbox 送达、失败或未知**。记为群背景和直接办理命令都是正常结果，不一定有 Run；只有平台回执才算送达。
2. 区分「本时间窗未观察到更新」「收到了但无可验证个人身份」「未准入」「收到但未唤起」「已启动、未送达」。窗口/连接中断或旧数据不可追溯时显示「无足够观测」，不倒推 Telegram 丢包。申请已存在、申请满、身份无效分别给出管理员可用的动作；群内不暴露名单或其他申请人的情况。
3. 复用既有连接、入站意图、Run 和 outbox 的关联。能绑定到已准入群的观测可按该群查看；群身份尚不可知时只列为 Bot 级计数，不能用其他群的流量解释目标群。适配器尚未落库的事件只需有界计数和原因码，不存每条群消息作追踪，不记正文、token、申请码、原始平台身份或完整回调。不要求用户反复发消息，不给每条群文本调用模型。

### P1：把本次用到的平台判断移到渠道一侧

1. 从上述接收链提取 **TG 申请/准入的原因分类与群唤起处置**，并让 P2 的名单判断、按钮生成与映射放在同一渠道集成边界。选一个已有平台判断移出执行包，以「旧入口转接、新旧行为对照」验收；不要只在 `harness` 旁新建一份相同判断。贴纸目录、其他命令、Provider 和工具后端不搭车重构。
2. Owner 经已有受限桥接保存事实并提交设置。现状是 **`channelwire` v3、loopback、路由 `/api/channel-plugin/v1/`**，路由中的 `v1` 不是 wire 版本。先核实现有字段能否表达「已验证来源、原卡、原提案、单次决定」；只有缺失时才做最小协议变更。不更换传输方式、不要求改 Webhook。兼容旧连接器保留普通聊天；未协商该能力时设置转 Web，协议本身不兼容则明确拒绝连接。不能把旧工具审批解释为设置确认。
3. 编码前确定名单及其修订、提案终态、实际确认人三类事实的存储位置。能复用就复用，语义不够允许最小迁移，并明确恢复与回退。平台 ID 由渠道集成解释，Core 只保留必要的不透明来源引用；既有撤权检查和同一事务不拆开。

### P2：A 批，只开放 TG 私聊设置确认

| 在当前已准入私聊中提出 | 预期交互 |
| --- | --- |
| 「把当前对话切到模型乙」 | 名单内原发起人看到可用的已配置模型「甲 → 乙，仅当前会话」，批准后收到「已保存，下一轮生效」。不改默认模型。 |
| 「这段对话用芋圆」 | 仅在扩展已安装、已启用、已选中且本轮可用时，变更一个已获本空间授权的现有选项。其他 Skill、MCP、扩展、搜索及显式关闭值原样保留；只有本空间可见候选确实重名时才提示重名。 |
| 「创建人物／启用扩展／调整全局压缩」或在群里提出设置要求 | 指向合适的管理页；不生成可点击的群设置卡，不把完整预览发到群里，不留下阻塞下一条消息的待决 Run。普通工具审批仍只认原请求人。 |

每个**已核实的 Bot** 一份数字用户 ID 名单，默认空；只能在认证后的 Web／本机维护。点击时绑定 Bot、聊天、原卡、原发起人、提案及当前授权；名单撤销再加回也不能复活旧卡。未授权点击只向点击者本人反馈，不消费原卡。批准、有效拒绝、过期均由宿主给原工具调用写入终态并结束原 Run；**决定之后额外模型调用数为 0**。设置提交和通知是否送达分开记录。

同目标竞态只对上述获准的声明式设置处理：修订变化时，重新核对权限及**规范化后的完整目标**；完全相同记「另一笔修改已完成，本提案未写入」，不增修订；任何其他字段已变都须重新预览。创建、删除、外发以及 UNKNOWN 不走这条捷径。

### P3：一个网页结果未知，不拦住其他来源

先查原 Attempt、已有回执或只读证据。**只有能证明未执行，或接收端能保证同一实际操作在有效期内去重，才有资格在原授权、预算和次数上限内重试**；这不是给所有工具新增重试器。超时、本地请求 ID、HTTP 方法名都不是去重证明。

本版的具体改动是：对「请求已发出、未拿到可用结果、执行器已结束」的 `web_fetch`，复用现有原子交接，将该 Attempt 保持 UNKNOWN，为原工具调用补齐结果。**不重发该 GET**；同批尚未派发的有副作用调用按原规则标为未执行。模型在看到未决事实后，可按原授权处理其他独立来源；如果只有这一个来源，明确说缺证据。结束时报告完成和未完成的部分，不把未确认的网页列为已读引用。未知细节只向原有授权受众展示。

不改变可信只读失败、派发前拒绝、设置版本冲突或上下文超限的分类。数据库提交无法核实、仍在运行的失控进程、权限撤回等不能安全隔离的情况，仍停止相关执行；TG 发送未知继续由原 outbox 管理，不补发，不伪造回执。P3 可与 P1/P2 并行，不依赖 TG 真人测试。

## 4. 发布验收：用记录判定，不只看聊天文案

在独立 PostgreSQL、合成模型、模拟 TG 及受控 HTTP 传输上执行。固定输入、平台请求次数、配置修订、Run/Attempt、outbox 终态分别可查；报告只放脱敏结果。下表均为**待测**。

| 夹具/场景 | 通过条件 |
| --- | --- |
| 只有另一群有入站、未准入、无个人身份、申请已满、申请重复、普通背景、显式 @ 本 Bot、回复本 Bot、重复 update | 目标群无入站只报「未观测到」，不串群。其余能定位到实际阶段；未唤起背景和拒绝均不启动模型；同一合格唤起最多创建 1 个 Run。投递分别注入成功、明确失败、丢回执，三者不混淆。 |
| 私聊确认、双击、Web 与 TG 同时决定、回执丢失后重启 | 一次决定最多 1 次写入；有效批准后下一轮确实使用新值；回调至收尾新增模型请求为 0。通知丢失仍能从记录核对设置，不重写、不自动再次发送。 |
| 空名单、名单外点击、撤销再加入、换 Bot/聊天/原卡、批准前撤回资源权限 | 均不能用不合格的决定写入；未授权点击不消费卡、不公开身份。私聊名单不能替别人审批普通命令。Web／本机保存后可刷新回读，普通配置保存不会覆盖名单。 |
| 两次读修订 5；其他请求先写为 6；依次构造完整目标相同及不同 | 读不推进修订。相同则以「已由另一笔修改完成」结清，仍为 6；不同时不写入、要求新预览。未选中扩展不能借改一个选项被启用。 |
| 群请求改设置、转发/重连后再展示既有设置通知；群内继续发普通请求 | 无群设置卡、无完整预览、无新增待决设置 Run；公开消息及本次设置流程返回的材料不暴露私有值；后续合法请求可用。 |
| 三个独立网页来源 A/B/C；A 的请求头写出后断连，B/C 可读 | 以 HTTP 传输层计数，A 只派发 1 次；原调用有配对结果和 1 项持久未决。B/C 按原有权限可完成；最终列出两项已核实结果及一项未取得，不把 A 当成已读。重启不重放 A、不复制未决项，下一轮不因该项单独被锁住。 |
| 拒绝发生在派发前、摘要/窗口超限、未决交接提交不明、后台进程仍存活、分段 TG 发送回执丢失 | 给出对应原因。压缩不负责「修」权限或 UNKNOWN。不可隔离的操作保留阻塞；已发但未确认的 TG 段不重发，未派发尾段仍遵守原 outbox 规则。 |
| 无渠道、无扩展、旧协议搭配、前端桌面/窄屏 | 普通 Web/CLI 的会话、撤权、工具审批和上下文恢复不依赖 TG；检验实际可支持的新旧连接器组合，拒绝不兼容组合且不越权。渠道页可查看原因并保存名单，无管理权限的入口不能写名单。 |

本版通过条件：P0 能定位合成故障；P1 同时通过[包依赖检查](../scripts/check-core-boundaries.py)与平台规则归属审查（仅移动文件不算）；P2、P3 的权限、写入、真实派发次数和重启断言全部通过。用户验收分别标「模拟 TG」「真实私聊」「真实群接收诊断」「真实群内设置确认」；没测写 `NOT_RUN`，B 批按钮未开放不算通过。真实群消息不可见时只报告证据缺口，不把用户再次发消息当作诊断方案。

## 5. 构建、发布和回退顺序

1. **隔离验证。** 基于 dev.4 数据备份副本（或合成等价夹具）验证旧权限、会话、未决和投递恢复；Windows 跑 Core、渠道、前端和便携包，Linux 跑独立 Owner、渠道、端口和数据目录。覆盖「停用连接器，Web/CLI 仍能运行」以及新旧程序的兼容边界。不让两个实例同时轮询生产 Bot token。
2. **发行。** 实施完成、验收有记录后，才确定版本、更新 `VERSION`，推送 GitHub 并发布对应预发行 Release，包含 Windows/Linux 便携包、匹配的渠道二进制、校验值和变更说明。说明哪些是真人实测、哪些未测、A 默认空名单及 B 未开放；不把源码推送当作已发布，也不捆绑强升 AffectWeave。
3. **Hytron。** 发布物先在 Hytron 7C13 / Debian 12 的隔离实例验包。升级常驻 `freeagent` 前核对活跃/待决任务、暂停队列、现有授权、扩展选择和可恢复备份；有未能安全处理的活动则延后。更新后核对实际运行版本、TG 重连、公网 Web、会话/数据、授权和 outbox。名单保持空或原保存值，不替用户配确认人、开群权限、改隐私模式或启动被暂停的任务。
4. **真人验收与回退。** 真人私聊、群聊、点击或真实外发另行确认目标和允许动作，不沿用旧轮授权；没有测试条件就公开标注未测。若决策/权限不可靠，禁用设置按钮，保留 Web／本机管理及群预览保护。若需回退存储，先保留升级后数据，按已验证的程序和同一时点匹配备份恢复，避免覆盖新会话或重复投递；不能无损合并时先停并告知影响。部署过程只记入指定私有运维记录，公开报告不含凭据和私人标识。

## 6. 原 dev.5 草案未纳入的内容（历史记录）

- **B：群内设置确认。** 只允许改本群当前会话中已获授权的一个扩展选项；同群已准入且在本 Bot 名单内的人可决定，发起人可撤回自己的未决请求。候选、预览、失败提示、历史和重连通知都须经群受众检查。与真人群验收分开设门槛：数据流未核实或真实群未验，继续转 Web。不开放群内切模型；Forum Topics 仅在已有端到端话题绑定时启用，否则转 Web。
- **渠道继续拆分。** 优先按实际维护需求迁移其余 TG 命令、贴纸/表情和配置校验，再考虑飞书、QQ 等各自的确认入口。`chunkburst/xxb` 的「是否应该参与」思路仅作可选策略参考，不是 FreeAgent 群消息丢失的证据；不把逐消息模型判定、默认监听全群或切换 Webhook 作为修复条件。
- **旧能力只做回归。** [搜索及独立浏览器/Computer Use](WEB_CAPABILITIES_IMPLEMENTATION_2026-11-17.md)、[上下文与压缩](CONTEXT_MANAGEMENT.md)、[AffectWeave 等扩展的接入](EXTENSION_DEVELOPMENT_GUIDE.md)、经验总结 Skill 仍沿用既有能力。本次不重写它们，不改用户保存的模型、压缩额度、分段或主动发送偏好。新的未决工具类型按各自的事实依据逐项接入，不开放通用自动重放。
