# 登录页与工作台一致性修正（v8.8.0-dev.5）

依据用户提供的三张实际页面截图修正正式前端。登录页先交付草图，用户确认后接入原有认证流程；其余修正涵盖输入区、设置布局和 Telegram 选项。

## 已修复

| 问题 | 修复与作用范围 |
| --- | --- |
| 公网登录页缺少完整布局与状态 | 桌面双栏、窄屏单列，沿用工作台的主题；支持密码显隐、提交中、服务端错误与帮助提示。显示地址来自当前 `window.location.host`，没有固定部署域名 |
| AffectWeave 回复方式直接占用输入器工具栏，控件高度与周围不一致 | 移到“能力”弹层的“本次请求设置”。继续使用通用扩展字段，不把回复策略写入 Core；发送时携带本次选择，发送后恢复继承。扩展默认设置仍在扩展管理页 |
| Memory、投递授权的标题和字段不在同一条左边线 | 设置详情增加唯一 `.settings-content` 容器，宽度上限 1040px；标题、说明、控件和表单整体居中，不分别居中每个直接子元素 |
| 通用、后台命令也存在相同偏移 | 同一次容器修正覆盖全部设置页，不增加逐页偏移补丁 |
| Telegram 选项没有统一字号与行间距，长文本挤成一行 | 使用既有 `.check-line`；宽容器两列、窄容器单列，14px 字体、18px 原生勾选框、至少 44px 标签点击区。每项勾选后仍保存该连接原有字段 |
| 其他设置页的勾选项大小不一致 | 设置与能力弹层统一同样尺寸；投递授权中遗漏样式的主开关和规则选项补齐，不改变保存/确认流程 |

旧规则 `.settings-detail > * { margin-inline: auto }` 与 `.settings-detail .setting-field { margin: 16px 0 }` 同时存在，造成控件与标题分别计算位置。2560px 视口中实际测得多页的偏移为 588px；新容器解决了这个原因。

## 登录实现

确认的草图位于忽略目录 `output/ui-concepts-20261115/login/`，可离线打开 `index.html`。正式实现为 `features/auth/LoginPage.tsx`，沿用 A+B 蓝灰、白色表单区、中文系统字体及既有语义 token，不引入运行时依赖。

左侧对话与文件为合成示意，不读取真实会话。正式表单继续调用已有 Cookie 检测、登录和 CSRF 接口，错误文字来自服务器；不推测锁定时长或将所有错误归为密码错误。密码只存在内存，提交时立即清除；同步提交门闩阻止双击或重复表单事件发起第二个请求。登录后保留原页面查询参数，已登录会话刷新后正常恢复。
