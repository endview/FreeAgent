# FreeAgent 联网搜索、浏览器与 Computer Use 后续版本方案

- 日期：2026-11-16。
- 基线：`v8.8.0-dev.11`；本次源码核对工作树为 `0aad68c`。
- 状态：2026-11-17 已开始实施，当前为 S0/S1 及 N1 已验证部分的本地开发批次 `v8.9.0-dev.1`。实际完成范围、测试与剩余事项见[实施记录](WEB_CAPABILITIES_IMPLEMENTATION_2026-11-17.md)和[真实联网验收](VALIDATION_WEB_SEARCH_2026-11-17.md)；以下仍是完整分批目标，不把后续阶段视为已完成。
- 建议版本：FreeAgent `v8.9.0`，分开发版本交付；浏览器与 Computer Use 分别作为可选扩展发布，不阻塞搜索版交付。正式开工时核对最新分支，再确定具体 tag。
- 约束依据：[扩展开发原则](EXTENSION_DEVELOPMENT_PRINCIPLES.md)、[扩展开发指南](EXTENSION_DEVELOPMENT_GUIDE.md)、[Provider 契约](PROVIDER_CONTRACT.md)、[上下文管理](CONTEXT_MANAGEMENT.md)。

## 1. 本次要解决什么

FreeAgent 应能搜索近期信息、阅读来源并提供可核对的引用；需要登录、网页交互或操作桌面时，再使用用户安装并选中的扩展。

用户已确定的方向：

1. FreeAgent 自带搜索 API 接入，尽量覆盖常见服务商，不要求安装 AffectWeave 才能搜索。
2. 实际模型和接口支持官方原生联网时，优先使用这条路径；否则可使用已配置的独立搜索 API。
3. 内置浏览器和 Computer Use 通过扩展提供，安装后由宿主界面承载入口。
4. 扩展加载后，应向 Agent 准确说明本轮可用能力、使用方法和限制。
5. 保持 Core 轻量：Provider 协议、搜索适配、浏览器实现、桌面操作、渠道格式和人物策略各有归属。

本文采用的工程默认方案：单次请求只选择一条主要搜索路径；新配置默认关闭联网搜索；浏览器使用独立用户目录；Computer Use 首期支持本机 Windows、由本机用户开启控制。它们是本次方案建议，不冒充此前已经逐项确认的产品要求。升级保留现有配置和明确选择，不擅自关闭已有能力，也不替用户开启新能力。

本次编写文档不执行代码改造、真实计费 API 调用、GitHub 发布或 Hytron 更新。相关交付步骤见第 13 节。

## 3. 职责划分：业务能力不继续侵入 Core

| 所属 | 本次负责 | 不在这里实现 |
| --- | --- | --- |
| Core / Harness | 通用能力选择、授权、执行记录、取消、预算、结果与引用归属、UNKNOWN、上下文装配 | 某个搜索厂商的字段、网页 DOM 操作、Windows 鼠标键盘实现、人物策略 |
| Provider 适配层 | 官方原生搜索声明、协议块、引用、usage、流事件和续接转换 | 另建 Agent 循环；把厂商搜索块伪装成本地工具调用 |
| 随包内置工具与适配包 | `web_search`、`web_fetch`；独立搜索 API 请求/结果转换、正文抽取 | 把十几家服务商的判断写入主执行循环；默认启动浏览器 |
| 浏览器扩展 | 浏览器进程、页面/标签、网页观察、交互、登录会话、下载及状态证据 | 第二套任务调度、独立模型密钥、绕过宿主授权 |
| Computer Use 扩展 | 本机应用发现、窗口观察、UIA/截图、输入与坐标映射、接管/暂停 | 在 Core 内嵌完整桌面自动化栈、通过公网直接暴露控制端口 |
| FreeAgent 前端/桌面壳 | 通用能力管理、状态/引用展示、扩展面板承载、用户接管入口 | 在主聊天页硬编码浏览器或某个业务扩展的私有字段 |
| Telegram 等渠道 | 平台格式、引用链接、消息长度与投递回执 | 搜索策略、浏览器权限或人物行为决策 |
| AffectWeave | 人物是否需要查资料、表达方式、主动对话与自然分段策略 | 搜索 API 适配、浏览器驱动、公共联网开关 |

搜索是随包能力，不等于搜索实现全部放进 Core。浏览器和 Computer Use 拟各有独立扩展包、版本及发行记录；仓库是否独立不影响上述边界，优先独立仓库以免把大型依赖带入普通发行包。

首版不引入搜索网关服务、通用插件商店、跨机器桌面代理、第二套数据库或第二套调度器。优先复用既有 Attempt、附件/产物、控制面和扩展宿主；仅在现有结构无法表达必要事实时增补通用契约并说明迁移成本。

## 4. 搜索模式与路由

### 4.1 用户看到的模式

| 模式 | 行为 | 不可用时 |
| --- | --- | --- |
| 关闭 | 不启用原生搜索，也不提供独立搜索/网页读取工具 | 普通对话照常；不能声称已联网 |
| 自动 | 在本轮授权内，优先选择已核实兼容的模型原生搜索，否则选择配置的搜索 API | 显示缺失条件；不擅自选新服务商、换模型或安装扩展 |
| 指定搜索 API | 使用用户选定的搜索连接，原生搜索不同时启用 | 报告该连接错误；备用连接仅按用户已保存的策略启用 |
| 指定模型原生联网 | 仅使用当前模型/端点对应的官方能力 | 明确说明不支持或未验证，不悄悄切独立 API |

“模型支持联网”是能力事实；“本轮允许联网”是用户选择；“这次实际搜索了”是执行事实。三者分别展示。模型选了原生工具但没有真正调用时，不显示“搜索完成”。

本表控制搜索与公共网页读取，不是隔离所有网络的总开关。模型 API、渠道连接和已单独授权的浏览器各按既有边界工作；界面用“搜索关闭”，不能误写成“离线”。用户明确要求禁止访问网络时，所有相关工具仍须遵守该范围，不能改用浏览器绕过。

### 4.2 自动模式的确定顺序

1. 读取当前身份、权限模式、会话选择与已保存连接；无联网授权时不派发。
2. 匹配实际 Provider、协议、端点来源、模型和工具能力。不因模型名称含 GPT/Claude，或接口兼容 OpenAI，就认定支持官方原生搜索。
3. 检查本轮是否还需要普通工具；只有原生搜索与这些工具的共存、后续回传已经验证，才选择原生路径。
4. 原生不适用时，选择已配置的独立搜索连接。没有连接就提示配置，不自动向未经选择的服务商发送查询。
5. 本轮请求记录所选路径与选择理由。切模型、连接或权限后，在安全边界重新判断；不能继续用旧模型的签名块和能力判断。

用户要求“务必检索后再答复”，而原生接口无法保证调用搜索时，应报告实际未搜索；在已有授权允许时改走独立搜索工具，不能把工具声明当作检索证据。

能力表只拦截官方明确不支持的组合，不因新型号未收录就拒绝用户自定义声明。用户可以显式测试或选择未验证连接，但自动优先路由仅采用已有兼容证据的组合；两类状态在界面区分。

默认每个请求只暴露一个统一搜索工具和一个网页读取工具，不向模型堆叠所有服务商工具。保留用户主动指定来源或多源核对的能力；后者是有预算的多次调用，不是每个问题自动并发搜索所有厂商。

### 4.3 失败、重试和备用源

沿用现有恢复入口与错误分类，不为每个适配器另写无限重试。认证、额度、限流、明确不支持、空结果、网络中断分别处理；遵守 `Retry-After`。

请求尚未派发，或明确被拒且没有产生结果时，可以按已配置策略选择备用源。已经流出部分答案、调用过托管搜索或收费结果不明确时，不静默重发或换源：保留原 Attempt、标明中断及可能已计费，再依据现有有界恢复规则决定是否新建请求。搜索只读不等于重试免费。

`web_fetch` 失败不会自动启动浏览器、登录账号或购买抓取服务。额外路径须已安装、已选中且获授权；用户能看出当前采用了哪一种。

| 阿里云百炼 / Qwen | 本次已核对的是模型原生联网，归 Provider 适配 | N2 | 不能把 `enable_search` 直接冒充任意模型可调用的独立搜索 API [S6] |

Google Grounding 归原生能力。Google/Bing 其他历史搜索产品不凭记忆宣布可用或下线；若后续接入，先核对仍可申请的产品、条款及接口，不用已失效产品充当支持数量。

S1 的一个适配器受账号或平台限制时，不阻塞已验收的其他适配器发布，但 Release 必须逐家列明实际支持范围和未完成项，不能把整张候选表称为“已支持”。

### 5.2 通用结果契约

先按真正共通的字段归一化：查询、服务商、抓取时间、结果标题、URL、摘要、来源标识，以及有来源证据时的发布日期/正文引用。发布日期缺失就为空，不用抓取时间伪装发布时间。

高级过滤按适配器声明，包括语言、地区、时间、域名和结果数量。不支持的过滤在派发前说明，不悄悄忽略，不把本地结果后筛选称为服务端检索限制。

默认取约 5 条结果作为起始值。摘要长度、正文总量、单页量和每轮联网调用受现有预算约束；用 UTF-8 字节与估算/实际 token 分别记录，不混用中文字符数。搜索结果只给有界摘要；需要原文时按引用读取，避免一次把十篇全文注入上下文。

搜索服务返回的“生成答案”要标明是该服务的生成内容，不能冒充原网页原文。默认不为每次搜索再增加一次总结模型调用。

查询只发送完成搜索所需的内容，不自动附上整段历史、系统提示、人物资料或其他扩展状态。工具结果记录检索时间；时效性查询使用运行时日期与用户时区，不能沿用模型训练时间或伪造网页发布日期。

### 5.3 `web_fetch` 与 HTTP 安全边界

新工具负责公共网页正文获取。实现上提取并复用旧 HTTP 工具的地址、超时、输出和回执逻辑；旧 `http_get` 的已保存授权与行为保持兼容。

| 问题 | 实施要求 |
| --- | --- |
| URL/SSRF | 校验 scheme、主机、端口、DNS 结果和实际连接 IP；每次重定向重新校验；覆盖 IPv4、IPv6、映射地址、内网/环回/元数据地址及 DNS rebinding |
| 自托管搜索 | SearXNG 等私有服务用用户明确配置的固定 origin；不得因此允许搜索结果随意访问内网 |
| 凭据和代理 | 公共网页读取不携带用户浏览器 Cookie、任意 Authorization 或主模型 Key；代理必须走可核验的网络边界，不能绕过目标地址限制 |
| 内容与大小 | 限制下载体、解压后体积、正文大小、时间和重定向次数；校验 MIME；脚本不执行，HTML 抽取后输出文本/Markdown，不插入可执行 HTML |
| 动态网页 | 报告需要浏览器；不在 Core 临时启动 JS 引擎补抓取 |
| 下载/PDF | 复用附件/产物和已有解析路径；不把未知二进制当正文，不自动运行下载内容 |
| 缓存 | 有界容量和保留期，按连接/账号/受众隔离；默认不持久缓存登录页或私人正文；读取缓存明确时间，不把旧内容当最新 |
| 链接自身有动作 | GET 可能触发退订、确认等操作；不凭 HTTP 方法认定无副作用。明显动作链接交给现有授权流程，不能随搜索结果自动访问 |

新读取工具的授权范围应是明确的“公共网页访问”，与现有逐 origin HTTP 工具并存，不靠全局 `AllowNetwork` 绕过所有检查。`None/Read/Write/Full` 等已有模式的可用边界在 S0 核实并做回归，不暗改含义。

| Google Gemini | Google Search grounding，工具、来源与 grounding/annotation 元数据 [S5] | 使用实际支持该能力的原生协议；先核实 FreeAgent 的协议缺口；模型/工具组合限制和展示要求单独验收 | N2 |
| Qwen / 百炼 | Responses 与 Chat 等入口有不同开启方式 [S6] | `enable_search`、`search_options` 和 Responses tool 分开实现；不要统一塞进 OpenAI 标准请求 | N2 |
| xAI | 官方原生 Web Search 工具文档 [S18] | 型号、续接、引用和混合工具在实施时核对；X Search 是另一项能力，不默认同开 | N2 |
| 智谱、Kimi 等其他预设厂商 | 候选原生联网接入 | 独立搜索 API、模型内置工具和网页产品功能分别核实；未核实保持“未知/未验证” | N2 条件项 |

“N1”优先接入不意味着 N1 全完成才能发布独立搜索；不同路径可按第 11 节分别交付。没有真实凭据的官方能力不能因为 fixture 通过就标记已实测。

### 6.2 DeepSeek 的专项边界

本次官方文档明确区分原生联网与独立 Search/Fetch。原生页关于工具共存的中文描述与英文错误信息范围并不完全一致；因此，先验证它与 FreeAgent 普通函数工具同轮使用、工具结果回传后的下一请求，不能仅凭请求被接受就认定完整兼容。[S3]

原生网页读取部分内容需要签名块续接。删掉块可能失去原网页内容；摘要/裁剪必须遵守具体协议，不承诺所有原生块都可任意删除。原生联网后的未完成答案也存在不能按普通 assistant 前缀续写的限制，应由 Provider 恢复适配明确处理；重新发起可能重复检索和计费。[S3]

若共存或续接未通过，自动模式使用独立 Search/Fetch 路径；不新建“搜索专用 Agent”来掩盖不兼容，不自动更换用户主模型。

### 6.3 引用、预算与错误

1. 原生搜索发生在厂商服务端，由 Provider 适配器报告活动和 usage。FreeAgent 不能声称可以逐次审批它内部的每个查询、控制其网络出口或保证看到全部网页正文。
2. 在派发前明确允许联网的范围；支持域名、位置或次数限制的厂商才能下发对应字段。用户要求的硬限制无法实现时，报告不兼容或选择可满足限制的已授权路径。
3. 保留必要协议原文和有界规范化引用；不把私有签名、加密块和巨大响应无限堆进通用日志。来源不完整时如实显示，不补造 URL 或搜索次数。
4. HTTP 200、搜索进度、部分文本都不代表最终成功。处理流中错误、未完成、暂停和截断；不从不完整响应派发本地副作用工具。
5. 引用先按各厂商实际索引语义解析，再关联到稳定来源标识。不能混用 Unicode code point、UTF-16 和 UTF-8 字节偏移。
6. 费用显示使用已知用量和计费规则；缺失就写未知。实际调用次数、内部搜索查询数、结果条数不是同一个量，不能互相代替。

## 7. 向 Agent 声明真实能力

### 7.1 复用现有声明链

继续采用 `extension.json → initialize → tools/list / workflow / context → 本轮选择 → 权限校验 → 实际请求`。新增字段确有必要时，在现有协议和 SDK 内版本化；不平行建立另一套插件注册中心。

能力是否可用由以下事实共同决定：已安装、已启用、本轮选中、平台/依赖就绪、当前用户授权、模型能处理相应输入、后端服务可用。前端勾选不能代替后端检查，模型读到一段介绍也不能使工具自动可执行。

| 给 Agent 的信息 | 规则 |
| --- | --- |
| 名称与来源 | 稳定、带命名空间的身份；清楚区分内置搜索、厂商托管搜索、MCP、Skill 与扩展 |
| 可做什么 | 例如搜索公共网页、读取当前浏览器页、观察指定窗口；使用与实际工具 schema 一致的描述 |
| 何时使用 | 页面需登录/交互时才使用浏览器；桌面应用任务才使用 Computer Use |
| 如何使用 | 先观察再操作、使用页面/窗口引用、核实结果；不鼓励猜坐标或猜元素编号 |
| 限制 | 当前权限、目标范围、是否允许外发/文件写入、平台条件、需要人工接管的状态 |
| 不可用原因 | 未安装、未启用、未选中、缺连接、权限不足、缺桌面、模型无图像能力、后端失联分别说明 |

能力说明按需有界装配，不把完整操作手册和全部不可用扩展每轮塞入提示词。状态查询走既有控制读取；详细用法按需读取。Skill 说明不能充当新增执行权限，MCP 只读声明仍沿用本地信任开关与服务端提示共同核验的规则。

### 7.2 生命周期与兼容性

- 本轮冻结选定能力与版本；撤销授权、扩展停用或目标失效时，后续派发立即重新校验，不因冻结快照继续执行。
- 在安全边界更新实际提供给模型的工具集合及不可用说明。模型对旧工具的调用得到确定的不可用结果，不伪造成执行 UNKNOWN。
- 扩展升级增加操作范围时重新展示新增授权，不继承旧授权扩大到其他账号、目录或窗口。
- 安装、启用和本轮使用分别可见。`/new`、新会话、复制/恢复和升级沿用已有继承规则，明确“不选中”不可被默认值覆盖。
- 先验证现有工具附件能否把截图送入每个 Provider 的下一次请求。若需补契约，只补通用图像/产物引用、大小和受众校验，不加 `if browser` 或 `if computer_use`。
- 不支持图像的模型可在真实可用时使用 DOM/UIA 文本能力；截图必需场景明确不可用，不暗中换成另一个视觉模型。

安装了扩展但未选中时，可在控制面解释如何开启；不能启动业务进程、注入网页内容或替用户调用。卸载后主聊天、搜索与已有历史照常工作。

## 8. 浏览器扩展

### 8.1 首版功能

扩展按需启动自己的浏览器运行时，支持标签页管理、页面导航、DOM/可访问性快照、截图、查找、点击、输入、滚动、下载及用户接管。工具数量以完成这些流程所需的最小集合为准，不为每个 UI 事件制造一个独立工具。

使用独立浏览器 profile，默认不读取用户日常 Chrome/Edge 的 Cookie 或现有标签。用户手动登录在该 profile 中保留；清理登录状态、停用与删除数据是不同操作。运行时固定版本并随扩展包提供或由用户显式安装，不在启动时悄悄执行 npm/pip/浏览器下载。

### 8.2 页面引用与结果事实

观察返回浏览器会话、标签、frame、页面修订和短元素引用。操作必须绑定观察到的页面与目标；导航、刷新、弹窗或 DOM 重大变化后，旧引用应失效并要求重新观察。仅凭“第 5 个按钮”或旧坐标不能跨页面操作。

点击成功只证明输入已派发，不证明订单提交、文件上传或设置保存成功。操作后读取页面/下载回执等证据；无法确认外部提交结果时记录 UNKNOWN，不重按按钮。

普通 DOM 方式优先；截图坐标作为明确需要时的补充。不得向模型提供无范围限制的页面 JS 执行、任意宿主文件读取或通用 CDP 通道，借此绕过工具效应和授权。

### 8.3 宿主展示与平台

| 环境 | 首版安排 |
| --- | --- |
| Windows 本机 FreeAgent | 支持本机可见浏览器与接管；Web/桌面壳展示真实会话状态、截图及“打开/接管”入口 |
| Hytron Debian 12 | 可在独立环境验证无头浏览器公共网页任务；无图形桌面不等于有本机可见浏览器 |
| 公网 Web 访问者 | 清楚显示浏览器运行在 Owner 所在机器；打开网页面板不等于操纵访问者自己的电脑 |
| 需要登录但没有可见接管通道 | 明确显示等待人工条件；不假设验证码、双因素或账号登录可自动完成 |

前端复用通用扩展详情/面板挂载位置，首版采用受控状态和截图展示；不把第三方页面用任意 iframe 强嵌进主应用，不关闭站点 CSP，不开放裸露的 CDP/VNC 公网端口。完整远程交互画面可独立排期，不能作为首版已经具备的能力宣传。

### 8.4 额外注意事项

浏览器需要覆盖子资源、重定向、WebSocket、WebRTC、service worker 等网络路径；只检查顶层 URL 无法防止页面访问内网。浏览器扩展自行实现并测试网络隔离/出口控制，无法保证的部署不能声明具备此隔离能力。

浏览器 profile、下载和页面证据按用户/空间授权隔离。截图可能包含密码、验证码和个人资料；DOM 密码框隐藏不等于截图已脱敏。只采集必要页面，敏感输入优先交还用户，凭据不进入模型上下文或公开诊断。

截图设置尺寸、数量和保留上限，复用附件引用；图像进入 Provider 时按该协议计量，不在普通文本里再复制一份 Base64。用户可清理 profile 和截图缓存，已保留的必要执行事实与图片正文分开管理。

关闭标签或取消 Run 不证明外部提交已撤回；停止进程时保留已派发动作记录。首次安装说明浏览器进程、磁盘占用和支持平台，未安装扩展时普通 Core 不增加常驻浏览器资源。

## 9. Computer Use 扩展

### 9.1 首版边界

建议首版只支持本机 Windows 已登录的交互桌面，由本机用户发起或明确开启控制；Linux 图形桌面、macOS、跨机器控制另行排期。Hytron 无头服务器不作为桌面点击验收环境。

扩展可列出允许的应用窗口，获取窗口级 UIA/截图，执行点击、文字输入、滚动、按键与窗口切换。优先使用 UIA 稳定引用；没有可访问性元素时再使用截图坐标。拒绝把任意脚本/命令入口藏在 Computer Use 工具里绕过现有命令权限。

### 9.2 操作与中断

- 操作绑定当前用户会话、窗口身份、进程身份和最近观察；输入前复查前景窗口，焦点变化先暂停，避免文字输进别的应用。
- 验证多屏、负坐标、缩放、窗口移动和截图缩放映射；至少覆盖 100% / 125% / 150%，不得把截图像素直接当系统坐标。
- 提供持续可见的正在控制提示、暂停/停止入口和紧急中止方式；用户主动输入或接管时暂停自动操作，再观察后继续。
- 锁屏、UAC 安全桌面、桌面断开、不可见窗口或失去控制时报告不可用；不尝试绕过系统边界。
- 对外提交、文件删除、发送等派发后失联时保留 UNKNOWN。重新截图能提供新证据，但不一定证明先前动作未发生，不能自动重放。

默认不允许 TG 或公网消息直接获得本机桌面控制；该限制是首版建议策略，应明确展示，后续若扩展远程授权需单独设计。查询扩展状态可以沿用现有入口，但“知道已安装”不代表有权操作。

本地扩展进程不是天然 OS 沙箱。普通用户权限、扩展协议权限与真实操作系统可访问范围分别说明；不宣称 manifest 能阻止恶意原生扩展读取所有本机文件。

## 10. 交互、上下文与副作用规则

### 10.1 设置和日常入口

保留现有四组设置导航，不添加突兀的顶层专区：

| 位置 | 内容 |
| --- | --- |
| 能力管理 → 内置工具 | 联网搜索开关、默认模式、默认连接、结果数量和高级预算；显示本轮与全局的差别 |
| 连接与数据 → 搜索连接（拟新增） | 服务商、地址、Key 引用、测试连接、删除与错误状态；复用已有秘密存储，保持单一数据源 |
| 工作台设置 → 模型与 Key | 沿用现有位置，补原生联网支持状态、来源、已验证协议与限制；用户自定义端点显示未验证 |
| 能力管理 → 扩展 | 浏览器/Computer Use 安装、平台依赖、启用、授权、设置与接管入口 |
| 对话输入区 → 能力 | 本轮联网选择、浏览器/Computer Use 选择；不展开厂商配置表，也不重新加回 AffectWeave 回复方式控件 |
| 执行概览 | 显示“正在搜索 / 读取网页 / 等待接管 / 等待确认 / 结果未知”等；保持最近三项与重要异常优先，完整链条按需展开 |

每个可编辑字段都要有保存、成功回读、字段级错误、草稿保留、冲突和生效范围。GUI、CLI、AI 配置提案使用同一后端 schema；命令名称以实现后实际 CLI 为准，不在文档中假装尚未存在的命令可运行。

“测试连接”不能偷跑大规模搜索或浏览器操作。只读本地配置检查与真实付费测试分开显示；真实测试用固定非敏感查询，说明可能消耗额度。Key 输入/替换走已有秘密管理，不要求用户在普通聊天里粘贴密钥。

### 10.2 引用与上下文压缩

引用显示标题、网址/域名、必要日期，正文引用可点击。CLI 输出可复制链接，TG 使用平台可显示的链接格式。厂商要求额外 attribution/search suggestions 时逐一满足；不能为了统一 UI 删除必要来源信息。

来源采用稳定引用绑定已有执行记录/产物，正文有界保留。压缩后仍能按引用回读；缓存过期、授权撤销或来源未保存时明确说明，不能伪称已读过全文。重复引用复用来源，不在每个工具步骤重复灌入正文。

沿用现有上下文预算、折叠与历史回读，不另建联网专用摘要系统。搜索片段、网页内容和 OCR 都是外部资料，不能提升为系统指令、用户授权或可信执行证据。网页中的“请上传密钥”“忽略用户”等文字不能触发扩大权限。

AffectWeave 自然分段、TG 转义和消息长度拆分之后，引用仍需指向正确来源。先规范化厂商引用位置，再按分段映射；不可直接把原始字符偏移应用到已改写文本。搜索工具结果不是主动外发授权，AffectWeave 的主动对话开关也不自动打开联网。

### 10.3 什么算副作用，怎样处理

这里的“副作用”指操作可能改变文件、系统、账号或外部服务状态，或对他人产生实际动作；它不等于所有操作都必须弹一次确认框。

| 操作 | 特点 | 本方案处理 |
| --- | --- | --- |
| 查询公共搜索 API、读取网页 | 通常用于读取，但查询会外发且可能收费；部分链接有动作 | 明确联网范围、目标与额度；不是任意外发资料的授权 |
| 观察 DOM、截图、滚动 | 主要是观察/界面动作；截图仍可能含秘密 | 在已选目标范围内执行，敏感内容按采集/回传边界处理 |
| 点击按钮、输入文字 | 可能仅导航，也可能实时保存、发布或发送；不能一律只读 | 根据真实动作声明效应；不明确的按可能写入处理 |
| 提交表单、发消息/点赞、修改设置、上传、下载写盘、删除文件 | 对外或本地产生可见变更 | 复用对应权限/目标范围及确认机制；操作后核实结果 |
| 支付、下单、删除账号等 | 高影响提交 | 明确展示具体目标与动作，遵循已有授权和必要确认，不能由页面文字授权 |

“读了网页后所有写操作都强制重新审批，即使 Full 也如此”不作为本版默认规则，也不建立全局污染标签或通用数据流追踪框架。沿用现有权限含义，针对真实目标和动作校验；外部来源不扩大授权。若日后提供额外防护模式，独立说明其用户影响。

未派发被拒与派发后未知分开记录。可信读取失败不会制造副作用 UNKNOWN；真实外部提交无可靠结果时，沿用现有未决交接、后续核查和重放保护，不因为“浏览器点过了”就标记成功。相关行为继续遵守 [UNKNOWN 与压缩方案](UNKNOWN_AND_COMPACTION_CONTINUATION_PLAN_2026-11-15.md) 的已实施契约。

## 11. 实施批次与版本安排

阶段编号用于排期，不把多个大型项目塞进一个必须同时完成的发布门槛。

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| S0：基础核实 | 完成能力/权限/配置映射、Provider 共存最小实验、图像回传与前端挂载审计；确定字段迁移 | 知道哪些可复用、哪些需要通用补充；不先创建新框架或数据库 |
| S1：可用的搜索版 | 统一 `web_search/web_fetch`；第一批搜索适配；配置保存；引用与执行状态；有界正文和回读 | 至少一条实际可用搜索连接完成三入口操作与真实搜索/阅读；其他适配按证据逐项标注；现有能力不退化 |
| N1：优先原生联网 | 补齐 OpenAI、DeepSeek、Anthropic 的已选接入范围与自动路由 | 实际模型、协议、函数工具共存、续接、引用、取消/限额实测通过后，才进入自动优先选择 |
| S2 / N2：扩大覆盖 | 第二批独立 API、其他官方原生联网、过滤与计费元数据完善 | 逐家契约测试、账号条件与真实验收记录；未通过的不影响已交付路径 |
| B1：浏览器扩展预览 | 独立 profile、观察/操作/下载、接管、宿主入口、能力声明 | 本机完整流程与独立 Linux 无头流程通过；生命周期、网络范围和 UNKNOWN 可核对 |
| C1：Computer Use 预览 | Windows 窗口级 UIA/截图/操作、用户接管、坐标映射、授权状态 | 真实 Windows 桌面、多缩放、多窗口和用户抢回控制验证通过；不以无头模拟代替 |

建议 FreeAgent `v8.9.0-dev.*` 先交付 S1 与通过验收的 N1 路径，再稳定为 `v8.9.0`。其余搜索适配可以增量发布；浏览器与 Computer Use 各从扩展 `v0.1.0` 预览起步，确需宿主改动时在后续开发版交付。未完成的平台不写入支持列表。

AffectWeave 不与搜索版本强制捆绑升级。只有人物联网策略、分段引用承载等扩展自身逻辑确需改变时，才单独改其仓库、测试和版本。

### 12.2 真实验收

2026-11-17 验收范围调整：用户指定跳过 Anthropic 官方实测，随后允许中转 Claude 测试。官方保留 `NOT_RUN（用户指定跳过官方）`；DeepSeek、四家已提供的独立搜索 API、中转 GPT/Claude 按实际协议分别验收，其余服务有配置后逐家补验。

- 搜索：用非敏感问题完成搜索、打开原文、对照引用，再验证时间/语言/域名过滤。真实访问条件不足写 `NOT_RUN`，Fixture 不证明服务商可用性或质量。
- 原生联网：至少覆盖一个已授权官方实际端点，分别测带普通工具和仅搜索请求；中转通过不替代官方证明，官方通过也不替代用户中转实测。
- 浏览器：公共静态页、动态页、标签切换、表单草稿、下载及登录接管；提交类验收优先使用自建测试站，不向真实收件人发送测试内容。
- Computer Use：真实 Windows 的多屏/缩放/焦点变化、文本输入、停止与接管；用测试文件/应用，避免触碰真实账号提交。
- UI：桌面宽屏、常规宽度、窄窗口、真实手机；长服务名、缺 Key、断网、全部设置组展开后的导航/滚动、等待接管及错误状态都无偏移。
- 渠道：TG 引用、长文本、AffectWeave 分段后的链接正确；真实发消息/表情/文件等仍需具体收件人授权，不能沿用此前另一组测试的授权。

记录搜索与读取耗时、结果大小、实际 token、模型请求数、压缩触发和已知费用。比较未启用新能力时的 Core 启动/空闲资源、发行包和首屏；浏览器/桌面依赖不得使普通 Core 常驻占用增加。阈值在 S0 同机实测后确定，不凭空声称节省多少费用或固定能承载多少页面。

## 13. 迁移、文档与发布

### 13.1 配置与兼容

旧 `web_search: supported` 的能力声明不能被直接解释成新用户授权；先核实旧版实际派发语义，在迁移测试中保留用户既有行为，再明确展示新分离的能力/选择状态。所有新增连接默认不启用，现有显式开关和会话能力排除不覆盖。

Key 继续使用已有秘密存储，普通配置保存引用。迁移不复制凭据到仓库、发行包、浏览器 profile 导出或报告。首版优先不改数据库结构；若截图/来源生命周期确需 schema 变化，另写迁移与备份恢复路径，不能宣称旧二进制直接可回退。

新扩展遇到旧宿主缺能力时，应在检查/启用阶段说明最低要求；新宿主配旧扩展不强行补出声明之外的工具。停用、卸载、保留数据、删除 profile/截图缓存有明确区别；清理扩展数据不能误删 Core 历史或用户普通浏览器数据。

### 13.2 开发文档交付

同步更新 [扩展开发原则](EXTENSION_DEVELOPMENT_PRINCIPLES.md)、[扩展开发指南](EXTENSION_DEVELOPMENT_GUIDE.md)、[扩展协议](../extension-kit/SPEC.md)、[Provider 契约](PROVIDER_CONTRACT.md) 和 [设置覆盖表](FRONTEND_SETTINGS_COVERAGE_V8_1.md)，并交付可复现示例：

1. 新增搜索适配器：连接/秘密引用、请求映射、归一化结果、测试和 UI 状态。
2. 新增厂商原生搜索：匹配规则、协议块、引用、usage、恢复与普通工具共存。
3. 新增有图像输出的扩展：声明、工具、产物/截图、受众、模型能力校验及取消。
4. 为扩展增加宿主入口：沿用详情/面板承载，状态可回读，不在 Core/聊天区硬编码业务。

正式指南只写已实现并在独立目录跑通的命令，不将本计划拟定的工具或设置名当成现成功能。

### 13.3 发布与 Hytron

进入实际发布阶段后，按用户的发布指令执行：源码/测试完成 → 版本及兼容表 → GitHub 推送 → Windows/Linux 包与校验和 → Release → Hytron 独立验证 → 维护窗口升级 → 数据与连接核对。

Hytron 保留现有 TG 会话、未决记录、凭据、排队输入和明确的扩展选择；升级程序不等于替用户安装/开启浏览器或桌面控制。常驻 `freeagent` 维护前核对在跑任务，独立验证使用不同 unit、端口与数据目录，不能用同一 Bot token 同时接收入站。

搜索版在 Hytron 验证连接、引用和上下文行为；浏览器版单独验证已支持的无头范围；Computer Use 首版在 Windows 验收。备份、回滚条件和实测结果按本机协作约定记入私有 VPS 文档及忽略目录，公开 Release 只放脱敏说明。

## 14. 首版明确不做与仍需确认的事项

不做通用网页爬虫平台、自动 CAPTCHA/登录绕过、跨机器桌面集群、任意远程控制端口、搜索结果向量数据库、自动安装依赖、每个服务商一个 Agent、所有工具的语义副作用识别，以及因读取网页而引入的全局审批框架。

开工时用 S0 实验解决三项技术问题：原生搜索与现有工具的共存；图像从扩展到 Provider 的完整路径；浏览器面板在本机/远端分别能提供什么接管能力。实验不通过就缩小对应发布范围，不削弱授权或隐藏不可用状态。

以下为方案建议，可在实现前按用户偏好调整：新配置默认关闭联网搜索、是否开启跨搜索服务备用源、付费网页抓取是否作为备用、Computer Use 首期仅 Windows 本机启动。默认关闭跨服务商备用与付费抓取备用，用户可明确启用；真实计费调用和外部提交仍按具体任务授权执行。

## 附录 B. 本次整理消除的歧义

- “模型本身联网”指请求启用了厂商托管工具，不是模型无需接口就能访问实时网络。
- 原生搜索可能返回来源、引用甚至部分内容；不能笼统说它只给答案或无法查原文。能否回读由实际响应和权限决定。
- FreeAgent 已有部分 Responses 搜索、HTTP 读取和扩展工具注册，本版应补齐并整合。
- 安装扩展不等于本轮可用；能力说明、真实工具定义、模型输入能力与后端授权必须对得上。
- 读取有隐私/计费风险，点击/输入也可能修改状态；不能靠动作名称一刀切，更不能把页面指令当用户授权。
- 浏览器和 Computer Use 的实现、依赖和生命周期属于扩展；AffectWeave 的人物、主动对话和分段仍属于 AffectWeave。
