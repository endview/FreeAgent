# 上下文管理

适用版本：v8.8.0-dev.2。GUI、CLI、Telegram 共用 Core 的装配、授权和压缩实现。原始对话与已捕获工具结果持久保存；投影、预览和摘要不会删除或改写原文，也不是执行成功的证据。

## 当前请求包含什么

固定执行规则与工具定义在前，所选 Memory 等稳定参考材料、当前授权视图的历史摘要和近期原文随后装配。Skill 与扩展仍按自身声明加入有界材料；动态块靠近当前输入。当前任务及已采纳引导、工具调用与结果保持协议顺序。未采纳的输入不会提前进入请求。

传输回执、命令回复和通知有独立类型。完整视图使用原创回答，避免把 TG 的分段回传当成第二次回答；渠道公开视图只使用该受众获准的公开内容。后台生成的候选及自动触发提示不冒充已说过的话，确认发送后才成为相应原创历史。

摘要按 `full`、`public_text`、`channel_public` 三种固定投影独立保存，服务端根据真实权限选择。它们互不覆盖。旧受限摘要无法证明来源安全时显示“需重建”，不能直接用旧私有内容生成公开摘要。分支不复制旧摘要。

## 三类额度

| 额度 | 含义 |
| --- | --- |
| 模型窗口 | 来自模型声明的 token 容量，扣除获准输出额度及安全余量；没有可靠声明时明确显示未知 |
| 请求字节保护 | Provider 实际编码的 HTTP 正文大小，包含图片编码，排除 Core 审计元数据；与 token 窗口分别校验 |
| 摘要目标 | 自动模式采用 token 软目标并保留独立存储保护；手动模式严格遵守指定 UTF-8 字节上限 |

未知窗口仍使用标明为保守折算的本地保护。输出 token 不从已知窗口场景的 HTTP 字节额度中重复扣除。图片编码计入载荷一次，图像 token 单独估算，不把 Base64 当正文 token 再计算。

旧的 128 KiB 请求保护和 10,240 字节等自定义值保留，不会因“恰好等于默认值”转成自动。窗口、输出及辅助思考放模型设置；请求字节保护等放上下文高级设置。设置只影响后续请求，活跃 Run 保留冻结配置。

v8.8.0-dev.7 新安装的请求字节保护默认为自动：窗口 W 已知时 clamp(W×8, 256 KiB, 8 MiB)，未知时 128 KiB。旧实例缺少 `context_byte_limit_mode` 时保持原手动行为；在设置选择“自动”并保存才切换，原手动数值仍保留。GUI、CLI/AI 的 `runtime.set_limits` 共用这一字段。

自动管理启用时先折叠工具正文，再尝试滚动摘要。预防性摘要失败而请求仍放得下时继续；到硬预算也不原参数重试已经确定无效的摘要。dev.7 可在有历史回读工具时应急省略已闭合的旧轮次；派发前、上下文来源与最终报告说明缺失，原记录和摘要游标不变。同 Run 按引用/修订复用选择，摘要覆盖或来源变化后只对仍匹配的记录生效。没有回读入口、自动管理已关闭或最小必需材料仍过大时，明确停止并指出原因。当前 Run 的必要协议字段不删除，不承诺无限长执行。

近期保留预算计算整个后缀，不能用一条短用户输入固定住其后的长工具结果。未决事实由原执行记录实时生成，不依赖摘要来解除。

## 日常操作

在输入区打开“上下文”，可以查看当前授权视图、最近准备请求、占用来源、摘要和暂停原因，执行手动压缩、重建、清除或保存默认目标。面板随同一条全局事件流更新，后台刷新不覆盖正在编辑的目标；保存仍检查编辑时的配置修订。

全局“设置 → 上下文”分别控制自动压缩开关、触发比例和摘要目标。自动目标与自动调度互不等同：关闭自动压缩后，手动压缩仍能运行。旧配置显示为保留的手动目标；可明确切回自动并保存。

| Telegram 命令 | 作用 |
| --- | --- |
| `/context` | 不调用模型，显示预算、最近测量和可执行动作 |
| `/compact` | 用户直接发起当前视图的手动压缩 |
| `/compact refresh` | 重建已过期的当前视图摘要 |
| `/new`、`/new 标题` | 已显式开启多对话时，原子创建并切到新对话；不取消旧任务 |

CLI 示例：

```sh
freeagent context inspect --session SESSION --json
freeagent context compact --session SESSION --summary-target auto
freeagent context compact --session SESSION --summary-bytes 10240
freeagent context refresh --session SESSION
freeagent config context --summary-target auto --automatic=true
freeagent config context --summary-target manual --summary-bytes 10240 --automatic=false
```

CLI 的 `--summary-bytes` 是单次维护目标或显式默认设置，具体取决于使用 `context` 还是 `config context`。模型提出默认设置、压缩或清除等持久修改，继续走已有确认；Full access 不绕过产品控制确认。

## 大工具结果与历史回读

完整的已捕获结果留在原始记录中。模型请求可以保留头尾预览、状态、退出码和原文引用；工具调用 ID、结果配对、思考签名及原生接续字段不因预览被改写。没有可用回读工具时不启用正文折叠。

模型可通过 `context_manage` 的 `read` 动作，按会话内引用、版本、UTF-8 字节偏移和长度读取原文。引用始终绑定当前会话与实际授权，不提供跨会话或模糊匹配。返回下一段偏移和原始大小；没有读到的部分不能声称已读。

单段和当前未压缩上下文内的回读合计均有界。重复读取相同来源、版本和范围只返回未变化状态。有效压缩后可以继续新的回读，不设普通 Run 整个生命周期的总读取量、步数或时长限制。

摘要对重复回读的引文保留引用和状态，不把整段引文重新总结；后续新发现、纠错和决定仍是摘要来源。工具自身已经标为截断的结果只能回读到当时实际捕获的内容。

## 失败、质量与观测

预防性压缩失败时，原请求能够安全容纳就继续。思考或输出配置导致的确定失败按同一视图和配置暂停；没有收益的压缩按语义来源暂停，不因普通通知重试。到达硬预算后仍重新判断当前请求及适用恢复，不原参数循环重发已知无效摘要，也不默认丢弃最早几轮。

摘要在完整候选通过预算、权限、来源和协议校验后原子生效。分片失败或提交 UNKNOWN 保留旧版及证据。摘要区分真实用户要求、参考信息、确认结果与待核实事项，保留近期用户原话的有界部分，并检查生成的历史引用。

估算与实际用量分别标明 Attempt。只有模型、协议、配置和已有前缀一致、请求仅追加内容时，才采用上一条实报输入加新增内容估算与余量；压缩、折叠或扩展内容变化会重新估算。缓存字段缺失显示未知，缓存命中不增加窗口。

## 升级与回退

没有新增数据库表或列；新消息类型、投递元数据和分槽摘要使用现有 JSON 与 meta。旧数据集中兼容读取，源完整性按未改写的原记录校验。

旧二进制不认识新配置字段、摘要槽及新回执读取方式。开始写入新格式后，不能只替换旧二进制来保证完整回退；应使用升级前一致备份恢复程序、配置、PG 与关联附件，并处理升级后新增数据。生产升级先核对活跃任务和投递，沿用既有备份与接续流程。
