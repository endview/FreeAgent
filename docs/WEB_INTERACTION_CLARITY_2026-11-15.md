# v8.8.0-dev.3：Web 状态与布局修正

这批修正来自实际页面和代码审查。沿用已有 React/TypeScript、Radix、语义 token 与 Core 控制协议，没有增加 UI 运行时、第二套状态缓存或扩展业务逻辑。

## 已修正的交互

| 原问题 | 现在的行为 |
| --- | --- |
| 设置同时显示会话侧栏、设置导航和资源列表，768 像素窗口里的编辑区只剩约 299 像素 | 设置使用独立导航和“返回对话”；资源布局根据实际容器宽度折叠，768×1024 编辑区约 487 像素 |
| 标题、简介和表单分别采用 700/860 像素宽度，边缘不齐；宽屏中表单仍被挤窄 | 同一内容轴、最大 1040 像素；桌面双列表布局有界，窄容器自动单列 |
| 所有页面统一写“全局设置” | 按客户端、Core 默认、空间、当前 Owner、条目或目标显示真实作用范围与生效提示 |
| 设置分类多而难找 | 增加本地设置搜索、当前分类语义标识，切页回到内容顶部 |
| 扩展处于 `stopped` 时像是未启用，启用开关在整个人物页下方 | 显示“未启用 / 已启用·按需启动 / 进程运行中 / 待初始化存储 / 不可用”；开关与立即保存说明放顶部 |
| 人物查看、当前对话选择、扩展默认人物混在一起 | 明确显示当前对话、下条消息使用的人物、扩展默认人物和最近实际请求；提供“预览用于当前对话”入口 |
| 默认人物为空仍显示“使用扩展默认人物” | 明确显示“未设置默认人物（不会注入）”，缺人物或受众不匹配时给出下一步 |
| 人物管理的高级 ID、分析、原始 JSON、状态演进、删除与备份堆在长页 | 按用途折叠；导入已有扩展时也按需展开。人物定义、当前状态、默认分析、高级运行和删除分开 |
| 全局开关、草稿、确认后的保存反馈不一致 | 直接开关明确即时保存；运行设置和扩展原始配置显示是否有未保存修改；控制确认完成给出两秒提示 |
| 在人物页修改配置后，旧的原始 JSON 草稿可能再把它覆盖 | 未编辑的原始配置跟随新值；有草稿时保留，保存前检查可见基线变化并提示读取最新配置。该前端检查不替代服务端控制版本约束 |
| “仅聊天”模式已注入人物，却清掉请求的扩展来源 | 保留已获准被动片段的使用元数据，显示在执行详情和人物状态页；没有工具或 Host 权限提升 |
| 320×568 能力弹层越过顶部，平板导航抽屉位移，窄屏上下文弹窗内部文字横向截断 | 弹层边界、可用高度、抽屉 translate、网格最小宽度及指标换行已修正；保存行不遮挡字段 |

“已选择”表示下一次准备请求会尝试使用；“已附加”来自对应的实际 Model Attempt，不保证模型采纳了人物风格，也不把配置状态当作历史执行证据。旧 None 请求没有保存扩展元数据时，不追溯伪造“已附加”证据。

## 比例验收

真实 Chromium 加独立 Core/PG，合成中文长文本、长链接与代码，实际发送 Echo 后检查聊天、设置、能力弹层、上下文弹窗、导航抽屉和保存字段。以下为 CSS 像素视口：

| 比例/使用场景 | 视口 |
| --- | --- |
| 超宽屏 | 2560×1080 |
| 16:9 桌面 | 1920×1080、1366×768、1280×720 |
| 16:10 | 1440×900 |
| 4:3 | 1024×768 |
| 平板竖屏 | 768×1024 |
| 手机竖屏 | 430×932、390×844、375×667、320×568 |
| 手机横屏/低高度窗口 | 844×390 |

逐项检查：无页面或设置横向溢出、输入与发送按钮可见、弹窗在视口内且内部可滚动、最后一个设置字段不被保存行遮挡。深浅主题和减少动态效果交替运行，保留截图并做视觉复查。新增可重复入口：`scripts/test-frontend.py --only layout`，与原测试一样需要 `--engine`、`--runtime`。

## 范围与后续

这是一批已确认问题的修正，不代表全部页面已完成产品重设计。空间级人物默认继承、统一所有设置页的字段级错误/未保存标识、减少高级策略的 JSON 编辑仍可继续做。本轮没有扩大人物授权范围，没有替用户开启分析、表情建议、主动发送或人格演进。

真实手机软键盘、原生 WebView2 的 125%/150% 系统缩放和辅助技术人工验收本轮未运行。浏览器视口、深浅色和减少动态效果检查不能代替这些真机测试。

双平台便携与 Hytron 部署结果在完成后补记；公网页面须刷新后使用新静态资源。
