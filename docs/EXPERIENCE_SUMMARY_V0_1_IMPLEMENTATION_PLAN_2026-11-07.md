## 1. 归属、文件和运行方式

经验总结是 **独立可选 Skill＋FreeAgent 入口**，不属于 AffectWeave，也不是 TG 或 Provider 功能。首版与 FreeAgent 同仓维护独立可选包，独立标记版本 0.1；不为一份 Skill 创建新常驻服务或数据库。

| 内容 | 位置 | 状态与责任 |
| --- | --- | --- |
| Skill 正文、示例、输出约定和说明 | `optional-skills/experience-summary/SKILL.md` 及同目录文档/合成样例 | 已实现独立包 0.1.0，包含版本、说明和三份合成示例；总结方法不写死在默认 Harness 提示词中 |
| 用户安装后的 Skill | 现有 `<data-dir>/skills/experience-summary/`，或显式信任工作区下 `.freeagent/skills/experience-summary/` | 复用当前加载规则；可选安装、默认不运行 |
| 来源选择、脱敏、普通 Run、范围校验 | 现有 Core 消息/Run、Memory/Skill、控制入口 | Core 通用支撑，业务内容由所选 Skill 提供 |
| 总结按钮与草稿编辑 | FreeAgent `internal/chatui/frontend` 的 Skill 管理和会话动作；CLI/TG 提供显式来源入口 | 不归 TG 插件；AI 提出的产物修改使用既有控制确认，不自动选择来源启动总结 |
| 确认后产物 | 现有 Skill 目录或 PG Memory 记录 | 继承现有作用域、版本、固定和撤销 |

发布包可以单独下载/启用，但不默认复制进每个 Core 的活跃 Skill 目录。未选择运行时没有总结模型请求；用户关闭总结能力后，已确认的产物按原管理机制使用。

## 2. 经验总结 0.1：独立可选能力

### 2.1 交付形态

依照既有决定，交付为可选 Skill 和“总结经验”入口，归入能力管理；不增加常驻进程或独立数据库。用户选取来源后启动一次普通 Core Run，使用已配置模型与现有预算。

| 产物 | 适用内容 | 保存与使用 |
| --- | --- | --- |
| Skill | 可重复流程，有输入、固定步骤、分支、验收和失败处理 | 现有 Skill 格式与目录；保存不默认执行脚本或启用 |
| Memory | 简短稳定约定、偏好或操作经验 | 现有有范围的 Memory；需要固定时明确选择保存并固定 |
| 草稿/局限说明 | 来源不足、失败未解决、UNKNOWN、一次性巧合 | 保留原证据和不确定性，不包装成成功经验 |

经验总结与上下文压缩、AffectWeave 人物经历分别处理。压缩不会自动产出永久知识；人物的私人事实不会自动变成全局 Skill。

### 2.2 完整用户流程

1. GUI 从单轮动作选取来源；CLI 选择 1–16 个 Run；TG 可选择 1–16 个 Run 及其消息范围。只读同一会话，渠道会话始终采用公开投影，预览实际内容和证据，不扫描整个数据库。0.1 不直接选择已有附件或产物作为来源。
2. Core 检查来源权限、版本和状态，提供有界内容；输入脱敏，排除 Key、凭据文件和默认不需要的 Provider 私有推理数据。
3. Skill 生成类型建议、标题、正文、适用条件、来源、局限和验收方法；用户可以修改类型与内容。
4. 显示具体内容、保存位置/作用范围、覆盖差异、是否启用/固定和预计上下文占用。
5. 通过现有持久确认发布。Skill 使用已实现的窄控制操作 `skills.publish`，不借普通 Full 文件写入绕过“模型发布经验必须确认”。经验入口保存 Memory 为新建，已有 Memory 的修改使用原管理入口。
6. 稳定来源与请求键防重复发布；覆盖已有 Skill/Memory 检查期望版本，冲突重新预览，不静默合并。
7. 发布后可在授权范围实际选择使用；停用总结能力不删除产物，撤销/取消固定/删除走既有管理。

来源选择、总结调用、草稿和发布结果复用现有消息/Run/产物记录，不新增“经验生命周期平台”。精确凭据匹配和常见秘密检查分别在输入与保存处执行；不宣称能识别所有未知秘密。

### 2.3 验收

至少用三类合成案例完成：可重复部署流程生成 Skill、短约定生成并固定 Memory、带未解决 UNKNOWN 的失败过程保留局限。验证 GUI/CLI/TG 范围一致、跨空间拒绝、确认/拒绝、重复发布、版本冲突、压缩后固定内容仍在、取消固定后新请求移除。

生成 Skill 不执行其命令；经验文本不提高权限；反应/贴纸/模型自评不能充当任务成功证据。
