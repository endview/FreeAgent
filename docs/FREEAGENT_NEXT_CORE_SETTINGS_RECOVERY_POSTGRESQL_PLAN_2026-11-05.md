# FreeAgent 后续开发：可选渠道、统一设置、执行恢复与 PostgreSQL

日期：2026-11-05（Asia/Shanghai）。状态：计划，尚未开始本文件中的架构改造。
输入交互补丁 v7.13.0-dev.2 独立交付，不作为本计划已完成的证明。

## 1. 用户确认的产品边界

1. TG、QQ、Lark 从默认 core 和默认配置中移除，按需安装渠道插件。
2. 模型 Provider/Key 与渠道凭据分别管理。模型协议列表不再出现 Bot 或应用 Secret。
3. 全局能力集中到统一设置，提供二级菜单；现有 Key 管理和能力管理归入其中。
4. 本轮/本对话能力留在输入框。GUI/CLI 运行中先排队，可手动引导；TG 直接插话。
5. 模型请求结果未知时允许自动重试；失败和 UNKNOWN 的原始记录保留，不能伪造成功。
6. 数据库改用 PostgreSQL。需要正面处理服务依赖、事务、Owner、备份和多核心场景。
7. 可选扩展统一命名为**经验总结**，位于“能力管理 → 扩展”。复杂且可重复的固定流程
   整理成 Skill；简单、稳定的经验可经用户确认固定到上下文。提炼逻辑不放进 core，
   不增加核心经验学习、资产治理、自动知识整理或后台扫描。

保持一套可组合 Harness。复用现有 Conversation/Run/Attempt/消息与 receipt，
不新增任务平台、插件市场、组织权限、多租户控制台或独立 Evidence/Checkpoint 系统。

## 2. 代码与生产核查结论

- `cmd/freeagent/owner.go` 在每个 Owner 创建 TG/Lark/QQ 运行时；关闭后不建立连接，
  但平台代码仍编入二进制。Harness、配置、UI 与平台实现存在直接依赖。
- `internal/chatui/src/main.mjs` 的 `key-protocol` 同时包含模型协议和 TG/Lark/QQ。
  当前设置入口集中呈现权限、工具、网络、渠道、压缩等内容，缺少清楚的二级导航。
- `internal/harness/channel_runtime.go` 在回复正文为空时，把任意 Run 状态与“UNKNOWN
  不会自动重试”拼在一起。生产最近一条 failed 记录实际属于输出限制，不能据此判为 UNKNOWN。
- `internal/harness/model.go` 的 `CallError.Certain/Category/Retryable` 已有分类基础；
  `Retryable` 目前只是建议，不授权自动重放。运行时已有 Attempt 与 UNKNOWN 事实记录。
- Store 目前依赖 SQLite，包括 JSON 路径查询/更新、`?` 参数、行号顺序、LastInsertId、
  部分唯一索引、PRAGMA、文件 Owner 锁、WAL 快照及 `VACUUM INTO` 备份。不能只换 DSN。

这些是核实的实现边界。渠道拆分后的体积/RSS/启动耗时、PostgreSQL 性能收益尚未测量。

## 4. 可选渠道进程与凭据分离

详细拆分边界见[渠道插件草案](CHANNEL_ADAPTER_EXTRACTION_PLAN.md)。

- 默认 core 包没有平台协议实现、Bot 凭据、轮询/长连接和专用配置。默认设置也不展示
  未安装渠道的空表单；在“扩展”中查看或安装可选包后才出现对应渠道入口。
- 一个渠道进程维护平台连接，可按明确聊天/空间绑定对接多个 core。每个 Bot 账号只由
  一个进程消费更新，不在每个执行核心复制连接、webhook、平台缓存和重试循环。
- core 保留标准化入口、空间/会话、用户身份约束和权限裁决。插件持有的能力令牌只允许
  所绑定来源与操作，不使用 GUI 管理员令牌，不直接打开核心数据库。
- 模型凭据属于 Provider 管理，平台账号和 Secret 属于渠道插件；可复用底层保密存储
  原语，但在类型、枚举、列表 API、表单、校验与导出中隔离命名空间。不能只改菜单名称。
- Provider 列表只显示模型提供方与其请求协议；OpenAI 兼容、Responses、Anthropic 等
  按实际适配器能力呈现。Telegram/Lark/QQ 永远不出现在模型协议下拉列表。
- 服务发行组合只是 core、可选渠道可执行文件和部署说明的组合，不维护另一份 Harness。
  不使用 Go 动态 ABI 插件，不建设在线插件市场或自研进程编排器。

验收包括默认 core 的 `go list -deps` 无平台实现、空闲时无平台连接、多 core 不重复
连接 Bot、插件/Owner 分别重启不重复消费、身份伪造/跨空间访问被拒绝、附件与回传可追溯。
TG 做真实私聊联调。Lark/QQ 保留已实现能力和模拟回归，其真实平台验收由用户后续安排。

## 5. 统一设置：一级分类与二级页面

主侧栏只保留“设置”作为全局管理入口。内部为分类导航和具体子页，保存位置、返回路径
和未保存草稿状态明确；切应用、切子页、刷新数据不清空正在填写的 Provider/Key。

| 一级 | 二级页面 | 内容 |
| --- | --- | --- |
| 模型与 Provider | 服务与凭据 | Provider 开关、地址、模型协议、Key、连接测试与返回模型列表 |
| 模型与 Provider | 可用模型与默认值 | 添加/删除模型、自动填充、默认选择、窗口/输出能力、Auto 的候选配置 |
| 能力管理 | 工具 | 全局工具可用性及默认范围；MCP 服务和连接事实 |
| 能力管理 | Skills | 已安装 Skills、显式启停与可见范围 |
| 能力管理 | 扩展 | 已安装工具/工作流/渠道包、可选的“经验总结”插件；未安装不创建运行时 |
| 权限与执行 | 默认权限和文件范围 | None/Ask/Workspace/Full、宿主/沙箱、允许目录与保护路径 |
| 权限与执行 | 命令与网络 | command_run 开关、单次命令策略、联网工具与允许目标 |
| 上下文 | 窗口和压缩 | 全局默认与模型窗口来源、自动触发比例、摘要限制；不放普通任务总步数/秒数入口 |
| 上下文 | 固定内容 | 用户确认的全局/工作区固定经验、来源与范围；当前会话的选择和排除仍在输入区 |
| 连接与安全 | 公网 Web | 登录、Cookie、IP 规则、防爆破、证书/代理事实与本机确认边界 |

设置页按内容按需加载，避免一开设置就探测所有 Provider 或启动插件连接。

### 全局与当前会话的边界

- 全局：安装/启用 Provider、工具、Skills/扩展、默认权限、文件/网络策略、压缩策略、
  数据库、渠道账号和公网安全，全部进入统一设置。持久化修改由 AI 提案时继续确认。
- 当前会话：选模型、在全局已允许的范围内选本对话能力、附件、当次权限选择、待发消息
  与引导、查看/排除固定经验，留在输入框。全局未安装/禁用的能力不能被会话选择重新启用。
- 当前 Run：仍冻结有效配置与权限；设置页明确说明新值对哪一轮生效。手动压缩可保留
  对话上下文入口，不能因集中全局设置而移走必要的就地操作。
- GUI、CLI 和 AI 对话使用同一控制契约，不能形成只在网页生效的设置或绕过确认的聊天接口。

验收：键盘/窄屏/深色模式可用；未保存 Key 不因失焦或导航丢失；连接测试不重置表单；
默认模型/模型列表操作持久有效；禁用全局能力后新 Run 与当前会话选择一致受限。

## 6. 可靠执行：先分类，再自动恢复

### 6.1 正确显示事实

失败、用户停止、输出截断、等待确认、上下文不足和 UNKNOWN 分开显示。TG 要给当前
问题的简短原因和可执行操作；有已确认的部分结果就保留并投递，不用万能 UNKNOWN
说明替代每个错误。原始诊断保存在记录中，按权限查询，提示不携带 Key 或服务器路径秘密。

### 6.2 自动重试策略

普通任务仍没有总步数/总执行秒数限制；重试属于一次调用失败后的恢复规则，必须有界。
建议默认最多自动重试 2 次，退避约 1s/3s 并加小量抖动；Provider 给 Retry-After 时遵守，
等待过长时显示等待并允许取消。默认值通过统一设置与现有控制协议调整，不另建调度系统。

| 已记录事实 | 处理 |
| --- | --- |
| 认证/权限拒绝、无效模型或参数 | 不用相同参数自动重试；显示具体配置问题 |
| 可恢复的 429/5xx、连接建立失败 | 在调用级次数内重试；记录每次真实派发及结果 |
| 纯模型请求已发出但响应未知/流中断 | 允许新 Attempt 重试，原 Attempt 保留 UNKNOWN；重试成功不把旧调用伪造为未发生 |
| 明确输出限制/length | 保留片段；在已有授权输出边界内尝试简短回答或合法续接，最多同一恢复预算；不执行未完成响应中的工具 |
| 明确上下文拒绝且未生成结果 | 沿用已有有记录的压缩后一次重试，并纳入统一恢复预算，防止两层各自无限重试 |
| 只读工具失败 | 仅当目标/输入与权限仍有效、工具声明允许时重试 |
| 已派发的写文件/命令/外部动作结果未知 | 先用 receipt、幂等键或可核对的后置状态确定结果；确认未发生才重试，确认成功则采用结果，仍未知则停止相关作用并提示核对 |
| 用户停止、取消、Owner 正在关闭 | 立即停止重试和等待，不因自动恢复又开一轮 |

用户要求 UNKNOWN 自动恢复，首先落在**结果尚未交付给任何本地工具的模型请求**上。
这样可能增加 Provider 计费，设置和日志明确可见。若 Provider 请求自身携带可能产生
不可逆外部作用的托管工具，则不能按纯模型请求重试，必须有该 Provider 的幂等/结果核对能力。
不能把“保留了失败日志”当作任意 Shell 命令或远端发送可安全执行两次的证明。

### 6.3 记录、接续与并发

- 同一 Run 继续工作，每次重试创建新 Attempt 并关联原 Attempt、输入指纹、原因、
  次数与决定；原 UNKNOWN/failed、流片段、usage 和已确认结果保持不可变。
- 一次逻辑模型请求只采纳一个完整响应；失败/部分响应返回的工具调用不能派发。
  迟到响应不能和重试响应一起进入工具执行。
- 为允许已安全替代的模型 UNKNOWN 后继续执行，增加轻量的结果处置关联；不改写旧
  Attempt 状态，也不让全局 UNKNOWN 阻断逻辑误把这个已处置的纯生成请求当成未决命令。
- 预算、重试派发与结果采用持久保存；Owner 崩溃后不能把次数清零或默认重放。未决
  写命令继续原核对规则，待发消息仍不能越过审批或未决作用。
- 引导、用户停止、权限撤销、模型变更发生时重新检查下一次派发。旧输入重试不能
  压过用户的新要求或换成权限更高的配置。

验收：故障注入覆盖首包前、流中、结束前断线、重复/迟到返回、限流、输出截断、停止、
重启和引导竞态；模型能恢复，工具副作用计数严格为一次。真实 DeepSeek 跑长对话与
受控中断，区分实际结果、模拟结果、未运行和 UNKNOWN。

## 7. PostgreSQL：单一新存储后端

按用户要求替换运行时状态存储，不长期保留 SQLite/PostgreSQL 双后端、同步层或旧平台
兼容层。原数据先可验证备份并保留；上线时如需要带入现有历史，只另写一次性显式导入工具，
严格核对字段、条数和关联，不能静默导入或在每次启动自动迁移。
是否实际导入生产历史在切换前单独决定；计划阶段不删除或改写现有 SQLite 数据。

### 7.1 产品与部署选择

- PostgreSQL 是共享的外部基础设施；多个 core 复用同一个 PG 实例，各自使用独立数据库
  和最小权限角色，不为每个 core 附带启动一个 PG，也不互相读取对话。
- GUI/CLI 继续 attach 同一 Owner。当前阶段不允许两个 Owner 同时执行同一个逻辑数据库；
  多核心意味着多个独立逻辑数据域，不新增多租户/组织权限平台。
- 本地 GUI/CLI 需填写数据库连接或接入用户已有 PG。便携包依然可解压运行程序，但不能
  再宣称不依赖数据库服务；发行说明必须在启动前说清依赖。
- 可提供用户显式启动的 PG 部署示例及独立开发测试 Compose。默认 core 不私自安装
  数据库、Docker、后台服务或初始化另一个机器上的数据库。
- DSN/密码使用秘密输入或凭据引用，不放进命令参数、聊天日志、公共报告和发行包。
  TLS 和证书校验明确配置，数据库网络连接不能被随意暴露到公网。

### 7.2 存储实现

优先使用 `pgx` 的现有连接池和事务能力。先提取 Store 内部连接/事务接口与关键 SQL，
不抽象一个能支持所有数据库的 ORM 平台。SQL 按实际 PostgreSQL 语义重写并集成测试。

- 参数改为 `$1...`；消息/Attempt 顺序采用显式序列，不能依赖 rowid 或事务提交的偶然顺序。
  新增采用 `INSERT ... RETURNING`，消息分支和输入采用仍保证完整边界。
- JSON 字段有明确格式与 JSONB 操作；保留既有记录身份和轻量 meta，不趁机拆成八套子系统。
- 队列取消、转引导、消费与 Run 创建使用同一事务锁定事实；源版本、唯一请求键、活动
  Run 唯一约束和审批摘要检查继续有效。并发写冲突只重试确定未产生作用的 DB 事务。
- 单 Owner 使用长连接 session advisory lock 或等价 PG 锁；连接断开会释放锁，Owner
  必须在检测到失锁后停止新派发并收束已有调用。锁连接必须独立持有，不能归还普通连接池。
  每次派发事务核对数据库保存的 Owner 代次；回写结果同样核对原派发代次，旧进程不能
  在失锁后继续以新 Owner 的身份记账。只靠本机文件锁无法保护其他机器。
- advisory lock 和代次校验不能撤销已经启动的宿主命令。初版不自动跨机器抢占同一
  数据域；旧 Owner 消失但仍有已派发调用时，先保留 UNKNOWN 并核对旧进程与实际效果，
  不让新 Owner 立即重复执行。人工接管须确认原进程停止、工作区与附件可用后再启用。
- 明确“失去 DB 连接但命令已执行”的处理：结果先按可保存的本机 receipt 保全并报告
  UNKNOWN；不能因事务没提交就再执行命令。DB 恢复后核对关联，再决定接续。
- 本地工作区、附件不可变文件和 OS 句柄仍在有权访问的机器上，不把所有大文件或秘密
  塞进数据库。跨机器搬 Owner 必须明确提供这些资源，不把数据库共享等同于文件共享。
- schema 初始化/升级是显式、可验证的部署步骤；未知 schema 拒绝。最小角色权限、
  连接池大小、连接/查询/事务超时和取消都有明确边界。

### 7.3 备份、性能与测试

备份从 SQLite WAL/VACUUM 切为一致的 PG 导出，并配套 config、指令和附件清单。
初版在维护边界禁止新派发和附件改动，保证 DB 快照与文件清单相互对应；既有任务要先
核查并收束，不新增一套分布式备份服务。恢复到新数据库和新数据目录后验证关系与文件，
禁止在线覆盖生产数据库。

验收使用真实 PostgreSQL（固定受支持版本）、独立测试数据库：

1. 核心全量/事务/并发、输入队列与引导、分支、摘要、附件、审批和失败记录等原契约通过。
2. 两个进程/两台主机竞争同一逻辑数据库，严格只有一个 Owner；失锁、断网、DB 重启
   不产生重复命令。不同逻辑数据库可独立运行。
3. 故障插入事务提交前后、连接池耗尽、死锁/序列化失败、命令结束但保存失败等边界。
4. 升级、备份、空库恢复、附件缺失与回退完整演练；生产旧备份始终保留。
5. 对比同样工作负载下的启动时间、空闲 RSS、请求 p50/p95、SQL 往返次数、并发吞吐
   和大历史查询。减少 N+1；队列、快照和日志查询继续有界。未测量不宣称性能更优。

## 8. 独立扩展计划：经验总结

### 8.1 名称与职责

用户可见名称统一为“经验总结”，归入“设置 → 能力管理 → 扩展”。它是新的可选插件，
按用户明确选择的执行记录提炼可复用做法。core 保存真实记录、提供有界授权读取与
既有能力调用，以及通用的上下文选择；core 不运行提炼、经验评分或后台学习。

“经验总结”与自动上下文压缩分别工作：压缩维持当前对话可继续，摘要会随对话更新；
经验总结产物需审核和选择用途，不因为发生了一次压缩就生成 Skill 或永久经验。

### 8.2 两类产物

| 适用内容 | 产物 | 运行时如何使用 |
| --- | --- | --- |
| 有明确触发条件、输入、步骤、分支/检查点与验收方式的可重复流程 | Skill | 平时提供名称和描述；用户调用或模型按已授予能力加载时才加入正文 |
| 一两条稳定事实、约定、偏好或简短操作经验，不需要整套流程 | 固定上下文 | 在选定范围的后续请求中持续带入已确认短文本，并计入窗口预算 |
| 证据不足、一次性巧合、仍含未解决 UNKNOWN 的结果声明 | 保留草稿或原记录 | 不自动发布为确定的成功经验；可以明确写成失败教训或待验证项 |

判断看流程是否可重复、步骤是否固定，不能只按字符长度自动决定。用户可在预览时
把产物改成另一种形式。生成一个 Skill 不默认把它的全文固定进每轮上下文。

例：带备份、配置修改、启动、健康检查和回退分支的服务部署过程适合 Skill；
“Linux 验收使用 Hytron Debian 12，普通测试使用独立目录”适合固定上下文。
“本次部署成功”是一次结果记录，不能直接升级为长期稳定规则。

### 8.3 用户流程与保存

1. 用户安装并启用扩展，选择 Run/会话、明确的消息范围或已授权的材料，发起“总结经验”。
   默认不扫描整个历史，也不在每次任务结束时自动运行。
2. 插件通过现有获授权接口读取结果、失败原因与必要上下文，生成候选产物。它不能
   把模型自报成功当作执行证据，不能读取其他空间、凭据或未选择的私有内容。
3. 预览显示建议类型、标题、正文、适用条件、来源和局限。Skill 显示输入/步骤/验收/
   失败处理；固定内容显示预计占用与生效范围。用户可以编辑或拒绝。
4. 用户确认具体内容及范围后发布。Skill 沿用现有 Skill 目录/格式和启用开关；
   简单经验优先复用已有 Memory 条目、版本与会话选择记录作为存储，不新增经验表。
   保存不等于自动启用：需要固定时，在同一次确认中明确“保存并固定”及目标范围。
5. 同一请求标识避免重复发布；已有内容的修改绑定期望版本，冲突时重新预览。禁止
   静默合并相反经验或覆盖用户已修改的 Skill。失败/取消保留已有产物。

固定内容是普通用户可管理的通用输入，不是插件专用核心对象。即使插件停用，已经
确认保存的 Skill 或固定文本仍可使用、修改、取消固定和删除；停用插件会停止后续
总结调用，不擅自删除用户产物。模型提出任何持久化修改继续走既有确认。

### 8.4 固定到上下文的准确语义

- 默认只固定到当前对话。用户可明确选工作区或全局范围；跨核心不自动同步。全局与
  工作区内容在设置中管理，对话输入区显示本会话实际带入的内容及其来源，可排除。
- 固定内容按源记录独立装配，不混进历史摘要，不随历史压缩消失；清除摘要不清除固定
  内容，取消固定则后续新请求不再带入。已发送的模型请求和旧记录不会被追溯改写。
- 同一固定条目在请求中只出现一次，当前对话显式排除项优先；相互冲突的条目显示冲突，
  用户选择替换或排除，不让插件暗自决定。当前明确用户要求可以覆盖普通经验约定，
  固定文本不能提高权限、启用工具或把历史宣称变成执行证据。
- 初版建议单条最多 2 KiB UTF-8、合计最多 8 KiB，同时受现有 Memory 与完整请求预算
  约束；先用少量内部默认值，不新增复杂预算面板。超限提示精简、取消固定或改为 Skill，
  不悄悄截断固定文本，也不无限压缩无关历史。
- 当前已有显式 Memory 选择，但 None/TG 路径不会带入这些本机私有条目。让固定经验在
  这些入口使用，需要补齐**通用的、已确认的公开上下文绑定**。默认只允许发布到本对话
  的短文本，保留来源、可见范围与撤销规则，不直接开放本机私有 Memory/Skill/扩展。
- 经验内容确认、保存和选择的版本需要一致。当前 Run 的选择保持冻结；修改或取消生效
  于后续新 Run，下一次派发继续检查源有效性，不能在后台给已授权运行加一条新规则。

因此这不是“把扩展生成文本直接塞进最高优先级 system prompt”。普通 Memory 参考数据
与用户明确确认的固定约定要保留不同来源标识，后者仍受当前请求与运行权限约束。

### 8.5 验收

- 不安装/不启用经验总结时，没有总结模型调用、扫描或后台工作；默认 core 不包含提炼器。
- 复杂流程形成可加载的 Skill，简单经验形成有范围和预算的固定文本，预览允许用户改选。
- 固定文本跨重启和多次压缩仍在所选范围生效；取消固定后新请求不再包含；全文不会因
  旧摘要又被自动固定回来。历史中对它的引用只是历史，不能被宣称为已删除旧历史。
- None/TG/群与本机私有范围互不泄露；未授权发布、来源失效、源版本冲突和重复确认正确处理。
- Skill 生成不自动调用其中的命令；固定内容不能扩大工具权限；未决结果不能被总结成已完成。
- 插件停用后已有产物仍可手动管理，删除产物按现有文件/Memory 删除确认执行。

## 9. 交付规则与停止条件

逐阶段提供实际源码、针对性和必要全量测试、使用/恢复说明及可下载产物，标明未运行的
真实 Provider/渠道矩阵。用户不需要模型输出哈希值。重试/插件/PostgreSQL 未实现前，
发行说明和界面不得提前宣称已支持。

Hytron 部署使用专门维护窗口：先查任务、备份并验证，再明确切换和健康检查；常规回归
使用独立 unit、端口、逻辑数据库和文件目录，不动 NPM 或其他业务。
渠道连接与数据库切换分别有回退路径，禁止一个维护步骤同时替换所有边界而无法定位失败。
