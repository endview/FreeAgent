# v8.8.0-dev.2 上下文重构验收

对应[三批实施计划](FREEAGENT_CONTEXT_STRUCTURE_AND_COMPACTION_REDESIGN_2026-11-14.md)。程序与便携归档来自干净提交 `8395050`；本记录在归档验证后补充，不改变程序。Core 继续复用 PostgreSQL、Run/Attempt、控制确认和扩展接口，没有新增数据库表、摘要服务或扩展业务算法。

## 交付行为

- 新写入区分用户输入、模型输出、工具结果、投递回执、通知、已发表内容和生成候选。投递确认使用现有 meta，不再另写一条可见于模型的助手副本；旧记录集中兼容，不能按物理相邻位置猜 Run。
- 主请求、摘要源和回读共用授权投影。完整工具组保持配对，异步发表/回执不切开协议；排队输入只在事务采纳后进入可见顺序。`full/public_text/channel_public` 摘要槽互不覆盖。
- 模型 token 窗口、实际编码 HTTP 字节和摘要目标分别检查。仅在配置、视图和已有前缀一致且纯追加时使用实报输入量校准；图片 Base64 不重复计入正文 token。
- 大工具正文可以转为头尾预览和准确引用，保留状态、退出码、UNKNOWN 及原生接续字段。原始已捕获内容可按当前会话、受众、版本和 UTF-8 范围回读；重复引文不反复总结。
- 自动开关与自动/手动目标独立。旧 `0`、10,240 字节和 128 KiB 请求保护保留实际含义，不能按数值猜自动模式。Web、CLI、AI 控制及 Telegram 确定性命令共用同一 Core；AI 提议持久变更仍需确认。
- 预防性压缩失败而主请求仍可容纳时继续；无效配置跨轮暂停，无收益按语义源暂停。硬预算重新判断，不原参循环、不自动丢旧轮次、不重放副作用。候选最终校验通过后原子生效。

使用方法见[上下文管理](CONTEXT_MANAGEMENT.md)，写入和读端清单见[记录来源契约](CONTEXT_RECORD_SOURCES.md)。
