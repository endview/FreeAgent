# v9.0.0-dev.9：统一设置与 Telegram 私聊管理绑定

本次预发行交付[管理账号计划](FREEAGENT_ADMIN_ACCOUNT_AND_SETTINGS_PLAN_2026-11-23.md)的 B、C 批。延续 dev.8 的账号、密码与入口隔离规则，不需要数据库结构迁移。

- **B：设置清单与保存一致性。** CI 对照 Core 配置、操作目录和设置页映射，缺少归属、入口、保存、回读或修订规则时失败。上下文预算、Provider Key 和渠道凭据保存会检查表单读取时的修订，过期草稿不能覆盖较新的配置。敏感值不回读；确认响应丢失时查询原操作结果，不自动重提。
- **C：可选的 Telegram 私聊管理绑定。** 在「设置 → 渠道 → Telegram 私聊管理绑定」管理每个 Bot 的绑定，默认不绑定。只允许已获准且已核实的私聊身份。服务器本机也可用 `freeagent admin telegram status` 查看；`bind`、`pause`、`revoke` 需要 Bot ID 和读取时的修订，建立绑定另需用户 ID。
- 绑定后，私聊可确认单独的全局自动压缩阈值，或在同一已保存的 HTTPS Provider 内切默认模型。允许提出但不能在 TG 确认的操作，转交到原 Web 提案；涉及扩大执行权限的变更仍需本机批准。重复点击不会重复写入，改密、暂停或解除绑定会使旧卡失效。
- 群聊不显示全局设置差异，不开放全局设置确认；现有会话确认名单、工具审批、渠道准入和 AffectWeave 选择不变。

测试使用独立 PostgreSQL、测试账号、浏览器与模拟 Telegram 回执。真实 Telegram 发信不在此次验收范围内。
