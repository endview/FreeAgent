# Telegram 渠道专项：格式、活动、贴纸与消息反应

日期：2026-11-07，实施更新：2026-11-08。状态：源码已实现，实际验证及缺条件项见 [验收记录](VALIDATION_V8_5_2026-11-08.md)；对应 FreeAgent v8.3.1 与 v8.4-B。本文维护 TG 平台规则，使用说明见 [渠道](CHANNELS.md)，版本排期见 [总计划](FREEAGENT_V8_3_1_TO_V8_5_CHANNEL_REASONING_EXPERIENCE_PLAN_2026-11-07.md)。

## 1. 归属、代码和数据

本专项属于 **FreeAgent 仓库的可选 TG 渠道组件**，运行在 `freeagent-channel`。用户没有安装/启用 AffectWeave 时，同样能够使用富文本、输入提示、收发贴纸和消息反应。

| 工作 | 所在位置 | 责任 |
| --- | --- | --- |
| Telegram API、格式渲染、UTF-16 与文件格式处理 | `internal/channels/telegram.go`、`media.go`；必要时增加同包内的 `telegram_format.go`、`telegram_stickers.go` | 平台行为和无状态转换，不判断人格/情绪 |
| 拉取消息/反应、调用平台、短效活动 | `internal/channelplugin/telegram.go` 与 `client.go` | 传递可信平台身份、资源和回执，处理连接/限流 |
| 与 Core 交换数据 | `internal/channelwire/protocol.go` | 有界消息/资源/活动/回执契约，不含人物规则或 Provider 参数 |
| 授权、资源可见性、消息与附件、可靠 outbox | Core 的 `internal/harness/channel_*`、附件与权限代码 | Core 配套工作；详细交付规则以 Core 投递专项为准 |
| TG 配置/资源预览 | `internal/chatui/frontend/features/settings/ChannelSettings.tsx`、必要的消息预览组件 | 前端归 FreeAgent；不加载扩展任意 UI 脚本 |

Bot token 由 Core 渠道 Key 命名空间保存并按现有启动流程交给渠道。平台游标和短效活动留在渠道进程；聊天记录、资源可见范围、启用的贴纸集合引用和逐项回执由 Core 保存。渠道可持有有界可重建的元数据缓存，不拥有第二套权限、会话或人物数据库。

贴纸/反应的语义判断由本轮模型完成；人物风格建议可来自 AffectWeave。TG 只返回平台资源和实际发生的事实，不将“点赞”自行换算成信任分数，也不根据表情触发人物学习。

涉及有序分片、停止、UNKNOWN 和主动投递的共同语义，引用 [Core 投递专项](CORE_REPLY_DELIVERY_PLAN_2026-11-07.md)；本文件不另定义一套重试与批准规则。

## 2. v8.3.1：TG Markdown 和正在输入

### 2.1 Markdown 转换方案

采用 **普通 Markdown → 语法树 → TG 文本＋MessageEntity**。优先使用成熟、维护中的纯 Go Markdown 解析库；实现前记录版本、许可证和包体积变化。不用正则替换承担整个 Markdown 语法，也不启动前端或 Node 做渠道格式化。

| 选择 | 评价 |
| --- | --- |
| 直接把模型 Markdown 当 MarkdownV2 发送 | 方括号、下划线、路径和代码的转义规则不同，容易请求失败；不采用 |
| 转成受限 HTML＋parse_mode | 可行，但拆段需闭合标签、转义并处理嵌套；保留作比较方案 |
| 文本＋entities | 显式指定样式范围，避免模型自己构造平台语法；采用，重点测试 UTF-16 偏移和拆段 |

首版映射：

| 输入 | TG 输出 |
| --- | --- |
| 粗体、斜体、删除线 | 对应实体 |
| 行内代码、代码块 | code/pre；语言标签仅在平台支持范围内传递 |
| 链接 | 文本链接，保留实际目标；禁用自动网页预览，延续现有行为 |
| 引用 | 平台支持时使用引用实体，否则可读的引用文本 |
| 标题 | 独立行和粗体，去掉语法用的井号 |
| 列表 | 保留编号/项目符号和缩进，不生成伪表格布局 |
| 表格 | 紧凑等宽文本或按行列展开；长表可作为附件交付 |
| 公式、HTML、未知标记 | 保留可读文本，原始 HTML 不执行，不擅自渲染远程内容 |

必须保留原回答；渠道展示转换不覆盖 Core 历史。不在代码块中删除 `#`、`*`、`_` 等合法字符。不为去掉符号损坏命令、文件路径或原文复制。

### 2.2 长文本与格式错误

- 平台渲染后按 TG 长度规则拆分，内部使用 UTF-16 单元校验实体范围，同时避免切坏 emoji、组合字符和代码结构。平台确切限制在实施时用当前 API 契约复核。
- 优先段落、行、句子边界；超长单行才做安全硬切。代码块跨条时分成多个有效 pre 实体，不能留下半截语法。
- 只有明确的格式/实体拒绝可以退回纯文本发送同一未送达部分，并记录降级；400 也须区分格式错误和无权限/目标不存在，不能一概补发。
- 网络超时、断线或成功响应无法核对时保留 UNKNOWN；不得为了尝试另一种格式再发一遍可能已送达的内容。
- 格式转换不能绕过授权、长度、附件和频率约束；不因格式失败重跑模型。
- 链接按既有安全规则验证，未知或危险协议作为普通文本；渲染器不为生成预览主动抓取目标页面。

### 2.3 正在输入

Core 根据真正的执行状态提供短效活动信息，TG 适配器调用 `sendChatAction`。默认对已启用 TG 的有效私聊回复显示，可在渠道设置关闭。

- 开始处理已接纳的输入、等待模型或短工具链时显示 typing；上传结果文件使用平台支持的对应动作。普通 emoji 和贴纸选择可复用相应活动类型。
- 不对未授权消息、未采用队列项、无人触发的群背景消息显示正在工作。
- 等待用户确认、停止、失败、完成、失去授权和渠道退出后不再续期。平台提示按其自身有效期消失，不伪造不存在的“清除 typing”请求。
- 每个 Bot/chat/topic 只保持一个有效活动，初始刷新间隔取 4 秒、内部租期取 8 秒，实施时按平台持续时间校准。同一聊天的多个关联动作不启动多个发送循环。
- 活动信息通过现有渠道连接附带的短效状态传递，进程内管理，到期即丢弃；不每 4 秒写一条 PG outbox、历史消息或交付回执。
- Core 不可用或租期过期即停止。活动请求 429/失败退避，不阻塞正文、附件和真实任务；不无限吞掉错误，诊断保留有界计数。
- 输入状态只是“正在处理”，不是思考内容，也不证明模型已经产生答案。

## 3. v8.4-B：贴纸、贴纸包与 emoji

### 3.1 先分清用户操作

| 用户操作 | 产品语义 |
| --- | --- |
| 发来一张贴纸 | 收到有效消息，记录来源、贴纸类型与可用预览，供模型理解 |
| 查看一个贴纸包 | 根据收到贴纸的 set_name 或用户提供的包名/链接读取列表 |
| 发包里的一张贴纸 | 从已知目录选择具体引用，调用 sendSticker |
| 把整个包分享给我 | 发送合法的添加贴纸包链接和名称；不把全包逐张刷屏 |
| 在回复中发 emoji | 普通 Unicode 文本，可单独一条或嵌入正文 |
| 给某条消息点表情 | 对那条消息设置 reaction，见第 4 节 |
| Premium/custom emoji | 与普通 emoji、普通贴纸不同；首批不宣称完整支持，按平台权限另行适配 |

首版从收到的贴纸、指定包名和链接获得可用集合，不读取用户 Telegram 客户端的安装列表，不建设贴纸市场、搜全网或整包后台视觉索引。

### 3.2 接收和理解

- 增加 Telegram sticker 结构与 wire 资源描述：平台文件引用、稳定识别信息、所属集合、emoji、尺寸、静态/动画/视频、缩略图和大小。只由可信入站事件生成，不接受模型伪造文件地址。
- 纯贴纸消息也进入当前空间/会话，不能因 Text 为空而丢弃；按现有私聊/群触发和权限规则处理。
- Core 保存通用媒体引用，TG 下载与格式识别由渠道适配器承担。真实 Bot token 和带 token 的下载 URL 不进模型上下文、客户端 URL 或公开日志。
- 静态 WebP 使用有界解码转成现有图像链可接受的 PNG/JPEG，限制字节数、解码像素和耗时，保留原贴纸引用用于发送。
- 动画 TGS、视频 WebM 先使用平台提供的可用缩略图作为视觉预览，同时标明这是预览帧。没有缩略图时提供类型、emoji、包名等已知信息，不能假称看过运动过程。
- 本批交付静态图识别及动画/视频的预览识别、原样发送；完整动画语义理解另列可选增强，需评估有界抽帧/渲染依赖，不默认随 Core 打包 FFmpeg、浏览器或 Lottie 服务。
- 当前模型没有视觉能力时，准确显示“收到贴纸，当前模型只能读取元信息”，不能把 emoji 标签当作完整图像描述。换模型仍由用户选择或已授权路由决定。
- 贴纸画面、标签和名称都是外部数据，不是执行指令；缓存图像遵守附件作用域和读取权限。

### 3.3 包列表与可用集合

通过 `getStickerSet` 获取明确集合的有界元数据；GUI 分页显示，缩略图按需加载，模型每次只获取一个小页或选中的少量候选。平台返回整包不等于整包进入模型上下文。

初值：每页 24 项、一次向模型提供不超过 12 个候选，下载与缓存复用现有附件限额；实际大包测试后记录调整依据。搜索先按包名、emoji、用户标签等明确字段，不默认花模型额度给整个包逐张打标签。

“本会话刚收到的贴纸”可作为当前回复候选；将包长期加入空间可用集合属于 Core 管理的持久设置，显示范围并确认。AffectWeave 可另存“这个角色偏好哪些已授权资源”的引用，但该偏好不能授予空间访问权。默认只在当前空间使用，不自动共享群和私聊的收藏。

使用内部资源 ID 表达模型选择，按 Bot 身份和作用域映射实际 file_id；file_unique_id 用于识别，不当可发送地址。更换 Bot 后重新解析可用发送引用，不沿用旧 Bot 的文件能力。

### 3.4 发送

- 普通、动画、视频贴纸优先使用平台可用的 file_id 直接发送，发送本身不需要先解析完整动画。首批不创建或修改 Telegram 贴纸包。
- 支持用户指定贴纸，也支持模型从明确授权的目录选择。普通聊天模型可在本轮获准的“回复表达”能力内发送，None 不因此获得文件、命令或任意网络能力。
- 模型只能选择 Core 提供的当前目标和可用资源引用，不能自行填写 Bot token、任意 chat_id、任意下载 URL 或伪造 sticker ID。
- 默认仍以文字完成任务；按需用贴纸回应。用户只要贴纸时不强制补一条同义文本；不让模型误把贴纸已排队说成已送达。
- 一次回答中自动选用的贴纸默认最多 1 张，可在明确设置范围内调整。超过上限返回可解释结果，不刷完整包。
- 回执记录实际平台 message_id 与资源引用；失效资源可重新查询明确集合，但 UNKNOWN 发送不自动重发。拒绝或失败不触发重跑原模型/工具。
- GUI/Web 展示贴纸预览和类型，CLI 展示可读引用及可访问附件；不支持的入口给出明确降级。

模型接入复用既有工具注册与调用记录，提供有界的资源查询和回复表达操作，不另建模型循环。只有当前目标支持且用户授权时才暴露；None 例外仅限原回复目标的交流表达，不能通过这条路径调用任意 Host 工具。模型不支持工具调用时，保留用户直接选择发送和文字回复，不用隐藏标记解析模型文本来伪造工具调用。

## 4. TG 消息表情回应

### 4.1 发送 reaction

新增给消息添加、更换、移除 Bot 自己反应的能力，使用 `setMessageReaction`。首版使用平台允许的常用 Unicode 反应；自定义和付费反应不在默认范围。

- 目标来自当前会话已知的真实消息引用，不能让模型自由构造其他人的聊天 ID。明确绑定 Bot、chat/topic、message_id 和当次授权。
- 默认只对当前正在回复的用户消息点一次表情；用户明确指定其他可见消息时才扩展目标。普通表达不会批量扫描历史挨个点。
- 用户可启用/关闭模型自主反应。默认关闭自主反应，用户明确说“给这条点个赞”可按本次意图执行；启用后在当前会话回复范围内无需每次审批。
- 首版每条消息至多保留 Bot 的一个普通反应，默认 `is_big=false`。这是产品初值，不推断所有平台类型有相同上限。
- 与文字、贴纸共用一轮表达记录，防止模型重复调用又重复发一条“已点赞”消息。无需文本时可以只用反应，但重要任务结果仍需可读交付。
- 权限不允许、消息已删或表情不支持时记录确切失败，不因为反应失败把已成功的主回答变成 failed。
- 设置/移除同一反应属于状态更新，与新发消息的副作用不同；恢复先保留原请求与回执，不在缺少平台证据时声称已成功或盲目新增消息。
- 允许模型调用反应接口必须同时让它知道可选反应、可操作消息引用和是否需要补文字，不能只写提示词宣称“可以点赞”而没有真实调用能力。

### 4.2 收到用户的 reaction

一并准备入站 `message_reaction` 等平台事件的处理，但只订阅实际能获得、已授权的类型。平台权限或匿名计数无法给出身份时，不伪造操作者；缺少事件也不推断用户不满。

已核对的原消息、操作者、原/新反应与时间作为互动事实保存，反应变化/撤销不能重复累计。普通计数只表示计数，不绑定到某个用户。

该记录可以供 AffectWeave 后续反馈分析使用：点赞最多是某个用户对具体消息的反应，不直接证明任务成功、用户爱意或关系改善；不自动成为 L3，也不自动写人物状态。

## 5. 本专项验收与维护文档

| 范围 | 必须覆盖 |
| --- | --- |
| TG 富文本 | 中文、路径、emoji/组合字符、嵌套样式、长链接、代码、表格、未闭合标记、跨段实体；原文可核对 |
| typing | 快慢请求、工具等待、审批、取消/失败/完成、Core 退出、租期过期、请求失败和限流，不形成历史垃圾 |
| 收贴纸 | 纯贴纸入站、静态 WebP、TGS/WebM 预览、有/无缩略图、无视觉模型、超大/畸形媒体、失效 file_id |
| 贴纸集合 | 包名/链接、分页/加载上限、包内容变化、权限撤销、更换 Bot、群与私聊隔离、整包分享只发链接 |
| 发表情 | 文本 emoji、单独 emoji、选定贴纸发送、添加/更换/移除 reaction、无权限/消息删除/不支持表情、拒绝越权目标 |
| 收到反应 | 明确身份、匿名计数、变更/撤销、重复事件、权限不足未收到事件；不自动增加关系或成功证据 |

与 Core 联测顺序、分片/资源权限和部分回执，且关闭 AffectWeave 后上述 TG 基础功能仍可用。真人客户端的样式、typing、贴纸和 reaction 单独验收；mock 不代表真实平台能力。Lark/QQ 不随本专项增加实现要求。

实施时同步 `docs/CHANNELS.md`、`docs/ATTACHMENTS.md` 与本专项状态，当前说明不得提前写成已支持。

## 6. 官方资料与限制

2026-11-07 已读取 [Telegram 官方 Bot API 实现](https://github.com/tdlib/telegram-bot-api/blob/master/telegram-bot-api/Client.cpp)，核对 sendChatAction、sendSticker、getStickerSet、setMessageReaction、entities 和 sticker 类型字段。

[官方 API 文档](https://core.telegram.org/bots/api)本轮读取遇到 TLS 握手失败；平台最新限额、私聊反应可见性和账户资格需在实施时补核对，不能因接口存在就宣称全部场景已验证。
