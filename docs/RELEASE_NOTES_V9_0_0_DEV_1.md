# v9.0.0-dev.1 — TG 接收链路诊断

本开发版交付 v9 计划 W1，不代表群话题与设置确认已完成。

- 渠道页新增接收与投递诊断：平台轮询、收到/过滤、准入、唤起、Run 和真实投递回执分别统计；已连接不再被当成“群消息已送达”。按聊天区分数据，无观测即显示无观测。
- 显示最近一次 Telegram getMe 的全局隐私模式；说明 Bot 群管理员身份可能扩大可见范围，不授工具权限。诊断不保存消息正文，随 Owner 代次重置；原执行和投递事实仍保留。
- 未唤起群消息在写入完整入站意图、消息和媒体前丢弃；不保存新背景。后续包提供明确开启、24 小时清理及旧背景管理。
- 接入申请满、个人身份不可核实、Bot 未绑定分别反馈；明确拒绝不再作为传输错误要求轮询反复处理。
- Core 与渠道程序统一 channelwire v4，须成对更新；协议不符明确拒绝并给出实际/要求版本。

本版不更改 TG 隐私设置、群/人员授权、模型、AffectWeave 选择或主动外发开关，不重放历史消息。私聊设置确认与群话题分别在后续开发包按同一 v9 计划交付。

实测与限制见 [W1 验收记录](VALIDATION_V9_W1_2026-11-22.md)。当前线上群的未观察到消息不能靠既有历史确定每条丢失原因；需使用新诊断记录定位实际发生的入站。
