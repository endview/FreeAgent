# FreeAgent：Telegram 会话设置确认实施方案

日期：2026-11-19。基线：FreeAgent `v8.9.0-dev.4`、AffectWeave `1.6.0-dev.3`。**历史专项设计，尚未实施；现行契约见 [v9.0 实施计划](FREEAGENT_V9_0_CHANNEL_CHATBOT_PLAN_2026-11-22.md)。** 私聊 A 与群内 B 各有开发版，正式版同时验收。群内不切模型、不建模型名单，论坛话题在 v4 端到端绑定；名单、精确目标、并发和受众测试仍可复用。

## 1. 目标与范围

首版要跑通的是：“把**这段私聊**切到另一个已配置且可用的模型”，或“用这个空间已获授权的芋圆”。具备资格的本人看清一个设置的旧值和新值，点一次批准，宿主就答「已保存，下一轮生效」。新设置不改变正在审批的 Run，也不为生成这句回执再调用一次模型。

人物和其他扩展选项都有前提：扩展已经安装、全局启用、已在当前会话选中，本轮也能看到它；目标选项已获准用于当前空间。**选用已有资源与授予新权限分开。** 创建/编辑人物和修改其授权空间仍在管理界面办理。未选中的扩展不能借“换人物”被顺手开启。

上次故障也说明了为什么要改反馈：两次读取都返回版本 5，另一笔确认才把同一选择写成版本 6，旧提案未应用。本方案借这个顺序测试“目标已满足”；原事件涉及**新增会话扩展**，不因此将这类授权加入 TG 可确认范围。

## 3. 两批权限表

已有准入、空间与人员权限继续生效。名单只允许作出下列设置决定；加入名单不会配对、提升到 Full 或赋予执行工具的权力。

**A：只在私聊确认。**

| 请求 | 名单内的原发起人在已准入私聊 | 任意 TG 群 |
| --- | --- | --- |
| 当前会话切模型 | 复用现有已配置且可用的模型选项；只换本会话模型，不改默认模型 | 只提示去管理界面 |
| 选用已授权人物，或改已选中扩展的一个已声明会话选项 | 一张卡只办一个选项；需在批准时仍可用 | 同上 |
| 自动压缩等全局设置、Provider、搜索、启停扩展、能力授权、人物管理 | 沿用已有管理入口及权限；无 TG 确认按钮 | 同上，不带设置预览 |
| 文件、命令等普通工具审批 | 仍按原执行权限，仅原请求人可批 | 同原规则；确认名单不能代批 |

首批群请求在生成设置提案前转管理界面，不创建群设置卡或留下一个等待确认的共享 Run。已从其他入口产生的待决提案仍由原管理入口处理，不自动撤销。名单为空、名单外私聊及不支持设置按钮的渠道不获得确认权。

**B：只扩到本群当前会话的既有扩展选项。**

| 请求 | 提出者 | 可作决定的人 | 群内结果 |
| --- | --- | --- | --- |
| 选用本空间已授权人物或同类单个会话选项 | 已准入、明确唤起的成员 A | 同群已准入且在本 Bot 名单内的成员 B（可与 A 相同） | 只显示本次可公开的旧值、新值和生效范围；不能完整且安全地表达就转 Web |
| 撤回这张尚未决定的提案 | A 本人 | A 只可撤回自己的请求，无须是确认人 | 结束等待，不写设置、不批准工具 |
| 群内切模型、全局设置、扩大权限或编辑人物 | 不建群设置提案 | 现有管理入口 | 不出群按钮、不展示管理信息 |

本方案不建立按空间保存的模型名单，也不在批次 B 交付群内切模型。不另设每群确认人、群管理员自动授权或跨渠道统一身份。

## 4. 用户看到什么

- 私聊：“把这段对话改用模型乙。”卡片写「当前对话模型：甲 → 乙。下一轮生效」。批准后由宿主回执；拒绝后回「已拒绝，设置未更改」，该轮结束。
- “用芋圆”只在当前空间可见候选内查找。唯一匹配时给预览；**当前空间确有多个同名候选**才提示「有多个同名人物，请到管理界面选择」。零匹配统一答「这个人物在当前空间不可用」，不透露它是否存在于其他空间。读取失败或结果不完整则提示暂时无法核对，不猜候选。
- 群里提出同一请求：A 批只提示去 Web；B 批获准后才展示本群的设置卡。未获准者点按钮，通过 Telegram 的 `answerCallbackQuery` 只向点击者反馈，群里不发送再删除消息；原卡仍留给有资格的人。

## 5. 实现约束

### 5.1 确认人员与存储

一份名单对应经 Telegram 核实的**数字 Bot ID**，同一个 Bot 不因出现不同聊天或连接名而分出多份；换成另一个 Bot 不继承名单。默认空，只能在认证后的 Web/本机「渠道 → Telegram」维护。采用数字用户 ID，不用群 ID、用户名或昵称。复用现有 Web 认证、CSRF、保存冲突和回读流程。普通渠道配置的全量保存不能改、清空或透出名单；模型提案、连接器入站消息也不能改名单。

开工先核实三个落点，记录决定后再编码：

| 需要持久化的事实 | 优先检查 | 判断标准 |
| --- | --- | --- |
| 谁可确认、本 Bot 的名单是否改过 | TG 渠道已有的专用授权记录和配置修订 | 只有语义本来就是“可确认设置”的授权才可复用。已核对的 TG 配对/准入只授权聊天。复用能反映名单变更的现有修订；移除再加回也不能复活旧卡，不建立人员级版本 |
| 提案结束的原因、是否真的写入 | 控制日志、提案关联的 Run/Attempt 结果及恢复路径 | 已保存、已拒绝、已过期、已由其他写入满足和结果未知能被区分，重启后仍一致 |
| 谁提出、谁实际作了决定 | 既有渠道绑定、回调记录与控制审计 | 能回查实际入口和确认人，不能把 B 记成 A、把系统比对相同记成用户批准；通用控制层只保留必要的不透明引用 |

现有存储能准确表达时不重复保存；否则允许最小结构变更，并补迁移、旧值默认、备份和回退验证，不用备注、错误字符串或无关字段冒充权限记录。名单不进入模型上下文或公开记录；渠道进程不直连 Core 数据库。

### 5.2 只接受一个明确的会话目标

渠道用已绑定的空间和会话定位请求，提案指定一个可验证的选项和目标值；不接受跨会话、批量或隐含扩权。规划和批准时都按真实差异检查，不能凭操作名放行。

- **模型（仅私聊）：** `conversation.set_model` 只接受现有配置里当前可用的模型引用，沿用已有选择和可用性检查。展示足以区分的名称，不暴露 Provider 地址、凭据或其他管理资料。没有可用选项就指向管理界面，不添加按空间的授权、配置页或模型清单。
- **已选中扩展：** 在已保存的能力选择上只改变一个扩展选项。人物按当前空间的可见候选判断；一般选项按扩展已有声明及取值校验。其余 Skill、MCP、扩展、搜索和显式关闭的值全部保留。`conversation.set_capabilities` 的整对象请求如果夹带别的差异，拒绝渠道确认。不允许借换选项启用扩展、主动发送或扩大其他权限。批准时以及扩展真正使用资源时，各自复核仍有权使用。
- **全局设置与群预览：** `runtime.set_limits`（包括自动压缩）、Provider、搜索和扩展管理都不在 TG 确认范围。A 批对群内设置请求只返回管理入口；对于投递到群的既有设置通知，包括重连再展示，也只下发提示，不拼接 `Confirmation.Preview`。限制范围是设置请求、设置卡及其提示，不改普通工具审批，不建设通用的群聊隐私框架。
- **群内候选（B）：** 按投递目的地和真实来源裁剪此设置流程的读结果。只向模型和卡片提供群可见、可核对的选项，不提供其他空间的存在性、配置旧值、完整人物或私有证据。数据流未核实、候选不完整或预览无法安全说清改动时，保持转 Web。

### 5.3 点击、撤回与 Run 收尾

1. TG 渠道核对真实个人、当前 Bot、聊天、原消息和仍有效的确认资格；私聊绑定原发起人，B 批群聊绑定同群已准入的确认人。名单和准入撤回按实际提交顺序处理。未经许可的点击不消费原卡，也不修改 Run。现有[连接器](../internal/channelplugin/telegram.go)已有 `answerCallbackQuery`，但目前固定答「已收到」。设置点击应根据可信的办理结果答复；未授权是已处理且未执行，不当作传输故障反复投递，也不当作批准成功。
2. Core 只接受可信[桥接](../internal/harness/channel_bridge.go)送达的、绑定这张原卡的一次决定，不接受文本或工具参数自报资格。复核 Run、Attempt、提案摘要、目标、版本、当前权限和候选，然后按现有提交边界完成一次。按钮不携带确认码或完整预览；Web 与 TG 并发决定时只有一个终态。
3. **批准后由宿主收尾，不再调用模型。** 给原工具调用写持久化结果并结束原 Run；用户收到「已保存，下一轮生效」。TG 设置的有效拒绝、过期、撤回或不支持也有明确终态：已存在的工具调用留下结果供模型后续读取，宿主向用户说明未写入及下一步；若在提案前拦下，则直接返回不支持并结束本次设置流程。不要为解释结果回到模型循环、换参数重提或隐式开新 Run。非法点击不是用户拒绝，不能替合法确认人结束提案。此要求仅改本方案的设置路径，不改变普通工具和其他入口的拒绝行为。
4. 复用现有提案期限和绑定校验，不另起群级 TTL、调度器或审批队列。当前控制服务的自动到期分支针对**直接操作**，不能假设老的 Run 绑定提案会定时释放。对本方案新建的 TG 待决项，在点击、恢复或下一次有人操作会话时按已保存期限判定；已到期就一次性结清等待，不让共享会话持续占用。
5. **确认人不在线（B）：** 原发起人可撤回自己的待决提案。现有 `/stop` 会暂停队列并请求停止，不能等同撤回；优先复用 [`TaskService.Abandon`](../internal/harness/taskservice.go) 已有的结束待决 Run 和 `withdrawProposal` 逻辑，提示明确写“撤回并结束本次等待”。须核对当前群、原发起人、原卡/提案和具体等待中的 Run，不按旧卡去撤销“最新一轮”。若通用命令不能精确定位，只加绑定到原提案的薄入口。撤回不写设置、不回滚之前的工具结果。
6. **Forum Topics：** 当前[桥接目标](../internal/channelwire/protocol.go)及 TG 入站映射使用平台、Bot、chat 等现有键，未发现 `message_thread_id` 端到端路由。本方案不新增话题群路由；B 批不能证明原话题绑定时，话题场景转 Web。若实施基线已有完整话题路由，复用其 topic ID 一并绑卡，并测同群跨话题点击；不以相同 chat ID 推定相同话题。

### 5.4 什么才算“目标已由另一笔修改完成”

只对 §3 **本渠道、本批次允许的会话级声明式操作**生效：私聊模型，或已选中扩展的单个现有选项。仍需同一资源、目标合法且可见，才能比较。不把已有的新增扩展提案或其他设置追溯改判。

| 点击或重读时的情况 | 行为 |
| --- | --- |
| 修订与预览仍匹配 | 按原有确认提交一次 |
| 修订变化，规范化后的完整目标与现值一致 | 记录「已由另一笔修改完成，本提案未写入」，结束等待；不写配置、不增加修订、不记一次批准、不重跑模型 |
| 修订变化，目标有差异 | 原卡失效并要求以新值重新预览；包括选中的人物相同但整份能力里其他设置已变。不得偷偷合并或沿用旧批准 |
| 创建、追加、外发、删除、执行命令、作用未知 | 不适用；保留原规则和证据。不能因为后来看到相同资源就推断第一次操作成功 |

配置提交和 TG 回执分别记账。回执丢失或卡片编辑失败时，通过既有记录查看原决定；不重新执行设置，不把 UNKNOWN 显示成已送达。

## 6. 其他扩展和渠道

后续扩展沿用已有清单、会话选项和业务授权，不因这次改动修改公共清单格式。只有**在会话中已选中、候选可验证、本次影响仅限本会话**的选项才适用。AffectWeave 继续管理人物及可用空间；模板或其他扩展按相同条件接入。无法提供对本受众安全的选项时，使用原管理页。扩展选项从不授权工具执行或主动外发。

其他连接器继续走原管理入口；将来单独接入时，由该连接器验证本平台的人和点击。Core 不维护跨平台的确认人员表。

| A | 群请求修改设置（含全局压缩），或来自管理入口的旧设置通知将投递到群 | 群只收到管理提示，不含合成的旧值、地址、路径或完整预览；群请求不创建待决设置卡、不锁住下一条群请求。普通工具仍只允许原请求人审批 |
| A | 重启、旧版连接器、回执丢失及管理页回归 | 设置结果和通知状态可分别核对；无重放。不同桥接版本、无名单和无扩展保持可用的管理入口；桌面、窄屏名单保存和冲突回读可用 |
| B | 成员 A 提出，名单内 B 确认或拒绝；无资格者、错误 Bot/群/卡、匿名身份尝试点击 | 只有当前同群合格者能决定该原卡；无资格者只收个人回调提示。B 不能借设置卡审批 A 的普通工具 |
| B | B 不在线时 A 撤回；撤回与点击竞速；提案到期后群再发请求 | 撤回仅结束原提案和等待，不写设置、不重跑模型。只有一个终态；旧卡不能影响后来 Run，群会话可继续 |
| B | 当前空间可见/不可见/重名候选；实际输入、卡片、失败提示、重连、回执、公开历史与 `/status` | 只出现这一次本群可见的差异，不泄露另一空间或完整人物；群内改模型和全局设置保持转 Web。未能证明数据流符合要求，群按钮不开 |
| B | Forum Topics | 仅在已有话题路由时测同群跨 topic 拒绝；本基线未支持，记“不适用：无话题路由”，不以普通群用例替代 |

真人验收另行确认 Bot、目标私聊/测试群及允许的动作；B 需要可区分的发起人和确认人。同一 token 不启动两个轮询实例。不具备条件时分别记录「模拟 TG：实际结果」「真实私聊：`NOT_RUN`」「真实群聊：`NOT_RUN`」。模拟群通过不能作为生产群验收记录。

## 9. 上线与回退

名单默认空，升级程序不自动加真实账号，不改变 TG 准入、扩展选择、人物空间授权或暂停队列。A、B 分开出验收和发布记录；仅在验证过的新桥接路径上受理设置决定，不将旧工具按钮解释为设置卡。

实施时按实际存储改动验证旧数据与恢复；如需迁移，写明备份和回退条件后再上线。出现问题先关闭相关渠道设置按钮，保持 Web/本机管理和已确认记录。回退不能恢复会发出完整群预览的路径、取消用户待决操作或覆盖对话数据库。
