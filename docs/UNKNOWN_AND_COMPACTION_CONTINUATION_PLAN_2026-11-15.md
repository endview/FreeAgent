# UNKNOWN 与上下文压缩：保留未决、继续执行方案

- 日期：2026-11-15
- 补充：2026-11-16，登记 AffectWeave 回复分段的独立核查与修正项。
- 基线：v8.8.0-dev.5
- 目标版本：v8.8.0-dev.6（批次 1、2）；v8.8.0-dev.7（批次 3、4）
- 依据：[排查报告](UNKNOWN_AND_COMPACTION_REVIEW_2026-11-15.md)、Hytron TG 会话记录及当前源码
- 状态：批次 1–4 已实现、测试并部署，最终发行 v8.8.0-dev.8（dev.7 主实现及公网交互补正）；不另部署中间 dev.6。实际结果见 [验收记录](VALIDATION_CONTINUATION_2026-11-16.md)。

## 1. 目标

1. 执行前拒绝、参数错误、可信只读失败按确定失败返回，模型能调整方法，避免误判 UNKNOWN。
2. 真正结果未知的动作保留为未决项。证据已可靠落库、工具协议完整且权限允许时，Run 继续其他工作，结束时由 Harness 汇总未确认事项。
3. 上下文按折叠、摘要、应急省略逐步恢复；原请求放得下时，预防性压缩失败不终止任务。
4. 原始记录、未知效果和已知部分作用保留。有副作用的原操作不自动重放；确认再次执行产生新的 Attempt。
5. 沿用现有 Attempt、meta、消息、outbox、权限和确认机制，不新增数据表、Run 状态枚举、通用依赖图或上下文框架。

任务结束与目标完成分别表达。用户停止、权限撤回、执行证据提交不确定、Owner 失联等不因“尽量继续”被忽略。

## 3. dev.6：失败分类与旧记录协调

### 3.1 分类规则

下表针对工具动作。主模型请求中断、数据库事务提交未知、后台工作流与投递记录各自沿用对应恢复规则，不能仅凭“没有文件副作用”统一改成确定失败。

| 情况 | 结果事实 | 处理 |
| --- | --- | --- |
| 执行前拒绝、参数错误、工具未启用或本轮未选中 | 已确认未执行 | 返回有原因的工具错误，模型可以修正方法 |
| 可信只读工具失败或超时 | 读取失败，无业务写入效果 | 不产生副作用 UNKNOWN，不启动通用核验；是否重试按错误类别和已有恢复规则判断 |
| 命令结束且非零退出、写入返回确定错误 | 调用失败；可能有已知部分作用 | 保留输出和部分作用，不宣称“没有改动” |
| 有副作用的请求可能已派发，最终效果没有可靠证据 | UNKNOWN | dev.6 保留现有保守阻塞；dev.7 按 §4 判断能否交接 |
| 工具仍在运行或进程清理未确认 | 运行状态或作用仍不确定 | 先沿用进程管理边界，不泛化为可继续的普通错误 |
| 数据库不可用、记录或事务提交未知 | 证据持久化不可靠 | 中止派发并协调存储；不得只记一段提示后继续 |

内置只读属性来自受审查的实现。MCP 仍要求本地显式 `TrustReadOnlyHint` 与远端 `readOnlyHint` 同时满足；扩展使用 Core 已接受的效应契约，缺声明按有副作用处理。

可确定的参数、能力和授权检查尽量前移到 Prepare；Execute 中再次检查以防权限在两阶段之间变化。拒绝和普通错误保存有界、脱敏的代码与原因。权限在动作启动后被撤回时，保留实际效果，停止新的执行。

`control_read_state` 应分别表达全局可用、本轮选中和受众可见性。查询操作 schema 时，即使附带的私有扩展状态不可读取，也应返回获准的 schema 与明确的局部错误；不把隐藏字段的空值解释成“未安装”。这不扩大能力或受众权限。

每个产生 UNKNOWN 的代码路径登记其类别、是否可能已执行、证据来源和交接规则。登记表与相关代码/测试共用，新增路径没有分类时检查失败；默认不自动交接。只读失败不再启动无法适用的单文件核验。

### 3.2 旧记录协调

复用 doctor/维护入口增加“预览 → 明确应用”操作，优先复用已有运行协调设施，不另建导入工具。实际命令及参数在实现时同步到帮助与指南。

自动判定候选必须有正向证据：原工具身份、冻结请求/能力、原实现版本和拒绝条件能证明未进入业务执行，或存在可信的明确未派发回执。不能把“没有开始日志”当作未执行证明；不能仅用当前工具的只读声明推断旧版本行为。

Hytron 的三条 `control_read_state` 记录以当时冻结能力为空、原请求及该版本的前置拒绝路径为核查依据。三条是预期候选数，实际数量必须由预览得出，不能按数量硬改。

- 先确认维护范围空闲并完成、验证现有在线备份。
- 保留原 Attempt 的 unknown 状态、请求和响应；向已有 meta 追加 `not_dispatched` 的协调结论、证据版本、操作者和时间。界面显示“原判 UNKNOWN，已核实未执行”。
- 为没有结果消息的调用幂等补齐“未执行”说明；已有用户结束时生成的占位消息不重复插入，后续投影使用协调说明。
- 所属 Run 只有在全部阻塞记录均被安全协调、没有活动调用/待确认操作时才解除阻塞。仍为 unknown 的该 Run 可结束为现有 failed，原因 `unknown_reconciled`；已经 abandoned/completed 的 Run 不改写为新状态。
- 应用时重新验证预览的源版本；有变化则重新预览，不覆盖迟到回执。失败可安全重试，不能产生重复结果消息。

dev.6 必须验收：原 TG 对话不用 `/new` 就能接受新请求，手动压缩可用；不自动恢复原业务动作或发送模型回复。

## 4. dev.7：未决项交接、继续与汇总

### 4.1 记录模型与统一判断

Attempt 记录执行事实，Run 记录任务是否仍在执行，二者分别判断。新增信息放在已有 `fa.meta`，按原 Attempt ID 关联；渠道项引用现有 outbox operation，不复制另一份投递状态。

| 信息 | 内容与作用 |
| --- | --- |
| `handoff` | 规则版本、来源、原 Run/调用、结果消息引用、完成时间；仅表示证据及协议交接完成，可继续安排工作 |
| `resolution` | 证据核验/用户确认/忽略、作用结论、来源引用、操作者、时间和修订；不覆盖原响应 |
| `display_number` | 会话内一次分配的固定短编号，绑定原操作；完成、忽略、迟到核验都不重新编号 |
| 备注 | 有界的核查说明与证据引用；模型意见明确标记为意见 |

“handoff 已完成”“事实已核实”“用户忽略”语义独立。出现 resolution 不能绕过协议未闭合、仍有活动进程、证据存储未知或权限限制。handoff 不写成现有 `verified_effect`。

统一实现以下三种读取：该操作是否阻止继续、该操作是否需要提醒、新动作是否需要重复执行确认。运行循环、Continue、新消息、重启、聊天投影和上下文维护共用它们，不通过把所有 unknown 一律当 finished 来解锁。

### 4.2 第一版允许交接的范围

所有交接均要求：Owner 已掌握原派发范围，未决证据可可靠保存；涉及命令或一次性执行进程时，其进程树须已确认终止/清理；原业务不会被自动重放。正常运行的常驻 MCP/扩展协议进程无需退出，但不能存在未处理的 Host 控制丢失。

| 原动作 | 可交接的情况 | 仍需保留的约束 |
| --- | --- | --- |
| MCP/扩展业务工具调用 | 请求可能已发出，响应丢失、超时或连接中断；本地 Host/进程没有未处理的控制丢失 | 外部工作仍可能完成；原操作及相关后端保护保留，不能把超时写成未生效 |
| 同步文件写入 | 原执行器已经返回，写入最终状态未确认；不是 Core 证据事务提交失败 | 保留部分写入及文件回执，使用现有确定性核验器 |
| 前台 `command_run` | 已证明进程及要求清理的子进程结束，退出状态/输出不完整 | 未确认清理、后台服务仍失控时不适用 |
| 渠道外发 | outbox 已持久记录结果未知且没有可信发送回执 | 按原 Bot/目标/组保持投递保护，迟到回执更新原 operation |

其他 UNKNOWN 路径默认保持原处理；主模型恢复、协作子任务、扩展状态提交等不能因为名称相似就自动加入上述清单。扩展协议进程意外退出涉及其他未完成 Host 操作时，先处理其独立记录。

### 4.3 交接与 Run 生命周期

交接使用现有执行锁和 PostgreSQL 短事务：登记未决事实/编号、幂等补齐对应 tool 结果、登记被阻止的同批未派发调用、写入 handoff。在同一事务中提交；不在事务内调用模型、扩展或远端服务。

幂等依据为原操作、Run、tool_call_id 和交接种类，不能只检查全库是否存在相同 call_id。结果消息只能生成一次；已有占位结果复用，差异通过元数据投影解释。

事务确认成功后才能派发下一请求。提交回执丢失时先按原操作重新读取并核对；无法确定则保持阻塞。重启使用相同的幂等协调函数，不重放原动作。迟到业务结果更新原证据与当前投影，不把旧 Run 恢复成 running。

| 当前情况 | Run 行为 | 会话行为 |
| --- | --- | --- |
| 正常运行中，交接完成且权限仍有效 | 保持 running，模型决定下一步 | 同一会话仍只有一个活跃 Run |
| 正常产生最终回答 | 结束为 completed；UI 显示“本轮已结束 · N 项未确认” | 允许下一 Run |
| 用户停止且调用已安全终止，未决完成交接 | 结束为现有 abandoned，原因区分用户停止；保留原输出和效果 | 释放会话 |
| 权限撤回或本轮不能再执行，未决已交接 | 结束为 failed，保存具体原因 | 新请求仍按实时权限决定是否允许 |
| Owner 重启，符合交接条件、没有活动进程/其他待处理调用 | 完成交接后将被中断的 Run 结束为 failed，原因 `owner_interrupted` | 允许新请求，不自动生成或派发 |
| 交接不能可靠完成，或仍有活动/待确认调用 | 保持原 unknown/待确认/进程管理处理 | 不强行释放执行槽 |

`stopped` 当前仍在单活跃 Run 索引内，不能把它当“已释放会话”。本方案只给已安全终止且交接完成的路径选择上述既有终态；普通 Stop/Continue 语义不统一改写。limited 沿用已有 settled-limit 机制。

实现需覆盖 `markUnknown`、恢复查询、`resolvedAttemptSQL` 的调用者、Continue/新消息、`chatState`、ContextState、分支及已有命令/outbox 管理入口。保留单活跃 Run 索引和 Run 枚举。

### 4.4 模型结果与同批调用

未知结果消息固定说明：

> 结果未知（#N）：动作可能已执行，不是成功证据。不要自动重复。依赖它的步骤先只读核查；暂时无法核查时，继续不依赖它的部分。原始记录可通过引用查看。

同时提供脱敏的动作/目标、开始时间、已知作用和有界输出。保留 assistant 原始工具调用、DeepSeek reasoning_content、Anthropic thinking/signature 与 Responses 原生续接字段，UNKNOWN 用结果正文表达，不能留下悬空工具调用。

一个调用进入未决后，同批尚未启动的副作用调用返回“本次未执行：请先查看 #N，再重新安排”，它们不算 UNKNOWN。可信只读调用可在权限有效时继续。并行已派发的调用分别收集回执和清理状态，不能改写为未执行。

模型看到完整结果组后才重新安排；Harness 不建设通用依赖分析。工具自己的确定性核验保留，通用核验只在确有适用协调器时触发。

### 4.5 展示、稳定编号与受众

- 每个会话新增一个短序号计数器，存入已有 meta；在首次登记原操作时用事务分配固定 #N。计数器和映射属于原操作记录，不存清单快照。不能按“当前 UNKNOWN 行”临时排序，否则旧 Attempt 迟到变成未知、协调或过滤后会变号。
- 原操作被解决/忽略后保留编号映射。接口和按钮同时绑定完整内部标识与记录修订，模型/用户只需使用短编号。
- 分支继承原操作引用和当时编号，之后的新项在分支内继续递增。编号解析始终包含当前会话；不得跨分支按裸 #N 修改原项。源会话后续新增未知由原操作保护处理，不重排分支编号。
- 详细清单按当前受众过滤；不向无权知道该操作的人泄露存在性、数量、编号或“仅 Owner 可见”的占位。有权知道操作但不能看正文时才显示脱敏说明。Core 的内部执行保护照常生效。
- 上下文和最终回复最多展开十项，每项和总文字有界，更多内容通过现有上下文工具分页。重放检查使用完整适用记录，不能只检查这十项。
- 未决事实由实时记录组成，放在当前输入之前；摘要可引用其编号与历史背景，实时结论以记录为准，摘要不能自行清除它。
- GUI/CLI/TG 共用结构化数据。右侧概览仍最多三条，完整清单可展开。停止、失败、限额结束同样保留报告，不把“任务结束”宣称为“目标完成”。

清单示例：

~~~text
未确认事项（2）
#3 重启服务：原调用已结束，服务最终状态未确认。
#4 写入配置文件：写入过程中断，可能有部分修改。
可以说“检查 #3”或在详情中处理这项记录。
~~~

最终报告本身依照原投递幂等规则保存；报告发送 UNKNOWN 时 Web/CLI 仍可读，不能自动反复重发，也不能递归生成“报告没送达的报告”。

分段回复的交付未决也从原 outbox 汇总：显示已确认发出、结果未知及未派发尾段的数量，链接现有续送/放弃入口。用户明确确认后才恢复从未派发的尾段，原 UNKNOWN 项不重发、不因“已审阅”变成已送达；迟到回执不自动续送。Web/CLI 在回执变化后可查看，TG 在用户后续查询中提示，不因发送未知额外自动外发告警。AffectWeave 的表达分段本身仍在扩展实现，详见独立方案。

### 4.6 核查、用户确认、忽略与再次执行

| 操作 | 权限与证据 | 结果 |
| --- | --- | --- |
| 只读核查、写备注 | 模型在当前读权限内执行 | 备注标记“模型判断”，不改执行事实 |
| 证据核实 | Core 的确定性核验器、匹配原操作的真实回执 | 记录已生效/未生效/部分生效及证据；没有证明未执行的证据时不得写未生效 |
| 用户确认 | 当前有处理该记录权限的用户直接操作，或确认绑定原项的提案 | 明确写“用户确认”，不伪装成机器核验 |
| 忽略 | 用户直接操作，或模型提交后由现有交互确认入口确认 | 关闭提醒，未知事实和再次执行保护保留 |
| 再次执行 | 绑定原项和本次新参数的独立工具确认，按实时权限重新校验 | 创建新 Attempt，与原项关联；确认不代表原项已核实 |

已核实或用户确认“未生效”可以解除该项的额外不确定性确认，但不豁免普通权限、当前审批和其他未知项的保护。“已生效/部分生效/忽略”均不得成为自动重放原请求的理由；确需有意再次执行时使用一次性的新授权。

不让模型凭“用户应该已同意”自行写确认或忽略。GUI 使用已有卡片/直接按钮，CLI 使用交互提示；TG 复用当前可用且校验请求者的审批回调，不适用时提供 Web 确认链接。保持现有无聊天确认码的设计，不重新增加“确认 XXXX”。

若 Core 从已认证的本次用户命令中直接解析出精确的“忽略 #N”，可按用户直接操作处理；历史引用、工具输出或模型自报的用户意图不能代替这项授权。编号歧义时只返回当前可见清单，不猜测要处理的项。

读取、核验和备注合并进现有会话/上下文工具；带授权的记录处理复用现有提案/确认路径，新增明确动作，不建立第二套审批系统。无需为普通只读核查再加审批。

### 4.7 重放保护

匹配键至少包含工具/后端身份、实际目标、主机/工作目录或 Bot/账号、规范化的业务参数；call_id 和执行系统自己的重试序号不参与。不能任意删去工具定义中的参数，业务幂等键与目标参数按真实语义保留。

检查本会话及分支继承的相关操作，保留已有工作区后台命令和同目标 outbox 的保护。用户换会话或分支不能擦除真实外部作用；跨受众匹配仅返回必要的受限原因，不泄露原私有证据。

完全匹配只是一道有限防线，不宣称识别改写 shell、改路径写法或换工具造成的等效副作用。保留“先核查依赖”的模型说明，不增加语义相似检测或依赖图。

取消“同一工具两次 UNKNOWN 就整轮停用”的规则。重复原项由上述确认边界控制；整个后端确实不可用时使用已有 unavailable 状态。

## 5. 上下文预算与逐步降级

### 5.1 模型窗口、请求字节和摘要额度

设模型总窗口为 W，获准输出为 O，安全余量 S 沿用当前实现，输入预算 B = W - O - S。窗口未知时沿用明确标记的保守本地折算，不把估算当官方窗口。

| 额度 | 默认/来源 | 约束 |
| --- | --- | --- |
| 模型窗口 W | 用户声明，或已核实的厂商、协议、实际型号精确匹配的预设 | 自定义中转、未知别名不猜窗口；界面显示来源 |
| 自动请求字节保护 L | W 已知时 clamp(W × 8 字节，256 KiB，8 MiB)；未知时 128 KiB | 工程保护初值，不是厂商能力承诺或通用 token 换算 |
| 手动字节保护 | 现有 max_context_bytes，继续受现有有效范围约束 | 用户已保存值原样保留 |
| 摘要目标 | 沿用现有自动/手动策略、独立模型输出额度和存储保护 | 不把摘要存储字节上限直接用作推理加正文 token 上限 |

L 检查 Provider 实际发送的完整序列化正文：文本、工具结构、原生续接字段、内嵌图像 Base64 等均计入一次；Core 审计元数据不计入。附件自身数量/大小上限仍额外检查，不能把附件从总载荷保护中排除。图片 token 单独估算，不把 Base64 再当文字 token。

已知 W 时输出预留只扣 token 输入预算，不能再扣 HTTP 字节。窗口未知时旧保守输出预留属于本地容量折算，界面单列；HTTP 载荷大小仍只报告实际正文。

新增一个现有配置内的字节模式字段 `context_byte_limit_mode=auto|manual`，冻结到 Run 快照；缺字段按 legacy_manual 解释，保留原有数值及旧兼容行为。即使原值正好等于 128 KiB，也不推断是未修改的默认值。新安装默认 auto，旧实例提供一次“改回自动”的可确认设置变更；GUI、CLI、AI 控制入口同步覆盖。

Hytron 实施时核实 DeepSeek 官方窗口与实际端点匹配情况，再通过标准控制入口补窗口并明确切换字节模式；记录改前/改后值和回退方法。当前文档修改不改变生产配置。

### 5.2 参数初值与实际用量校准

| 参数 | 定稿规则 |
| --- | --- |
| 自动触发 | 保留现有可配置比例，默认 80% |
| 压缩目标 | 约 60%，是软目标，不保证固定材料很大时仍可达到 |
| 近期历史保留区 | 完整可选后缀最多约 B 的 20%，同时遵守字节保护；当前输入/已采纳引导与必需协议字段独立计量 |
| 应急历史原话块 | 最多约 B 的 5%，并限制在 8 KiB UTF-8 内；允许缩小以满足整体请求预算 |
| 回读容量 | 沿用“有效摘要检查点之间的回读区间”，token 软上限约 B 的 10%，同时保留现有单段、字节总量和去重上限 |
| 低收益标准 | 下降不足 5 个占用百分点时不重复同源同配置压缩；已经放得下就发送，不能仅为凑比例继续删历史 |

占用采用 token 与实际字节两条限制中更紧的一条。窗口未知时用可用本地字节容量代替上述百分比基准，并标明折算来源。百分比不新增一组用户配置项，保留区/引用块/回读数值作为实现初值用固定夹具验证。

“实际输入 + 新增估算”继续使用现有 `context_calibration.go`：模型、权限视图、配置、工具和已有前缀一致才复用。摘要、折叠、扩展块、图像或模型变化则重新估算；校准缓存丢失可以退回保守估算。保留实际值、估计值、依据 Attempt 和估算方式。

不增加整个 Run 的回读次数/时长上限。已读片段重复请求返回状态；有效摘要后释放原回读区间的占用，不能因为一次省略就无上限反复读回同一内容。

### 5.3 完整保留区与摘要边界

首先对已闭合工具正文做有界折叠，再按完整后缀计量近期保留区，包括用户、助手、工具结构和必要续接字段；不能只计算用户原话。超过软目标则缩短保留区，将更早的闭合组纳入连续摘要前缀。

当前输入和已采纳引导保留原文。未闭合工具组、正在执行的调用及协议要求保留的原生字段不得拆开。`covered_through` 保持连续，不增加稀疏覆盖状态。

首批允许当前 Run 的较早闭合工具结果缩短正文并回读；当前 Run 内旧组是否能摘要只按已通过 Chat/Responses/Anthropic 协议回归的能力放行。无法安全缩短的原生续接字段成为最小必需请求的一部分，不承诺长 Run 可以无限增长。

### 5.4 一次准备请求的降级流程

以固定 Run 配置、受众、历史版本和本次扩展/附件材料为边界，每步重新计算实际请求；预算重建不重复执行 hook。采纳新引导时依既有逻辑重建输入相关材料，旧候选失效。

1. **正常发送**：未到预防性阈值且未超任何硬限制，直接派发。
2. **折叠**：使用现有 foldToolContext，将可折叠旧正文换成有界说明和引用，保留状态、退出码、路径、未决引用及协议配对。不把正文缩短解释为原结果丢失或未执行。
3. **滚动摘要**：处理已有检查点之后、保留区之前的连续闭合组；仅摘要获准的对话原文，不把 Memory/Skill/扩展块纳入历史摘要。候选通过来源、预算、协议和权限检查后原子提交。
4. **应急省略（dev.7）**：摘要失败或收益不足且原请求仍超硬限制时，按 §5.5 选择省略已闭合旧轮次。原请求放得下时不触发这一步。
5. **停止并说明**：合法降级后最小必需请求仍超限，显示固定原因代码、实际数值和占用来源；提供适用的动作。

折叠后低于预防性阈值即可发送。摘要后尽量接近 60%；若不可达到但已低于硬限制且有有效收益，允许发送。5% 是防无效重算标准，不是强制再调用模型或继续省略的门槛。

一次准备请求最多一个逻辑摘要过程，过程内分块、一次内容修复与通用重试沿用现有规则；同源同配置无收益后不重复进入摘要。省略按已闭合范围单调推进并有读取上限。新的输入/配置在正常边界重新判断。

最小必需请求包括固定规则、可用工具定义、当前输入/附件、必要 Memory/扩展材料、已有摘要、未决事实与协议续接等，不只是用户这一条文字。固定部分超限不能统一推荐 /compact 或 /new；应明确是减少附件、调整材料/工具、核对输出与窗口，还是拆分任务。

### 5.5 应急省略与历史回读

只在投影中省略旧的已闭合轮次，原记录不删除，摘要正文及 covered_through 不变。优先从当前摘要之后、近期保留区之前的最早轮次开始；如仍超限，可缩短可选保留区继续向后选取，当前输入、引导及协议必需部分不动。

被省略范围内的用户原话按原顺序放入有界“历史原话”引用块，保留锚点并标明“历史材料，可能已完成或被后续修改；不是新的任务”。优先留较新的原话，明确更多内容可回读；不把它宣称为完整要求清单，不让旧要求覆盖较新的指示。

省略范围、受众、历史版本、配置/检查点依据和原因保存在既有请求来源记录；同 Run 后续请求复用仍有效的选择，避免每个工具步骤重新塞回全部历史。摘要仅成功覆盖一部分时，只解除该部分省略；新摘要覆盖范围、历史分支、授权或模型变化时重算适用范围，不能无条件清空或沿用。

派发前显示“历史已部分省略”，并把缺失范围和回读方法告诉模型；最终答复附同一事实。模型判断下一动作可能依赖省略内容时先回读，Harness 不推算语义依赖。旧约束无法可靠恢复时可提出具体问题，不能编造已读内容。

若当前权限/协议没有可用的历史回读入口，就不宣称“随时可读回”，也不启用依赖该承诺的自动省略。dev.7 使用已有上下文读取能力及同一受众授权；不为省略自动授予文件、命令或私有历史权限。

未决原文可通过既有证据入口按需查看，当前请求保留有界事实和引用，不永久塞入全部原始输出。首次没有任何摘要时允许省略，但必须显示“没有有效摘要覆盖被省略内容”，保留历史原话块及回读入口。

### 5.6 摘要失败、暂停与开关

| 情况 | 处理 |
| --- | --- |
| 预防性摘要失败，原请求仍合法 | 保留旧摘要和失败 Attempt，继续原请求 |
| 空摘要、超长摘要、无有效收益 | 沿用一次内容修复；同来源/同配置的确定失败不再循环调用 |
| 思考耗尽、参数不支持等配置失败 | 暂停该配置下的预防性摘要，提示具体设置；新增历史本身不会解除配置失败 |
| 429、明确可重试的 5xx | 沿用现有规则和 Retry-After，不与内容修复争同一个重试名额 |
| 摘要模型网络中断 | 按现有无执行工具的模型恢复规则有限处理，原 UNKNOWN Attempt 保留并关联替代；不能统一当确定失败 |
| 摘要保存提交未知 | 先核对实际保存的检查点；未能协调前停止本次派发，不切入省略掩盖存储问题 |

达到硬预算时重新规划恢复，不被“暂停预防性压缩”直接挡住；同配置已确定无效的模型摘要仍跳过，选择折叠、省略（dev.7）或具体设置提示。配置变化可重新判断配置失败；新来源只解除源相关失败；显式手动 /compact 可发起一次新的维护尝试。

继续遵守用户的 automatic_compaction 开关。关闭自动压缩时不自动调用摘要模型，也不启用会省略历史的应急策略；必要的既有有界工具投影仍生效，手动压缩可用。界面在同一“自动管理历史”设置附近说明自动开启后的折叠/摘要/必要省略行为，避免设置与实际行为矛盾。

同会话、受众、失败类别和有效配置只提示一次相同预防性失败；新的硬限额必须解释当前阻塞，不能因提示去重静默停止。停止/取消/权限撤回仍优先，禁止继续派发。

### 6.1 上下文固定夹具

- 使用脱敏或合成的线上结构：约 458 字节用户原话、约 60 KB 工具正文，以及旧摘要、工具定义和近期回答。明确设置可触发恢复的模型/载荷限制；不能提高预算后让根本未触发的请求算作“压缩通过”。
- 在可达到目标的模拟场景，摘要完成后占用低于 60%，来源覆盖实际推进。固定材料本身超过目标时，断言有效下降、低于硬限制并继续，不要求不可能的比例。
- 覆盖无摘要、已有摘要、连续短输入、长工具组、当前长 Run、零收益、暂停状态、配置变更、手动目标、UNKNOWN 和同组多个工具。
- Chat/Responses/Anthropic 分别验证思考原生字段、tool_call/result 配对；摘要/折叠/省略不删除原记录。图像编码只计一次，旧校准不能在前缀变化后复用。
- 连续至少五轮跨越触发点，记录调用数、恢复原因、压缩后占用和实际用量；同源同配置不能反复无收益压缩，回读不能无限挤满请求。
- 真实 DeepSeek 记录实际用量和质量，不要求真实模型恰好输出固定长度；不得使用模拟测试冒充线上收发。

### 6.2 未决与崩溃矩阵

注入以下时机：外部作用发生后/回执前、交接事务提交前/提交响应丢失、交接后下一请求前、最终回答保存前后。分别验证：

1. 原动作最多派发一次；原未知证据保留。
2. 结果消息和编号不重复，交接未确认时不派发下一请求。
3. 已交接历史在 Owner 重启后不重新锁住 completed/failed/abandoned Run；新的 Run 可以创建，单活跃索引仍有效。
4. 同批未派发写操作返回未执行，已派发并行项各自处理；用户停止和权限撤回阻止新调用。
5. 不可交接进程/事务路径仍阻塞；用户“忽略”不能解除该硬阻塞。
6. 迟到真实回执只归属原操作；编号在处理、旧 Attempt 迟到 UNKNOWN、分支和分页之后稳定。
7. UI 十项以外的操作仍受重放保护；无权受众看不到私有存在性、编号和内容。
8. outbox 发送未知、报告发送未知、后续新消息、回执迟到各自幂等，不递归发送报告。
9. API/CLI 的处理动作校验身份、作用范围、修订和请求幂等键；模型备注不能伪造用户确认。

## 8. 减重与实现边界

- 无新数据表、Run 枚举、通用步骤依赖图、语义相似命令识别、第二套调度器或审批系统。
- 元数据仅记录交接、处理来源、固定编号及必要请求选择；不复制完整历史/工具结果，不维护清单快照。
- 保留区、历史原话与恢复复用既有投影、摘要、回读；不新增稀疏摘要检查点。
- 不设“同一工具两次 UNKNOWN 即全 Run 停用”，不重新引入总步数、总时长或整个 Run 的回读次数上限。
- MCP、渠道与扩展通过既有接口提供真实回执；AffectWeave 的人物、回复策略不进入 Core 恢复规则。
- 是否继续、是否提醒、是否允许再次执行分别判断；不能复用一个 verified/ignored 布尔值概括三者。
