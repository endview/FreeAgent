# Embedded read-only control web

This directory contains the React and TypeScript Control Overview plus the
narrow, explicitly confirmed `MODULE_DISABLE` workflow.
The committed `dist` directory is the exact asset set embedded by the Go
package. The package exposes an exact asset resolver only; it does not register
HTTP routes, enable the control plane, create a listener, or change the default-
off composition boundary.

In an explicitly enabled same-origin Control server, the browser exchanges one
short-lived handoff, retains only the rotating resume credential in tab-scoped
`sessionStorage`, keeps CSRF material in memory, and reads the bounded Overview
with exact scope headers and strong ETag revalidation. The interface derives
choices only from server-authorized scopes and current Workspace references. It
contains no event stream, worker, or durable client cache; it does not add a
second business-rule or application-service path.

Runtime dependencies are limited to React, ReactDOM, and TanStack Query. Node.js
and npm are build dependencies only. `scripts/Test-ControlWeb.ps1` reconstructs
the project in a disjoint external directory with exact npm, type-checks and
tests it, builds it, and requires every generated byte to match committed
`dist`.

## Interface locale foundation

The interface locale layer is internal and adds no npm dependency. It ships
static `en-US` and `zh-CN` catalogs, resolves unsupported or incomplete locale
data through the `en-US` fallback, and exposes one React provider with locale-
bound `Intl` number, token-count, date/time, relative-time, and list formatters.
The initial locale uses the saved preference when present, then the browser
language, then `en-US`. Changing it updates the document `lang` and title.

The only durable interface preference is the locale string under
`freeagent.ui.locale.v1` in `localStorage`. No session, authority, response, or
Control data is stored there; blocked or unavailable storage fails open to an
in-memory locale selection. Session resume data remains tab-scoped as described
above.

Messages use `{{name}}` plain-text interpolation. A numeric `count` selects an
`Intl.PluralRules` suffix such as `_one` or `_other`; absent interpolation
values remain visible placeholders, and a key absent from both the selected
catalog and `en-US` invokes the optional diagnostic hook and renders as the key
itself. Built-in catalogs are validated for equal keys and interpolation
parameters at module initialization. Translations return strings, not
HTML. Render interpolated values as ordinary React children so React performs
its normal escaping; raw-HTML rendering is forbidden by the static policy.

The same static policy checks that both catalogs have identical keys and
interpolation parameters, every direct translation reference exists, and UI
files do not reintroduce visible hard-coded JSX text or labels. The P2 surface
is limited to existing handoff, Overview, Modules, confirmation, error,
loading, empty, and accessibility text; it does not add lifecycle operations
or new Control routes.

## P4 management read models

The current module-management surface is read-only. It consumes the same
application/control services as the CLI and exposes bounded, tenant/workspace-
scoped projections for Review/Decision/Artifact, UNKNOWN evidence and
reconciliation, Store verification, backup constraints, and server-owned
Artifact Admission. List/detail responses carry projection digests and strong
ETags. Handlers re-check scope and capability and fail closed on stale,
cross-tenant, or invalid inputs.

The UI never accepts a server path, Secret, request body, signature material,
or replay material. UNKNOWN has no resend, replay, Provider substitution, or
implicit retry action. Backup creation and restore are not online UI
operations; restore remains offline staging followed by atomic publish.
Install, Activate, Bind, Grant, Review, Apply, and Execute remain separate and
are not opened by the read models. The supported Provider matrix remains exact
`zhipu` / `glm-4.5` for the new entry; this document does not claim
compatibility with every GLM model or endpoint.
